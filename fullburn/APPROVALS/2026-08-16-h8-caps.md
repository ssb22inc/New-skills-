## How the path list below was produced

The approver's message left `[items]` as a literal placeholder. The list was
NOT filled in by hand. It is the verbatim output of

    cd fullburn && npm run owed-approvals -- .. b1fc37d

which reads the PR's diff through the same `isClass2()`, the same
`class2TouchedPaths()` and the same hash functions that `class2-gate.mjs`
enforces with — so what is approved here is exactly what the gate demands, by
construction. This mechanism exists because the hand-maintained list drifted in
both directions inside a single commit (adversary finding H-17): it named files
the diff never touched and deferred files the gate demanded, so the human would
have signed a set that was not the set that changed.

If the approver's intent was narrower than this generated set, the correct
remedy is to revoke this entry and reissue, not to edit it — approvals are
append-only history.

## Standing caveat this entry does not resolve

An approval proves WHAT was approved by content hash. It does not prove WHO
wrote it: this file was transcribed by the builder from the approver's written
decision, and nothing in the repository can currently distinguish that from a
builder writing its own approval. Only CODEOWNERS on `APPROVALS/**` makes
"human-only" real — that is H19, and it is not yet in place (ledger L11, L13).
Until it is, every entry in this directory, including this one, is advisory.
