## Findings

### 1. [blocker · clinical] Numeric values cannot preserve reported precision

- **Where:** abg.jsx — decimals(), halfUnit(), abgConsistency() · confidence high
- **Problem:** Trailing zeros disappear from JavaScript numbers. Consequently, pH 7.30 receives a ±0.05 rounding allowance, and pH 7.00 receives ±0.5, despite being displayed to two decimals. For {ph: 7.0, paco2: 40, hco3: 24}, the consistency gate accepts values implying pH about 7.40 and reports acidemia with an unresolved primary process. Likewise, {ph: 7.4, paco2: 50, hco3: 26} is accepted and called fully compensated respiratory acidosis although those PaCO₂/HCO₃⁻ values imply pH about 7.34, not the displayed 7.40.
- **Fix:** Carry reported precision explicitly, using original strings or precision metadata. When unavailable, use a documented reporting-precision policy rather than inferring precision from the numeric value. Add regression tests for pH values ending in zero, including 7.00, 7.20, 7.30 and 7.40.

### 2. [blocker · clinical] A normal-range pH does not require compensation from a fixed baseline

- **Where:** abg.jsx — CANDIDATES.moved; interpretAbg() normal-pH/no-fit branch · confidence high
- **Problem:** {ph: 7.44, paco2: 40, hco3: 26.3} is internally consistent: Henderson–Hasselbalch gives about 7.441. PaCO₂ also falls within the tool's expected metabolic-alkalosis interval, 37.4–41.4 mmHg. Nevertheless, the tool rejects the gas because PaCO₂ has not risen above 40, stating, 'A normal pH needs the other value to have compensated, and it has not.' A mild primary disturbance can remain within the pH reference interval; normal pH does not establish that pH previously left the interval and returned. Individual baselines are not necessarily 40/24.
- **Fix:** Remove the requirement that a normal-range pH must demonstrate movement past the assumed baseline. Keep internally consistent borderline results interpretable, with appropriate uncertainty about the primary process and compensation. Do not automatically label them inconsistent or fully compensated.

### 3. [major · consistency] Formatting can round an abnormal value onto the normal boundary

- **Where:** abg.jsx — fmtNum(); Gauge text and dynamicCaption() · confidence high
- **Problem:** fmtNum() stops at three decimals even though interpretation accepts more. For {ph: 7.3499, paco2: 50, hco3: 26.668}, the values agree and interpretation returns partially compensated respiratory acidosis. The gauge and caption display pH 7.350, however, which is within the stated 7.35–7.45 interval. This directly contradicts the displayed diagnosis and the source's promise never to round onto a limit.
- **Fix:** Use the kit's exact-value formatter, or enforce and disclose an input-precision limit before classification. Display and interpretation must use the same supplied value without rounding it across a reference boundary.

### 4. [major · consistency] Valid extreme gases are labeled as inconsistent

- **Where:** abg.jsx — INTERPRETED range check, recheck(), verdictLabel() · confidence high
- **Problem:** Exceeding the tool's supported range returns disorder='inconsistent' and the inline verdict 'Values don't fit: recheck'. For example, pH 6.77, PaCO₂ 40 and HCO₃⁻ 5.6 agree mathematically, but pH is below the tool's automatic-interpretation limit. The caption distinguishes unsupported interpretation from disagreement; the inline diagram does not. A student sees the same invalid-values verdict used for mutually contradictory numbers.
- **Fix:** Create a separate unsupported/manual-review status and verdict, such as 'Outside automatic interpretation range'. Reserve 'inconsistent' and 'Values don't fit' for failed consistency checks.
