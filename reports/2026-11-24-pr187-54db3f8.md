## Findings

### 1. [major] Vite query imports are omitted from the marketing dependency graph

- **Where:** `pulsern/ops/seo-page-change.mjs:33` · confidence high
- **Problem:** Import specifiers are treated as literal filesystem paths. For a supported Vite import such as `import copy from "./marketing-copy.html?raw"`, collectSources searches for filenames containing `?raw` and never records the actual `pulsern/src/marketing-copy.html` dependency. The regex also misses valid imports without whitespace after `from`, so the graph does not fulfill its stated coverage of every local import.
- **How it fails:** After landing.jsx imports and displays marketing-copy.html through `?raw`, a later commit changes only that copy file. It is outside public/, is absent from SOURCES, and therefore produces changed=false. The workflow skips the model and writes a PASS report even though the public homepage copy changed. Existing tests cover only plain import specifiers and would not catch this.
- **Fix:** Resolve imports using Vite-compatible semantics, including stripping supported query suffixes before filesystem resolution, and parse valid JavaScript import syntax rather than relying on this regex. Add regression tests showing that changes to queried and transitive copy dependencies require review.
