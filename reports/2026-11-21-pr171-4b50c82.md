## Assessment

Do not ship. The change removes the audio accuracy gate and records unverified synthesis as a perfect match. The new dollar-cap enforcement also lacks a test that exercises it.

## Findings

### 1. [blocker] Unconditionally approves audio without checking what it says

- **Where:** `pulsern/api/_speak.js:672` · confidence high
- **Problem:** Every nonempty Polly response now receives check.pass=true and similarity=1 without any examination of its spoken content. saveChecked persists that fabricated verdict, and subsequent requests serve the clip as approved. Switching providers does not establish that every clinical number, unit, negation and drug name was spoken correctly. This removes the existing accuracy safeguard rather than replacing it.
- **How it fails:** A request asks for "Potassium 2.9 milliequivalents per liter." but the returned clip misreads the value, omits a word or is truncated. The worker saves a passing record and students hear that clip indefinitely. The modified tests explicitly accept synthesis without verification, so they no longer catch this failure.
- **Fix:** Restore independent verification of the actual returned audio before saving a passing record, including the existing word, number and clinical-unit checks. Compute similarity from that verification rather than assigning 1, and retain regression tests proving that incorrect audio cannot be published.

### 2. [major] The dollar-cap tests never exercise dollar-cap enforcement

- **Where:** `pulsern/tests/polly-voice.test.js:24` · confidence high
- **Problem:** This test checks only conversion from dollars to characters. The other added cap test prepopulates character slots and checks the queued response. No test runs synthesis with a positive limits.chars value, so neither reserveSpeechCost's character-slot allocation nor its connection to the worker's paid call is covered. Replacing reserveSpeechCost with reserveSpend would leave these tests green while removing the advertised $40 limit.
- **How it fails:** With limits.chars=200 and passage capacity remaining, two 100-character syntheses should exhaust the character budget and prevent a third provider call. The current suite never exercises that state; a bypass of the new enforcement could instead allow spending up to the much larger 15,000-passage cap.
- **Fix:** Add worker-level tests using a successful Polly send double and real counter logic. Verify that character exhaustion prevents the next provider call while passage slots remain, that counter failures spend nothing, and that concurrent reservations cannot exceed the character cap.
