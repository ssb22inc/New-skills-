## Assessment

Request changes. There are reproducible navigation-state defects and a keyboard-accessibility defect in the new dialogs. The added helper tests do not exercise these interaction paths.

## Findings

### 1. [blocker] Confirming a leave to the active section does not clear the round

- **Where:** `pulsern/src/App.jsx:889` · confidence high
- **Problem:** For non-Home destinations, applyLeave only calls setTab(destination). When that destination is already active, React preserves the component and all its question, draft, and navigation state. This contradicts the confirmation's explicit promise that the open question and place in the round clear.
- **How it fails:** Start a Practice question, select an answer, click the already-active Practice tab, and confirm "Leave round". The same question and unchecked selection remain. The equivalent problem affects the Case Study and Cards tabs.
- **Fix:** Treat selecting the current section as a no-op before showing a leave confirmation, or explicitly reset/remount that section after confirmation. Add interaction tests for active-section clicks with an open draft.

### 2. [major] Abandoning failed scoring leaves the next exam's Home exit blocked

- **Where:** `pulsern/src/App.jsx:909` · confidence high
- **Problem:** homeAfterExam is cleared on successful scoring or the specific "Back to exams" button, but not when another navigation control abandons a failed submission. The stale destination then prevents confirmLeave from invoking examExitRef for a later exam.
- **How it fails:** During exam A, confirm Home, then let the submit request fail. The failure unlocks navigation, so click the header Home button and later start exam B. Confirming Home in exam B now merely closes the dialog: homeAfterExam is still truthy, so no submission or navigation occurs. If B is completed normally instead, the stale destination unexpectedly sends the student Home and discards the locally held item-review screen.
- **Fix:** Scope the queued destination to the current attempt and clear it whenever that attempt's failed submission is abandoned through any navigation path. Also ensure a new attempt cannot inherit a previous destination. Test the failed-submit, navigate-away, start-another-exam sequence.

### 3. [major] The new modal dialogs leave keyboard focus in the underlying app

- **Where:** `pulsern/src/tour.jsx:48` · confidence high
- **Problem:** Neither LeaveDialog nor Tour moves focus into the dialog, traps focus, or makes the background inert. aria-modal does not implement those behaviors. Opening a leave confirmation from the header leaves focus on the underlying Home button, and subsequent Tab presses traverse background controls before reaching the dialog.
- **How it fails:** A keyboard user opens Home confirmation during a question. Instead of landing on the confirmation actions, focus remains behind the overlay and can reach question controls or navigation. The user can modify the underlying session while the modal is pending. During the multi-screen tour, background controls likewise remain keyboard-operable despite the modal presentation.
- **Fix:** Implement shared modal focus management: focus an appropriate dialog action on opening, contain Tab and Shift+Tab within the dialog, make background content inert while open, and restore focus when closing. Add keyboard interaction tests for both dialogs.
