## Assessment

The checked-audio gate remains intact, but the new cache and player-unlock handling introduce two reproducible playback defects. Changes requested.

## Findings

### 1. [major] Played clips remain permanently pinned in the warm cache

- **Where:** `pulsern/src/read-aloud.jsx:154` · confidence high
- **Problem:** hold() adds each played blob URL to playing, but nothing ever removes it. evict() consequently treats completed, stopped, and failed clips as still playing.
- **How it fails:** After eight warmed clips have been played—roughly one or two questions—the cache contains eight permanently protected entries. Starting a download for a ninth clip immediately evicts that new pending entry, so start() returns 0. Warming then stops working for every subsequent item during the session, even while playback is idle.
- **Fix:** Add a release operation and invoke it when playback ends, fails, pauses, or is aborted. Protect only the clip actually using the player, and run eviction after releasing it. Add a regression test that completes playback of eight clips and verifies that a ninth clip can be warmed and an old clip revoked.

### 2. [major] A failed unlock prevents later taps from priming an uncached item

- **Where:** `pulsern/src/read-aloud.jsx:242` · confidence high
- **Problem:** The new !player.src condition makes priming a one-time attempt, including when that attempt failed. A rejected play leaves src populated but the player still locked, so subsequent Listen/Resume taps do not attempt to unlock it during the gesture.
- **How it fails:** On a strict-autoplay browser, let the initial priming attempt fail and the reader enter blocked state. Navigate to an uncached item, then tap Listen. Because the previous src is nonempty, unlockPlayer does nothing. When the new URL arrives after the gesture, play() is rejected again. The existing retry test misses this because its URL is already cached, allowing playback synchronously inside the second tap.
- **Fix:** Separate gesture-time unlocking from ordinary player retrieval. A real Listen/Resume tap must retry unlocking a still-locked element without resetting an active passage during normal playback. Extend the strict-browser test to navigate to an uncached item after a failed unlock and deliver its URL after the next tap.
