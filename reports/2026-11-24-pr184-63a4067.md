## Assessment

Not ready to ship. The supplied changes leave a progress-overwrite path, reset the displayed daily progress of legacy users, and contain two incorrect reward/feedback behaviors. Tests were reviewed but not executed.

## Findings

### 1. [blocker] An authentication read failure can still become an empty progress save

- **Where:** `pulsern/src/App.jsx` · confidence medium
- **Problem:** store.get ignores the error returned by supabase.auth.getSession() and returns null whenever session is absent. readProgress interprets that null as a successfully verified new account. If the subsequent getSession in loadProgress succeeds, autosave is enabled with defaults and can overwrite the existing progress row.
- **How it fails:** AuthGate has mounted App, but the session lookup inside store.get encounters a transient token-refresh failure and returns { data: { session: null }, error }. The next session lookup recovers. No progress SELECT was completed, yet the app treats the account as new and upserts empty progress under the recovered user ID. I could not execute the installed SDK to reproduce its refresh-error behavior, but the returned-error/missing-session path is explicitly unguarded.
- **Fix:** Check the authentication error and fail closed when no session is available. Only classify an account as having no progress after a successful SELECT for the expected signed-in user returns no row. Add a browser regression covering a failed session lookup followed by recovery and assert that no default upsert occurs.

### 2. [blocker] Shift completion falsely tells students all misses are corrected

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** The completed-shift explanation says, "Your reviews are done and your misses are corrected, so rest now." However, shiftStatus completes the Fix a miss task after any one correction, regardless of how many current misses remain.
- **How it fails:** A student has eight questions answered today, no cards due, one corrected miss, and twenty other current misses. shift.complete is true, and opening "why this works" tells them their misses are corrected and recommends stopping, although those twenty misses remain unresolved.
- **Fix:** Make the explanation match the actual one-correction task, for example by saying that today's scheduled cards are cleared and a miss was corrected. Do not claim all misses are resolved unless the current-miss count is zero. Add a feedback-copy regression with fixes > 0 and missesOpen > 0.

### 3. [major] Legacy users' current-day progress becomes zero on upgrade

- **Where:** `pulsern/src/state.js:55` · confidence high
- **Problem:** A legacy save receives rewards.days = {}, but the existing Q TODAY display and daily goal are replaced with counters sourced exclusively from rewards.days. The preserved daily field is no longer used for those live surfaces.
- **How it fails:** A student answers eight questions today before this release and saves daily = { day: today's local date, answered: 8 }, without a rewards key. After upgrading, Today reports Q TODAY = 0 and Assessments = 0 of 8. Answering one additional question changes those displays to 1 rather than 9, making an already completed daily goal appear incomplete.
- **Fix:** Handle the migration day explicitly before replacing the legacy counters. Preserve the existing activity/goal display during that transition, or disclose unavailable historical question counts instead of reporting zero. Do not blindly copy daily.answered into a question-only counter because legacy flashcard grades also incremented it. Add an actual legacy-load dashboard regression.

### 4. [major] Hard bank questions are incorrectly treated as previously answered case steps

- **Where:** `pulsern/src/rewards.js:156` · confidence high
- **Problem:** sameAnswer assumes an unsourced difficulty-3 log row is a legacy case answer. Ordinary QBank rows also have no source field and can have difficulty 3. Consequently, a matching numeric ID and category can spend the XP entitlement of an unrelated case step.
- **How it fails:** A student correctly answers bank question 101 in Physiological Adaptation at difficulty 3, then correctly answers the sepsis case's second step for the first time. That step aliases legacy ID 101, so answerXp returns reason "repeat" and awards zero XP. The new test claiming bank/case disambiguation uses only a difficulty-1 bank row and misses this collision.
- **Fix:** Record an explicit question-versus-case source discriminator and use unambiguous identities for repeat detection. Do not infer that an unsourced row is a case solely from difficulty 3; handle ambiguous legacy rows conservatively. Add the same-number, same-category, difficulty-3 bank regression.
