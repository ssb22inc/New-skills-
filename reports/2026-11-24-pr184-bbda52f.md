## Assessment

Do not merge yet. The guest flow can discard answers after a device-storage failure, and its question-linking logic can re-serve trial questions as new. The run-counter rewrite also introduces a batch-recording regression that needs verification against the real exam scorer. Review was limited to the supplied diffs and images; tests and build were not executed.

## Findings

### 1. [blocker] Failed device saves silently discard trial answers during sign-up

- **Where:** `pulsern/src/guest.jsx:38` · confidence high
- **Problem:** saveGuest returns false when localStorage cannot be written, but this effect ignores the result. The trial continues and displays "Saved on this device for 7 days". Creating an account unmounts GuestTrial, while the signed-in handoff reads only localStorage, so answers held only in React state disappear.
- **How it fails:** localStorage.setItem throws QuotaExceededError during the trial. The student completes five questions and selects Create free account. The account receives either no trial answers or only the older subset successfully stored, despite the save confirmation.
- **Fix:** Track device-save failures and do not claim persistence when a write fails. Preserve the current trial through the authentication transition using an explicit in-memory handoff, or require a successful retry before discarding the component's only copy. Add a browser test where reads succeed but setItem throws, then complete the sign-up transition.

### 2. [major] Trial-question aliases depend on unrelated database identity values

- **Where:** `pulsern/src/guest.js:116` · confidence high
- **Problem:** linkBuiltInGuest requires both the built-in numeric id and stem to match. A shared-bank copy of the same built-in question can have a different generated database id. In that case the helper supplies no guest alias, so QBank treats the already-answered question as fresh and answerXp awards first-answer XP again.
- **How it fails:** The student answers built-in question 7 during the trial, producing guest-7 after import. The approved bank contains that same stem under id 700 because it was seeded after other rows. New questions serves it again, and a correct answer receives full XP rather than repeat handling.
- **Fix:** Resolve copies using a stable content/source identity rather than equality between built-in and database ids. For existing rows, match the verified built-in content independently of the database id and attach the corresponding guest alias. Test a different-id/same-content bank copy through both fresh-pool exclusion and XP calculation.

### 3. [major] Captured run state loses increments when scored answers arrive in a batch

- **Where:** `pulsern/src/App.jsx:944` · confidence medium
- **Problem:** The previous functional setRun updater accumulated every recording. The replacement calculates nextRun from the render-captured run and then calls setRun(nextRun). Two correct recordings through the same callback therefore both write the same increment, undercounting the run and personal best. The new tests exercise substitute record handlers rather than this App handler.
- **How it fails:** Starting at run 0, deliver several correct exam results through one captured record callback: each calculates nextRun as 1, so the resulting run and bestRun are 1 instead of the number of consecutive correct answers. The supplied diff omits ExamCenter's scoring implementation, so whether it refreshes the callback between results could not be verified.
- **Fix:** Accumulate per-answer run state using a reducer or synchronously advanced state reference, preserving correct return values for combo feedback. Add an integration test that sends a multi-item exam result through the real App recording handler and verifies run and bestRun.
