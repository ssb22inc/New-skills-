## Findings

### 1. [blocker] Nonempty audio is automatically certified as clinically accurate

- **Where:** `pulsern/api/_speak.js:667` · confidence high
- **Problem:** makeChecked now assigns pass: true and similarity: 1 to any nonempty audio without inspecting what it says. saveChecked persists that fabricated verdict, and speak serves the clip to students. Reviewing the input text does not establish that the synthesized output preserves its numbers, units, drugs, or negations. This removes the existing accuracy safeguard. The updated tests explicitly accept one take even when the former misread-number fixture is supplied; the remaining voiceCheck tests exercise a function production synthesis no longer calls.
- **How it fails:** The script says "Potassium 2.9 milliequivalents per liter", but the returned clip reads a different value or drops a clinically significant word. The clip is saved as passing and reused for every student listening to that passage.
- **Fix:** Restore an independent check of the actual synthesized audio before publication, including exact clinical-value and word checks. Do not manufacture a perfect similarity score. Restore an end-to-end test proving that incorrect audio is neither saved as passing nor served.

### 2. [major] Polly throttling is saved as a seven-day passage rejection

- **Where:** `pulsern/api/_speak.js:616` · confidence high
- **Problem:** Polly can return ThrottlingException with HTTP 400. Because that name is not classified before the catch-all status === 400 branch, it becomes a permanent passage failure. voiceClaimed then saves a rejection record and drainQueue removes the request. The existing HTTP 429 fetch-double tests do not cover Polly's HTTP 400 throttling behavior.
- **How it fails:** Polly exhausts its request-rate or concurrency allowance. After SDK retries are exhausted, otherwise valid passages receive HTTP 400 ThrottlingException and become unavailable until their seven-day rejection records expire, even after throttling clears.
- **Fix:** Classify ThrottlingException as transient before handling HTTP 400. Prefer explicit passage-error names over treating every remaining 400 as permanent. Add a Polly-client test asserting that a 400 throttling response retains retryable work and creates no rejection record.

### 3. [major] Automatic SDK retries bypass per-synthesis budget reservations

- **Where:** `pulsern/ops/read-aloud-worker.mjs:572` · confidence high
- **Problem:** PollyClient retains the AWS SDK's automatic retry policy, while makeChecked invokes beforeTake only once per polly.send. Consequently, one passage and character reservation can authorize multiple SynthesizeSpeech requests. The fetch-based budget tests bypass the SDK and cannot detect this.
- **How it fails:** AWS accepts and synthesizes a passage, but its response is lost before the client receives it. The SDK resubmits the request automatically. Both accepted syntheses can be billed, while storage records only one passage's character cost, allowing actual spending to exceed the advertised daily cap.
- **Fix:** Set maxAttempts: 1 and leave retries to the worker's existing separately budgeted retry mechanism, or reserve spending before every underlying SDK attempt. Add coverage that counts actual SDK request attempts against the corresponding budget reservations.
