## Assessment

Changes need fixes. Static review found two correctness defects in legacy review/trial-import handling and a large-bank render regression. I did not run the test suite.

## Findings

### 1. [major] Correct reviews cannot advance an ambiguous legacy schedule

- **Where:** `pulsern/src/answer-apply.js:89` · confidence high
- **Problem:** adoptRawSchedule refuses adoption when an old row is unclassified, but scheduleEntry still serves that same raw schedule to the canonical question. A correct answer then finds no canonical schedule, so updateMissSchedule creates nothing. Subsequent pool builds keep finding the unchanged, overdue raw entry even though the latest canonical answer is correct.
- **How it fails:** A legacy miss has id 7 and schedule[7] due today. Both the bundled and shared-bank catalogs contain 7, so classification leaves the old row unresolved. The student correctly reviews bank:7. The raw schedule remains overdue, no bank:7 schedule is created, and the question keeps returning as due instead of advancing three days.
- **Fix:** Make unresolved-schedule lookup and adoption consistent. After a keyed review, either establish an advancing canonical schedule or stop applying the unresolved raw schedule to that key, while preserving ambiguous history separately. Add a regression covering classification, correct review, and the next Today/Review Misses pool.

### 2. [major] Historical imports calculate XP and corrections against future answers

- **Where:** `pulsern/src/answer-apply.js:146` · confidence high
- **Problem:** answerXp receives the entire existing log before the historical answer is inserted. The later prior lookup does the same. Consequently, an account answer that happened after the imported trial answer can be treated as an earlier miss, changing both the trial's XP and its fixes ledger.
- **How it fails:** A student earns 20 XP for a correct difficulty-2 trial answer on Monday. Before accepting the import offer, they answer the same bundled question incorrectly in their account on Tuesday. Importing Monday's answer now awards only the 5-XP correction bonus and records a Monday fix, although Monday's answer preceded the miss. Answering those events chronologically awards 20 XP and no correction on Monday.
- **Fix:** Determine prior outcomes from the answer's chronological prefix, not the full pre-import log. Reconcile once-per-question credit explicitly so importing history neither duplicates existing credit nor treats later misses as earlier ones. Test that delayed imports produce the same per-question XP and fixes as chronological application.

### 3. [major] Every candidate question rebuilds the complete answer-history index

- **Where:** `pulsern/src/question-review.js:56` · confidence medium
- **Problem:** settledResult rebuilds latestResults(log) for every question and performs additional full-log scans for unmatched questions. unseenQuestions and reviewPools both invoke it per candidate, and App's dashboard and QBank run these calculations during answer-driven renders. The new lookup therefore scales with bank size multiplied by history length, repeatedly allocating the same result map.
- **How it fails:** With the intended 3,000-item bank and 3,000 logged answers, each pool pass performs roughly nine million history-row visits just to rebuild latest-result maps. A practice render performs multiple such passes, plus the fallback scans, putting substantial synchronous work and allocation on the student's main thread after answering or navigating. I could not benchmark the resulting delay on a phone.
- **Fix:** Build the latest-result and unresolved/raw-id indexes once per log change, and the catalog identity/peer indexes once per catalog change. Reuse those indexes across fresh, review, and Today pool construction. Add a representative large-bank regression or benchmark.
