## Findings

### 1. [blocker] Queued answers can disappear on ordinary page navigation

- **Where:** `pulsern/src/guest.js` · confidence high
- **Problem:** createSaveQueue keeps the newest snapshot only in a promise chained behind the active write. Only the sign-out handler waits for that queue. Closing the tab, reloading, or following the app's About link can destroy a snapshot before its storage task has even started. Before the eight-second timeout, there is also no unsaved-progress warning.
- **How it fails:** A pre-answer save is still in flight on a slow connection. The student checks another answer, which queues the updated log, then opens 'Meet the RN behind PulseRN' or closes the tab. The queued task never runs, and the account retains only the older snapshot. The checked answer is lost.
- **Fix:** Track whether the newest snapshot is durably saved and guard document navigation while it is pending. Flush internal full-page navigation explicitly, and provide unload protection for dirty progress. Do not rely on a queued promise surviving page destruction; add a browser regression test that leaves while an older write is stalled.

### 2. [major] An unavailable bank miss can strand the Today round

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** The q.catalogMiss branch provides only Retry, with no question-navigation controls or way to defer the item. A saved miss can legitimately remain absent from every successful catalog load after the reviewer withdraws that question. Retrying cannot recover such an item.
- **How it fails:** A student has a due miss on a subsequently rejected bank question. Today selects its catalogMiss card before new questions. Every Retry reloads an approved-only catalog that excludes the question, leaving the round stuck on the same card and preventing access to the remaining questions.
- **Fix:** Allow the unavailable item to be deferred without marking it correct or deleting its history, and continue the round using the existing held/deferred mechanism. Distinguish a withdrawn item from a transient load failure where possible. Test a successful catalog response that permanently omits the saved miss.

### 3. [major] Historical category names make legacy misses impossible to identify

- **Where:** `pulsern/src/question-review.js` · confidence high
- **Problem:** unresolvedCards filters candidates using exact equality with the saved category. Legacy saves can contain 'Psychosocial & Health Promotion', while the current catalog uses the split official categories. Migration 020 also compares these category strings literally, so it marks those rows unresolved, after which this filter removes their valid candidates.
- **How it fails:** A legacy save contains an incorrect answer for built-in question 19 with category 'Psychosocial & Health Promotion'. The current question is categorized as 'Psychosocial Integrity'. The student opens Review misses and receives 'Which question was this?' with no matching question button; Leave unresolved cannot repair or review the miss. The previous numeric-ID review path could serve it.
- **Fix:** Recognize historical category aliases and splits when matching legacy rows, both in the SQL relabel and the candidate filter, without rewriting the original stored history unnecessarily. Add coverage using the actual retired category name and current built-in questions.

### 4. [major] The migration rewrites progress without creating its advertised rollback snapshot

- **Where:** `pulsern/supabase/migrations/020_relabel_legacy_progress.sql:301` · confidence medium
- **Problem:** The migration creates backup_20261124 and its catalog helper tables, then updates public.progress, but never creates or populates backup_20261124.progress. The supplied rollback script depends on precisely that missing table. The backup comment does not make a migration-created snapshot exist.
- **How it fails:** On a database deployed from the repository migrations without an out-of-band backup table, migration 020 relabels student histories. Running the supplied rollback then fails with a missing-relation error, leaving no repository-provided way to restore the original blobs.
- **Fix:** Create and securely populate an idempotent pre-change progress snapshot before the UPDATE, transactionally with the migration, or make a verified backup an enforced deployment prerequisite. Test forward migration and rollback against a clean database. An existing production snapshot could not be verified from the supplied change.
