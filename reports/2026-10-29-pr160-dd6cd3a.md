## Findings

### 1. [major] Passage release can delete a replacement owner's claim

- **Where:** `pulsern/api/_speak.js` · confidence high
- **Problem:** releasePassage reads the claim, checks its owner, then removes the path in a separate storage operation. A takeover can replace the claim between that check and the removal. The owner check therefore does not enforce the documented guarantee that release removes only the caller's own claim.
- **How it fails:** A synthesis fails without saving a record, and its release is delayed by storage latency. Release reads owner A near the lease boundary. After the lease expires, B takes over and uploads its claim. A's delayed remove then deletes B's claim. C can now create a fresh claim while B is synthesising, so B and C both pay to voice the same passage. The daily spending cap still holds, but one-synthesis-per-passage exclusion does not.
- **Fix:** Make takeover and owner-checked release atomic, for example through a transactional database claim table/RPC with conditional update and delete operations. Add a concurrency test that pauses release after its owner read, completes a takeover, then resumes release and verifies that the replacement claim remains and a third caller stays busy. The existing sequential ownership test does not exercise this interleaving.
