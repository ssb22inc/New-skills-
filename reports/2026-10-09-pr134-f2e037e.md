## Findings

### 1. [blocker] Report uploads still run after the symlink guard rejects the checkout

- **Where:** `.github/workflows/pulsern-narrate.yml:209` · confidence high
- **Problem:** The link check exits with failure, but the subsequent report-reading, artifact-upload and save steps use `if: always()`. They therefore continue accessing the rejected checkout. The diagram-map and diagram-review workflows have the same defect. The regression test executes only the guard shell fragment, so it does not verify that downstream readers actually stop.
- **How it fails:** A selected branch contains `pulsern/reports/narration/run-env.md` symlinked to `/proc/self/environ`. The guard rejects it, but upload-artifact still traverses the reports directory and follows the link, placing the upload action's environment—including its Actions runtime credential—into a downloadable artifact. A failed workflow verdict does not undo that disclosure.
- **Fix:** Give checkout validation a step ID and require its successful outcome on every subsequent step that reads, uploads or writes branch files, including otherwise-always cleanup/save steps. Test the downstream step conditions as well as the guard itself.

### 2. [blocker] Valid imports can escape the diagram approval fingerprint

- **Where:** `pulsern/ops/diagram-attest.mjs:63` · confidence high
- **Problem:** The dependency scanner recognizes static imports only at the beginning of a line. Valid JavaScript such as `import React from "react"; import { LOW } from "../clinical/limits.mjs";` omits the second dependency from both the reviewer request and `sourceKey()`. The top-level directory hashing does not cover that nested clinical module.
- **How it fails:** After a diagram using that import layout receives approval, only `src/clinical/limits.mjs` changes its threshold from 7.35 to 7.30. The diagram's runtime interpretation changes, but its source key remains identical. `approval()` and `mapIsCurrent()` still accept the old review and pairings, bypassing the required diagram re-review.
- **Fix:** Use a syntax-aware dependency collector that handles valid import/export layouts and fails closed on unsupported loading mechanisms. Add a regression that changes a nested dependency referenced by the second import on one line and verifies that both the request and publication fingerprint change.

### 3. [major] Local reviews lose frame labels and produce different cache keys from CI

- **Where:** `pulsern/ops/review-diagrams.mjs:68` · confidence high
- **Problem:** The local path converts `imagePlan()` through `reviewData()`, which removes each image's label. It then passes `d.images` directly to `diagramRequest()`, whose prompt reads `p.label`. Only the prepared-data path runs `reviewPlan()` to reconstruct those labels.
- **How it fails:** `node ops/review-diagrams.mjs --only abg` sends a paid request listing every frame as `Image N: undefined`. Running the CI review afterward produces proper labels and therefore a different prompt-derived review key, paying again for unchanged content. Alternating local and CI runs continually invalidates the single cached entry.
- **Fix:** Normalize local and prepared entries through the same trusted frame-plan builder before constructing requests. Test that identical diagram data and PNGs produce identical labelled prompts and cache keys through both paths.
