## Findings

### 1. [blocker] Hyphenated E-R is discarded as a filler

- **Where:** `pulsern/ops/narrate-lib.mjs:246` · confidence high
- **Problem:** keepLetters protects "ER" and "E.R.", but not the hyphenated "E-R" spelling encouraged by the narration instructions. speechTokens subsequently joins "E-R" into "er" and removes it through FILLER. This both rejects a faithful transcript using "ER" and accepts a transcript that omits the qualifier entirely.
- **How it fails:** audioCheck("E-R tablets release medication slowly.", "Tablets release medication slowly.") returns pass: true. recordAll can therefore publish audio that incorrectly generalizes an extended-release property to all tablets.
- **Fix:** Preserve clinically meaningful abbreviations before filler removal, including hyphenated letter spellings, or stop treating "er" as droppable. Add paired tests proving that "E-R" matches "ER" and that deleting it fails. Increment QA_VERSION so recordings accepted by this rule are rechecked.

### 2. [blocker] Common U-300 spellings still select the U-100 insulin profile

- **Where:** `pulsern/src/diagrams/match.js:76` · confidence high
- **Problem:** The exclusion recognizes only an optional ASCII hyphen in "U-300". It misses "U 300" and "U‑300" with a nonbreaking hyphen. Both then match the generic glargine expression and produce type: "long", whose drawing and worked caption specifically represent glargine U-100.
- **How it fails:** extractInsulin("Insulin glargine U‑300 was given at 2100.") returns {type:"long", givenAt:"21:00"}. If the pairing is approved with values, the student receives the approximately 24-hour U-100 profile for a formulation that lasts longer. The pairing prompt's extracted-number check is not a deterministic formulation check.
- **Fix:** Normalize whitespace and Unicode hyphen variants before identifying formulations, and reject unsupported concentrations before selecting a profile. Add extraction and proposal tests for "U 300", "U‑300", and "U–300", alongside a passing U-100 case.
