## Findings

### 1. [blocker] Branch-controlled cache entries can impersonate completed reviews

- **Where:** `pulsern/ops/review-diagrams.mjs:83` · confidence high
- **Problem:** The trusted paid runner reads its approval cache from the untrusted branch. A matching key, completed=true and matching frames are sufficient to reuse a PASS without calling the reviewer. All these fields, including sourceKey, are publicly computable; none authenticates a completed paid review. The mapper and publication tests subsequently trust this same branch-controlled index.
- **How it fails:** A branch writes an index entry containing the locally computed review key, current sourceKey, expected frame names, completed=true and verdict=PASS. The paid review reuses it, exits successfully without asking the model, and the mapper accepts the diagram as visually approved.
- **Fix:** Accept cached approvals only from an authoritative trusted store or verify a signature produced by the trusted review job. Bind that attestation to the request/source digest, frame digests and actual verdict. Add an end-to-end test showing that a correctly hashed but fabricated branch cache cannot suppress the model call or authorize publication.

### 2. [blocker] Prepared screenshots are not proven to depict the pinned source

- **Where:** `pulsern/ops/review-diagrams.mjs:49` · confidence high
- **Problem:** The prepare job runs the branch's own preparation and rendering scripts. The paid job checks a self-reported commit, diagram IDs, step keys and frame labels, but never establishes that the supplied PNGs were rendered from that commit. Checking the inventory does not authenticate the pictures. The resulting approval nevertheless binds those pictures to the current sourceKey.
- **How it fails:** A modified or faulty prepare script supplies screenshots from an older, correct diagram, preserving every expected frame label and writing the current HEAD into plan.json. The paid runner accepts them and can record a current visual PASS even though students will see a different drawing. Including source text does not establish that the visual review examined the shipped rendering.
- **Fix:** Run a trusted preparation/rendering harness in the secret-less job rather than the branch's ops scripts. Render the pinned source in isolation, reject unexpected worktree changes, and bind the resulting artifact provenance to that commit. Add a regression test that substitutes stale frames while retaining the correct commit and complete inventory.

### 3. [blocker] TypeScript imports stop dependency traversal and preserve stale approvals

- **Where:** `pulsern/ops/diagram-attest.mjs:125` · confidence high
- **Problem:** resolveImport accepts .ts, .tsx and .mts files, but diagramSources treats everything except .js, .jsx and .mjs as data and stops following imports. Dependencies loaded by an accepted TypeScript module are therefore absent from both the review request and sourceKey.
- **How it fails:** A diagram imports src/clinical/interpret.ts, which imports src/clinical/thresholds.json. Changing a threshold used only for non-example patient values changes neither the collected source nor the example screenshot. The old visual approval and map remain current, allowing changed clinical interpretation logic to ship without renewed review.
- **Fix:** Parse and traverse every supported executable module format using the appropriate parser language, or reject unsupported formats explicitly. Apply equivalent handling to other accepted dependency-loading formats. Test a JSX-to-TypeScript-to-nested-JSON chain and require a leaf edit to change both the request and publication key.

### 4. [blocker] Audio QA drops ASCII micrometer units as hesitation words

- **Where:** `pulsern/ops/narrate-lib.mjs` · confidence high
- **Problem:** FILLER contains "um", and speechTokens removes it unconditionally. "um" is also the commonly used ASCII spelling of the micrometer unit. A recording that omits that unit can therefore pass the supposedly exact word check.
- **How it fails:** audioCheck("The particles measure 5 um.", "The particles measure five.") normalizes both sides to the same tokens and returns pass=true with similarity 1. The recording loses the measurement unit but is eligible for publication.
- **Fix:** Do not discard "um" unconditionally. Preserve unit-bearing tokens and normalize ASCII um, µm, μm and spelled-out micrometers consistently. Add positive and unit-deletion regression cases, bump QA_VERSION, and recheck clips approved under the weaker normalization.
