## Findings

### 1. [major] Build spec still promises 10*diff XP, which the new XP rules do not deliver

- **Where:** `pulsern/PULSERN_BUILD.md` · confidence high
- **Problem:** Section 5.4 says XP is `10 * diff as elsewhere, on full credit`. The new src/rewards.js answerXp instead pays 0 for too-fast/repeat answers and only a small fix bonus (5 XP) for a missed-then-corrected item, even when full credit is earned.
- **How it fails:** A developer following the spec to implement or test a new question type will assert that a full-credit NGN item awards `10*diff` XP. A correction of a missed full-credit item actually awards 5, and the test will fail or the implementation will be misjudged. The spec no longer describes the shipped behavior.
- **Fix:** Update §5.4 to reference src/rewards.js answerXp, for example: XP is awarded by answerXp — full first-try credit pays 10*diff, a corrected miss pays the fix bonus, and repeats/too-fast answers pay 0.

### 2. [major] No-row reset leaves legacy_hold=true and can silently drop an older tab's save before the first post-reset write clears it

- **Where:** `pulsern/src/App.jsx` · confidence medium
- **Problem:** In the store.delete reset path, when no progress row exists, `legacyHold` is set to true and the first subsequent `store.set` inserts the new row with `legacy_hold: legacyHold`, so the server row is created with legacy_hold=true. The revision-guard trigger drops revision-less writes when legacy_hold is true without parking them. The module clears legacyHold after the insert, but the server row stays true until a later update sends legacy_hold=false.
- **How it fails:** A brand-new account (no progress row) presses Reset. The first autosave inserts a row with legacy_hold=true. Before the next save flips that column, an older revision-less client for the same account sends an update; migration 022 sees `old.legacy_hold is not true` is false and returns old without inserting into progress_pending_merge. That older client believes the save succeeded, but its answers are discarded.
- **Fix:** When no row existed, do not set `legacyHold` for the resulting first insert: either set legacyHold=false before the insert path, or have the insert explicitly send legacy_hold:false for the no-row case, since there is no old row to protect.

### 3. [major] Streak icon changed from flame to heart

- **Where:** `pulsern/public/product/pulsern-adaptive-practice.png` · confidence high
- **Problem:** The top-bar streak indicator icon changed from a flame to a heart, which is a misleading label for the protected streak feature.
- **How it fails:** A nursing student sees a heart with a count of 0 instead of a flame, potentially misinterpreting it as a lives/health counter rather than a streak.
- **Fix:** Revert the top-bar icon to the flame to preserve the streak feature's visual identity.

### 6. [minor] New hard-coded colors bypass the app palette and dim theme

- **Where:** `pulsern/src/rewards-ui.jsx` · confidence high
- **Problem:** The RewardsStyle block introduces literals such as #24433C for .rw-dial-seg and .rw-dial-txt, rather than using the existing design-system variables. That is a new color outside the stated teal/green/monitor palette and it will not adapt correctly in dim mode.
- **How it fails:** A student using dim theme may see rank-dial segments or dial text rendered with low contrast because these literals are fixed rather than theme-aware. Future changes to the monitor palette will also leave these elements stale.
- **Fix:** Use the existing monitor/ECG palette variables or add theme-aware variables through the established Style variables instead of new hex literals.
