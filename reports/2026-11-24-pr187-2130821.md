## Assessment

Changes needed. The new verdict parser can turn an unfinished review into a passing status, and the marketing-source detector misses valid directory-index imports. The added tests do not cover either failure.

## Findings

### 1. [blocker] An unfinished final verdict can be discarded in favor of a passing example

- **Where:** `pulsern/ops/astra-review.mjs:529` · confidence high
- **Problem:** parseReviewText accepts the single completed object found anywhere in the answer. Its incomplete-verdict check only recognizes an unfinished object after a double-quoted assessment/findings key followed by a colon. An unfinished second object before that point is silently discarded, allowing an earlier example to determine the release verdict.
- **How it fails:** Return text consisting of {"assessment":"Example only","findings":[]} followed by a newline and {"assessment" with finishReason="stop". unclosedReview returns false, jsonObjectSpans returns only the completed example, and runReview records PASS and returns code 0 even though the final review did not complete. The same fail-open occurs with an unfinished single-quoted final verdict.
- **Fix:** Require the answer to contain exactly one complete verdict payload after narrowly defined unwrapping, rather than accepting an object extracted from arbitrary surrounding content. Reject additional unfinished object starts and ambiguous example/final-review combinations. Add end-to-end regression tests for these inputs with finishReason="stop" and assert a failed review status.

### 2. [major] Directory-index imports are omitted from marketing dependencies

- **Where:** `pulsern/ops/seo-page-change.mjs:35` · confidence high
- **Problem:** For extensionless imports, collectSources probes only basename.mjs/js/jsx/json. It never resolves directory index files, although Vite supports them. Consequently the collected set does not fulfill the stated contract of including every local file imported by the homepage.
- **How it fails:** landing.jsx imports a component from "./marketing-banner", implemented in src/marketing-banner/index.jsx. The import builds successfully, but the index file is absent from SOURCES. A subsequent commit changing only that component's public marketing copy makes marketingPagesChanged return false, so the workflow skips the model despite the homepage changing.
- **Fix:** Use resolution consistent with the actual build, including directory-index imports, or determine whether marketing output changed from the built artifacts. Add a fixture with an extensionless directory import and verify that changing its index.jsx requires review.
