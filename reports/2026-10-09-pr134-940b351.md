## Findings

### 1. [blocker] Image detection can hide executable HTML behind benign pixels

- **Where:** `pulsern/ops/astra-review.mjs:265` · confidence high
- **Problem:** The non-UTF-8 branch overrides the path classification and sends only an image attachment whenever the bytes begin with a recognized image signature. Valid image files can contain trailing data that image decoders ignore but an HTML parser executes. Neither the hash nor the rendered pixels expose that data.
- **How it fails:** Add pulsern/public/learn/example/index.html containing a valid small PNG followed by an HTML script element. The public server serves the .html path as HTML, allowing the appended script to execute. collectChanges instead classifies it as an image and sends benign pixels plus a hash, withholding the script from Astra.
- **Fix:** Do not allow image recognition to replace source review for HTML, JavaScript, or other executable/document paths. Fail closed on conflicting file types. For supported image paths, validate the image container and explicitly handle non-image payloads. Add a regression using a real decodable PNG with appended HTML under an .html path.

### 2. [blocker] Lossy filename decoding still turns unreadable changes into empty reviews

- **Where:** `pulsern/ops/astra-review.mjs:250` · confidence high
- **Problem:** Blob contents now use fatal UTF-8 decoding, but the NUL-delimited filename list still goes through gitIn's lossy UTF-8 string decoding. An invalid filename byte becomes U+FFFD. Subsequent blob reads address a different path, and blob() catches the errors and returns null, indistinguishable from an absent file. Collection can consequently produce an empty diff and no full content instead of failing.
- **How it fails:** Commit an in-scope file whose filename contains byte 0xFF. Git preserves that filename, but collection requests the replacement-character spelling. For an added generated page, both inputs to textDiff are then empty; for an ordinary source file, the replacement-character pathspec also matches nothing. The model receives the filename with '(no textual change)' and can return PASS without seeing its contents.
- **Fix:** Read the filename list as bytes and reject unsupported filename encodings before decoding, or preserve exact path bytes throughout collection. Also make any unexpected blob-read failure fatal; only the known absent side of an addition or deletion should become null. Test this with a real Git filename containing invalid UTF-8.

### 3. [blocker] Control-character escaping makes executable changes indistinguishable

- **Where:** `pulsern/ops/astra-review.mjs:213` · confidence high
- **Problem:** visibleControls replaces actual control characters with textual backslash-u markers without escaping existing literal markers. This representation is not one-to-one: actual U+2028 and the source characters \u{2028} produce identical review text, although JavaScript treats them differently.
- **How it fails:** The base contains a JavaScript line comment followed by the literal characters \u{2028} and a function call, so the call remains commented out. Replace those literal characters with an actual U+2028 line separator. The call now executes, but visibleControls makes the removed and added source lines look identical; the attached post-change file also looks like the original comment.
- **Fix:** Use an unambiguous source encoding that distinguishes literal backslashes from escaped controls, and explain that encoding in the review prompt. Add an end-to-end collection test for a literal marker changing into U+2028, proving both that the JavaScript behavior changes and that the representations remain distinguishable.

### 4. [major] Image tests do not exercise delivery through the actual review call

- **Where:** `pulsern/tests/astra-review.test.js` · confidence medium
- **Problem:** The valid-image test calls collectChanges and buildMessages directly. The runReview tests never review a valid image or assert the image-bearing outbound request. Removing messages: buildMessages(prompt, images) from runReview would leave these tests green while restoring hash-only reviews. The supplied files also do not establish whether llmCall forwards the new messages argument.
- **How it fails:** A regression drops the messages argument, or the adapter ignores it and constructs a text-only request from prompt. Astra receives image hashes but no images, returns an empty findings list, and the workflow posts PASS. The new image tests still pass because they only test the unused message-building helper.
- **Fix:** Exercise runReview with a real small image through the production LLM adapter and a mocked HTTP boundary. Assert that the outgoing request includes the exact before/after image attachments, and that losing this transport causes the test to fail rather than permitting a hash-only pass.
