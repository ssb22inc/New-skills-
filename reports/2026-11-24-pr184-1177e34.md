## Findings

### 1. [blocker] Answer replay discards XP earned from flashcards

- **Where:** `pulsern/src/guest.js:247` · confidence high
- **Problem:** Whenever the merged log contains an unseen attempt, reconcileProgress replaces local XP with replayed.xp. replayUnseen reconstructs only question answers; it does not include flashcard XP earned since the baseline. The flashcard schedule can survive while its earned XP disappears. The new regression test named "keeps a flashcard grade" supplies zero local XP and checks only the schedule, so it misses this failure.
- **How it fails:** Two devices start from XP 0. Device A grades a card Good and earns 5 XP. Device B answers a new question correctly and saves 10 XP. A's save encounters the revision conflict. Reconciliation retains the question and card schedule but writes 10 XP instead of 15. The same loss is possible when a failed card save is followed by a payload containing a new question answer.
- **Fix:** Preserve non-answer XP changes relative to the baseline when reconciling question attempts, with idempotent handling of retries and card undo. Add a regression using a real 5-XP card grade plus a concurrent question answer, and assert both the total XP and the retained schedule after saving and reloading.

### 2. [blocker] Conflict reconciliation overwrites server progress fields with stale local copies

- **Where:** `pulsern/src/guest.js:246` · confidence high
- **Problem:** The merged blob starts with {...local, log}, and only a few fields are subsequently reconciled. Server changes to examResults, customQs, fcNew, rewards, and other persisted fields are discarded even when this device never changed those fields. In particular, replayed rewards are ignored whenever local.rewards exists, which is always true for a migrated App save.
- **How it fails:** A student leaves the app open on a laptop, completes a never-repeat readiness exam on another device, then changes a setting on the laptop. The laptop's conflicting save retains the remote answer log but replaces the newly saved examResults with its old empty object. The exam attempt remains consumed, but its saved result is gone. Remote reward history and new-card usage can likewise be rolled back.
- **Fix:** Use the baseline to distinguish unchanged local fields from actual local edits across the entire persisted contract. Preserve server-only changes and explicitly merge per-form exam results, per-day reward history, new-card usage, and other collections. Exercise the actual conflict/refetch/save path with a remote completed exam and an unrelated local setting change.

### 3. [blocker] Concurrent answers are replayed in save order rather than answer order

- **Where:** `pulsern/src/guest.js:169` · confidence high
- **Problem:** mergeLogs orders new rows by at, but applyAnswer never writes an at timestamp into live answer rows. Imported trial rows also lose their original at value through applyAnswer. Consequently, conflicting live histories remain server-first followed by local-only answers, regardless of when those answers were actually given. latestResults and the Elo/SRS replay then operate on the wrong sequence.
- **How it fails:** From the same baseline, device A answers a question correctly, then device B answers that question incorrectly and saves. A's older answer saves afterward and conflicts. The merged history becomes [B's newer incorrect answer, A's older correct answer]. The app treats the question as corrected and advances its review ladder instead of retaining the latest miss and its one-day reset; Elo updates are also applied in reverse order.
- **Fix:** Record stable answer-time ordering metadata when each attempt occurs, preserve it through trial import and persistence, and merge new attempts in that order while retaining the baseline history. Use the same ordered history for latest-result lookup and deterministic replay. Add a test where an older local answer is saved after a newer remote answer to the same question.
