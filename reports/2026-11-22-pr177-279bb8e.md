## Assessment

Two issues need revision: the tour can hide its highlighted control, and the exam-exit tests omit the production navigation path that protects one-shot attempts. Review was based on the supplied diffs and images; tests were not run.

## Findings

### 1. [major] The missed-question tour target remains behind the bottom sheet

- **Where:** `pulsern/src/App.jsx:527` · confidence high
- **Problem:** scrollIntoView cannot scroll beyond the document's bottom. For students, qbank-review is effectively the last content in Practice, with only card padding and the body's 96px bottom padding below it. The tour sheet is substantially taller than that space. scroll-margin-bottom does not create additional scrollable space, so the highlighted Review misses controls remain behind the sheet.
- **How it fails:** On a 390×844 phone, a non-owner advances to 'Misses come back on a calendar'. Scrolling clamps at the page bottom, leaving the final button row underneath the tour dialog rather than visibly demonstrating Review misses.
- **Fix:** Provide enough tour-only trailing space to move the target above the sheet, or position the sheet based on the target's measured bounds. Add a browser assertion that the qbank-review target does not intersect the tour-card rectangle.

### 2. [major] Exam-exit coverage bypasses the production confirmation and navigation logic

- **Where:** `pulsern/tests/browser/exam-leave-harness.jsx:66` · confidence high
- **Problem:** Host reimplements requestLeave and calls examLeave.confirm directly. None of these tests exercises App's requestLeave → LeaveDialog → confirmLeave → applyLeave path. That newly added path decides whether a live, already-consumed exam may be unmounted, so its failure could lose responses without any of the new tests failing.
- **How it fails:** If production requestLeave navigates directly while an exam is running, or confirmLeave incorrectly treats the exam as inactive, Home discards the one-shot attempt without submitting it. The browser tests still pass because their separate Host implementation always invokes the correct hook branch.
- **Fix:** Exercise the real App Home control and confirmation dialog with mocked services, including Cancel, running, submitting, and recording states. Alternatively, extract the production request/confirm/navigation logic into a shared implementation used by both App and the harness instead of duplicating it.
