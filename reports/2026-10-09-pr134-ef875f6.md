## Findings

### 1. [blocker] Tag normalization still hides executable handler changes

- **Where:** `pulsern/ops/astra-review.mjs:111` · confidence high
- **Problem:** Removing whitespace around every unquoted '=' changes HTML attribute boundaries. Two tags with different browser behavior can therefore produce identical digests, leaving the reviewer with '(no textual change)'. Preserving quoted values does not close this bypass.
- **How it fails:** Change `<img src=x onerror=window.x =alert(1)>` to `<img src=x onerror=window.x=alert(1)>`. In the first tag, the onerror handler is only `window.x`; in the second, a failed image load executes `alert(1)`. normaliseTag() produces the same output for both.
- **Fix:** Preserve raw tag source, or use browser-compatible parsing with a lossless fallback rather than normalizing unquoted content. Add this pair as a regression test through both pageDigest() and collectChanges().

### 2. [blocker] Dependency summaries omit installation-affecting flags

- **Where:** `pulsern/ops/astra-review.mjs:161` · confidence high
- **Problem:** LOCK_FIELDS excludes fields such as dev, optional and devOptional. Changes to these fields alter npm installation behavior but generate an empty dependency-summary diff. The full lockfile is never supplied as a fallback.
- **How it fails:** A package already marked with `hasInstallScript: true` changes from `dev: true` to a production dependency by removing its dev flag. With `npm ci --omit=dev`, that package and its installation script now run where they were previously omitted, but the review sees no change.
- **Fix:** Digest all package metadata deterministically rather than maintaining a partial allowlist, and retain or reject unsupported lockfile structures instead of silently omitting them. Add regression tests for changes to dev, optional and devOptional.

### 3. [blocker] Audio QA erases negative signs before comparing numbers

- **Where:** `pulsern/ops/narrate-lib.mjs:50` · confidence high
- **Problem:** wordsToNumbers() replaces every hyphen with a space, including a numeric minus sign. Both speechSimilarity() and speechTokens() use this transformation, so the new exact-word check still considers a positive value and its negative equivalent identical.
- **How it fails:** For the ABG pH narration, a transcript that faithfully reproduces the script except for writing `-7.35` instead of the spoken `seven point three five` passes audioCheck(). A recording that incorrectly says 'minus seven point three five', transcribed numerically, can therefore be uploaded and published.
- **Fix:** Distinguish compound-word hyphens from signed numeric values and preserve signs in the comparison. Add paired positive and negative tests using the actual narration scripts, including digit-form and spoken-form negative numbers.

### 4. [major] The shipped-map test rejects every newly generated map

- **Where:** `pulsern/tests/concept-explainers.test.jsx:75` · confidence high
- **Problem:** The test still requires item-map.json version 1, while buildItemMap() now always emits version 2. The existing fixture can pass without exercising the format produced by the changed mapper.
- **How it fails:** Run ops/map-diagrams.mjs successfully, including a dry run that reaches save(), and commit its output. The next npm test fails at this assertion even when every pairing and sourceKey is valid.
- **Fix:** Migrate the checked-in map and its validation test to version 2. Validate the new content fingerprints and sourceKey requirements, and add a producer-to-consumer test using buildItemMap() output.
