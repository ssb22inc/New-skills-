## Assessment

Do not merge. The change replaces audio verification with an unconditional passing verdict. The voice migration also loses pending legacy work and fails on a fresh storage setup. The new dollar budget is not reflected in queue responses. Tests were reviewed from the supplied diff, not executed.

## Findings

### 1. [blocker] Nonempty audio is now automatically declared accurate

- **Where:** `pulsern/api/_speak.js:666` · confidence high
- **Problem:** makeChecked returns pass: true and similarity: 1 for every nonempty AudioStream without inspecting what it says. saveChecked persists that invented verdict, and speak serves the clip as approved audio. A hash binds bytes to a record; it does not establish that the bytes speak the requested words. Switching TTS providers does not preserve the existing accuracy gate. The changed tests explicitly remove wrong-number rejection coverage and still describe this path as an accuracy gate.
- **How it fails:** For the script "Potassium 2.9 milliequivalents per liter.", a completed clip that says 9.2, drops a negation elsewhere, or is truncated receives a passing record and reaches students. No check in this path can reject that mismatch.
- **Fix:** Restore independent verification of the generated audio before writing a passing record or serving it. Reinstate integration tests that supply a wrong number, changed unit, and dropped negation and assert that no playable clip is published. Exercise the Polly production branch rather than only the separate fetch fake.

### 2. [major] Pending marin requests are discarded rather than migrated

- **Where:** `pulsern/ops/read-aloud-worker.mjs:500` · confidence high
- **Problem:** queueLegacyMarin migrates only passages with an existing marin MP3. Pending queue and retry entries normally have no MP3, so they are excluded. drainQueue then deletes those entries because raw.voice is not Joanna. CHECK_VERSION remains unchanged, so an existing completed or advanced prewarm cursor does not restart to recover the omitted passages.
- **How it fails:** An old run finishes its bank scan while leaving a failed passage in queue-retry. After deployment, the migration skips that passage because it has no saved MP3, drainQueue deletes its marin entry, and prewarmBank returns immediately because its completed scan is less than seven days old. The student's pending request disappears until another Listen request or the weekly rescan.
- **Fix:** Migrate valid pending legacy queue and retry entries before deleting old-voice work, rebuilding their text against the current approved bank. Bind the prewarm cursor to the voice configuration so a provider change restarts the scan. Add an upgrade test with a completed legacy cursor and an unvoiced legacy retry.

### 3. [major] The migration prevents first-use bucket creation

- **Where:** `pulsern/ops/read-aloud-worker.mjs:516` · confidence high
- **Problem:** The CLI always calls queueLegacyMarin before runJob. On a fresh setup, missing-bucket reads are treated as empty, but writing polly-revoice.json uses the worker's plain put helper, which does not create the bucket. That write fails and the CLI exits before reaching the existing bucket-creation paths.
- **How it fails:** With AWS and Supabase credentials configured but no read-aloud bucket or previous Listen request, every scheduled run exits with "Could not queue the existing marin clips". Bank prewarming cannot initialize itself, contrary to the documented first-use behavior.
- **Fix:** Ensure the private bucket exists before running migration, or make migration writes use the same safe create-on-missing behavior as the speech storage helpers. Test the actual worker initialization sequence against a missing bucket.

### 4. [major] Queue responses ignore exhaustion of the new dollar budget

- **Where:** `pulsern/api/_speak.js:745` · confidence high
- **Problem:** queuedReply checks only the synthesis-count cap. The worker now also stops at the character budget, but the route still receives plain LIMITS without that budget and never examines the character counters. Consequently, its documented after: "tomorrow" response is absent when the dollar cap stops work.
- **How it fails:** At the default $40 budget, 12,500 passages reserving 200 characters each exhaust the character allowance while remaining below the 15,000-synthesis cap. The worker stops for the day, but subsequent Listen requests continue receiving ordinary queued responses instead of the next-day indication. The new test named "caps a day" only checks configuration arithmetic and cannot catch this behavior.
- **Fix:** Make the route observe the worker's effective daily character limit or a durable budget-exhausted marker, and return after: "tomorrow" when either cap is exhausted. Add a behavioral test that exhausts characters while leaving synthesis slots available.
