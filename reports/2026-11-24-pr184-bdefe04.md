## Findings

### 1. [blocker] A failed device save silently loses trial answers during sign-up

- **Where:** `pulsern/src/guest.jsx:37` · confidence high
- **Problem:** The persistence effect ignores saveGuest's false return value. The trial still says the answers are saved and that everything will move into the account, but the authentication transition unmounts GuestTrial and discards its in-memory state. Account handoff reads only the device copy.
- **How it fails:** localStorage.setItem throws QuotaExceededError while the student answers trial questions. The student then selects Create free account. The authentication screen and signed-in app find either no trial or an older partial copy, so the remaining answers, XP and ability updates are permanently lost without warning.
- **Fix:** Handle device-write failures explicitly. Retain the trial through the authentication transition or prevent that transition from discarding the only copy until persistence succeeds. Show a truthful unsaved/retry state, and add an integration test where setItem throws during the trial.

### 2. [major] Guest aliases fail when the same seeded question has a different database ID

- **Where:** `pulsern/src/guest.js:115` · confidence high
- **Problem:** linkBuiltInGuest requires both the built-in numeric ID and stem to match. Shared-bank IDs are database-generated and are not guaranteed to equal the bundled IDs. Consequently, identical seeded content under another database ID receives no guest alias and remains in QBank's fresh pool.
- **How it fails:** A student correctly answers bundled question 1 during the trial, which merges as guest-1. The bank contains that same question as ID 1001 because other rows existed before seeding. Practice serves ID 1001 as new, awards first-answer XP again and records another ability observation for content the student has already answered. The existing test covers a matching numeric ID and an unrelated stem, but not this case.
- **Fix:** Resolve built-in identity independently of the database row ID, using a stable source key or verified content fingerprint, while preserving the protection against unrelated questions sharing a number. Test identical content with different database IDs as well as different content with the same ID.

### 3. [major] Session recap loses card grades when the session crosses midnight

- **Where:** `pulsern/src/rewards.js:470` · confidence high
- **Problem:** The recap subtracts the starting day's card count from the current day's card count. These counters belong to different local dates after midnight, so their difference is not the number of cards reviewed in the session.
- **How it fails:** A student starts a Today round at 23:55 after reviewing five cards earlier that day, grades two more before midnight and three after midnight. The recap calculates max(0, 3 - 5) and displays zero cards instead of five.
- **Fix:** Track a session-level grade count independent of the daily ledger, or aggregate grades across all participating local dates while subtracting the starting-day baseline. Add a recap regression test that advances the local clock across midnight.
