## Assessment

Not ready to approve. The changes close several earlier gaps, but publication controls, pairing freshness, and review-error recovery still have concrete defects. This was a static review; I did not run the tests or verify repository-level branch protection and environment settings.

## Findings

### 1. [blocker] Fully qualified refs bypass the prohibition on publishing directly to main

- **Where:** `.github/workflows/pulsern-narrate.yml:49` · confidence medium
- **Problem:** The guard rejects only the literal inputs main and master. actions/checkout accepts refs/heads/main, and the later push becomes HEAD:refs/heads/main. The same bypass exists in pulsern-diagram-map.yml and pulsern-diagram-review.yml.
- **How it fails:** Dispatch narration with branch=refs/heads/main. The guard passes, main is checked out, and the workflow attempts to commit the generated manifest directly to main without a reviewed PR. If repository rules permit this token to push, the required review is bypassed; GITHUB_TOKEN pushes also suppress ordinary push-triggered workflows. Branch protection might prevent the final push, but that configuration was not supplied.
- **Fix:** Validate and normalize branch inputs before checkout. Reject the repository's actual default branch, including fully qualified aliases, and reject non-branch refs. Use the validated canonical branch consistently for checkout, push, concurrency, and PR lookup. Add tests covering refs/heads/main and a non-main default branch.

### 2. [blocker] Question edits to options or the answer leave obsolete pairings visible

- **Where:** `pulsern/src/diagrams/fingerprint.js:25` · confidence high
- **Problem:** The runtime question fingerprint includes only stem and rationale, whereas the pairing decision depends on options and the keyed answer too. The mapper also extracts diagram parameters from options. The new diagram-content fingerprint does not close this question-side freshness gap.
- **How it fails:** A bank item is corrected from NPH to regular insulin in its options while retaining its stem, administration time, and general peak-risk rationale. Its old pairing can still carry type=nph. pairsFor accepts that pairing because both runtime fingerprints still match, so the student receives the old insulin's peak window until the mapping job runs again. An answer-only correction likewise does not invalidate the pairing.
- **Fix:** Fingerprint all question content used by pairing review and parameter extraction, including options and the keyed answer, using a canonical representation shared by the mapper and client. Rebuild existing pairings and add options-only and answer-only mutation tests.

### 3. [blocker] The spoken and overview glargine claims still omit the U-100 restriction

- **Where:** `pulsern/src/diagrams/insulin.jsx:274` · confidence high
- **Problem:** The data and long-step caption now correctly restrict the approximately 24-hour profile to glargine U-100, but the new narration still says simply that glargine provides a background level for about 24 hours. The visible overview table likewise says only Long · glargine. The U-300 distinction in the facts array is not displayed in that overview.
- **How it fails:** A student studying the static table or listening to the narration learns an unqualified glargine duration of approximately 24 hours and applies it to glargine U-300, despite this file explicitly recognizing its longer duration. Saying that other basal insulins differ does not identify another formulation of glargine as excluded.
- **Fix:** Identify glargine U-100 explicitly in the visible table and spoken narration, not just in metadata, the SVG description, and one caption. Regenerate the affected recording and test the visible and spoken product qualification.

### 4. [major] A transient review error becomes a permanently cached rejection

- **Where:** `pulsern/ops/review-diagrams.mjs:56` · confidence high
- **Problem:** Operational errors are saved in the index as FAIL with the same content key used for completed reviews. On the next run, the unchanged-key branch skips the reviewer regardless of whether the previous review actually completed. The new publication gate then treats this cached operational failure as a rejected diagram.
- **How it fails:** A diagram's first review encounters a timeout, authentication error, or malformed model response. After the underlying problem is fixed, rerunning pulsern-diagram-review on the same code skips the call and returns FAIL again. The workflow does not expose --force, so its normal retry path cannot recover, and the mapper continues withholding the diagram.
- **Fix:** Record whether a valid review completed separately from its clinical verdict. Reuse cached verdicts only for completed reviews; retry operational failures automatically. Add an end-to-end test in which the first call throws and the second call, with identical content, succeeds.
