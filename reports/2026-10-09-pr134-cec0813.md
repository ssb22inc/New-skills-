## Assessment

Not ready to merge. The signed-record pipeline still trusts branch-supplied data in ways that can bypass content checks, and a keyless narration dry run can erase paid clip records. These findings are based on the supplied code; I could not run CI or verify GitHub environment protections.

## Findings

### 1. [blocker] Prepared proposals can revive pairings the current matcher rejects

- **Where:** `pulsern/ops/map-diagrams.mjs:52` · confidence high
- **Problem:** In prepared mode, proposePairs reads PLAN.proposals rather than evaluating the pinned source's matcher. checkInventory verifies diagram IDs and step keys, not proposals. Both the cache-reuse check and publishable then compare decisions against this same untrusted proposal data, allowing the trusted job to sign a current map without checking what today's matcher actually proposes.
- **How it fails:** A signed cached decision contains an insulin pairing that a matcher correction now excludes. The branch-controlled prepare script supplies the old proposal and extracted values. Once the diagram has a current visual approval, the paid job accepts the old decision's signature, skips another pairing review, and signs the obsolete pairing with the new sourceKey. The publication tests accept it, and the client displays it.
- **Fix:** Compute proposals from the pinned matcher using trusted preparation code in an isolated, secret-free execution environment, rather than accepting output from the branch's ops script. Ensure reused decisions are compared with that authenticated result. Add an end-to-end test where prepared proposals disagree with the pinned matcher and publication is refused.

### 2. [blocker] Narration signatures do not establish that the recorded script belongs to the source

- **Where:** `pulsern/ops/prepared.mjs:40` · confidence high
- **Problem:** narrationPlan accepts arbitrary branch-supplied narration after checking only its shape. The paid job records and signs those words without comparing them with the pinned diagram's narration. The publication test verifies the signature and QA version but never checks the signed clip ID against the real script. At playback, the only script binding is the 32-bit FNV textFp, which is not resistant to deliberately constructed collisions.
- **How it fails:** A branch prepare script supplies a clinically incorrect sentence for an existing diagram and step, with a suffix chosen to collide with the real narration's FNV fingerprint. TTS and transcription QA agree on the supplied incorrect sentence, so the trusted job signs it. CI accepts the signature, and audioFor accepts the colliding textFp, playing words that the diagram's clinical review never approved.
- **Fix:** Obtain narration from the pinned source through trusted preparation code, and bind each signed clip to a cryptographic digest of the exact script. Before publication, compare that digest and recording configuration with the actual diagram step, not merely with fields supplied by the preparation artifact. Test a mismatched prepared script and an FNV collision.

### 3. [blocker] A keyless dry run deletes existing narration records

- **Where:** `pulsern/ops/narrate.mjs:51` · confidence high
- **Problem:** When --dry-run runs without PULSERN_ATTEST_PUBLIC_KEY, KEYS.verify always returns false. Consequently every existing clip fails isCurrentClip, its manifest entry is deleted, and the DRY branch calls save(), overwriting narration.json with the emptied clip collections.
- **How it fails:** After paid narration has been committed, a developer runs the documented local --dry-run command without signing-key configuration. Even with unchanged scripts and voice, the command removes all current clip records and their audio URLs from the tracked manifest. The existing prepared-run test starts with an empty manifest, so it does not catch this loss.
- **Fix:** Make dry runs leave the manifest and decision records unchanged; write only a separate planning report. An unavailable verification key should be reported as unverifiable, not converted into destructive invalidation. Add a test that starts with populated signed clip records, omits the public key, runs --dry-run, and asserts byte-identical manifest contents.
