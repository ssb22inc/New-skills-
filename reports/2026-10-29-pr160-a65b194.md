## Findings

### 1. [blocker] The audio gate does not protect clinically significant terminology

- **Where:** `pulsern/api/_speak.js:107` · confidence medium
- **Problem:** voiceCheck adds exact unit matching to audioCheck's documented similarity/number/negation/direction checks, but does not require diagnoses, medications, or other clinical terms to agree. A clinically opposite word can therefore fit within the allowed transcription difference and produce a passing record. This is not the word-for-word verification described in HUMAN_TASKS.md.
- **How it fails:** Use the long medication-record prefix already present in the tests, followed by "The client has hypokalemia." Have the transcription return the same passage with "hyperkalemia" instead. Numbers, units, negations and direction words remain unchanged, and similarity remains above 0.92. Under audioCheck's documented contract, that incorrect explanation passes and is cached for students. I could not execute this example because the imported comparator's implementation was not supplied.
- **Fix:** Reject non-equivalent clinical wording before publishing audio, rather than relying on overall similarity and the current protected-token lists. Add adversarial tests for long passages with changed diagnoses, medication names and clinical qualifiers, including hypokalemia versus hyperkalemia.

### 2. [major] Repeated worker attempts reuse one budget reservation indefinitely

- **Where:** `pulsern/ops/read-aloud-worker.mjs:40` · confidence high
- **Problem:** The worker assumes the queue-time reservation covers its first synthesis on every run. When synthesis succeeds but transcription fails, makeChecked returns a non-final result and the entry remains queued. The next run pays for another synthesis without claiming another slot. Only second takes within an individual invocation are metered.
- **How it fails:** Queue one passage with a global limit of one. Let OpenAI speech synthesis succeed and transcription return 429 or 500. Every scheduled run retries and pays for speech again, despite the only global slot already being consumed. A failed retake reservation can similarly leave the passage repeating unmetered first takes on subsequent runs.
- **Fix:** Make each worker synthesis attempt claim a durable spending reservation, including first takes on later runs. Separate queue-admission quotas from synthesis-attempt quotas if necessary to avoid double charging. Test repeated drains after transcription failures and assert that paid calls stop at the configured limit.

### 3. [major] A transient queue download error deletes valid queued work

- **Where:** `pulsern/ops/read-aloud-worker.mjs:32` · confidence high
- **Problem:** A download error is converted to job = null and then handled as a malformed entry. The worker removes the queue object instead of retaining it for retry, even though it never obtained or validated its contents.
- **How it fails:** Supabase listing succeeds, but downloading a valid queued passage returns a transient storage error. The subsequent remove succeeds, permanently dropping that request without producing audio or reporting an error. The passage is only queued again if a student explicitly requests it, consuming another quota reservation.
- **Fix:** Handle download failures separately from successfully downloaded but malformed entries. Preserve the object, report the operational error and retry later. Add a test where download fails temporarily and verify that the queue entry remains and no synthesis occurs.
