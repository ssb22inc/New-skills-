## Assessment

Do not merge yet. The review boundary still permits an unreviewed workflow to obtain the status-publisher key, and narration QA can erase clinically significant units. Paid diagram reviews also lack the checkpoint protection used by the code reviewer. This assessment is based on the supplied code; tests, browser checks, and GitHub settings were not independently executed or verified.

## Findings

### 1. [blocker] An unreviewed workflow can obtain the trusted status-publisher key

- **Where:** `pulsern/ops/astra-review.mjs:59` · confidence high
- **Problem:** IN_SCOPE excludes root workflows whose names do not start with pulsern-. The new astra-review environment restriction protects a branch, not a particular workflow: another workflow running on the default branch can request that environment and read ASTRA_APP_KEY. Consequently, silently excluding other workflow files defeats the new App-based trust boundary even when the environment is configured exactly as documented.
- **How it fails:** A PR adds an innocuous PulseRN documentation change and .github/workflows/bypass.yml. The latter runs on pushes to main, requests environment astra-review, and reads the App key. Only the documentation reaches Astra, so the PR can receive a genuine passing App status. Once merged, the excluded workflow runs on main and can mint App tokens to certify subsequent commits without review.
- **Fix:** Review all root workflow changes that can access this security boundary, or refuse to certify PRs containing such excluded control-plane changes until a separate trusted review approves them. Add an end-to-end regression using a differently named workflow. Do not treat a default-branch environment restriction as workflow-specific authorization.

### 2. [blocker] Narration QA silently equates micrograms with grams

- **Where:** `pulsern/ops/narrate-lib.mjs:207` · confidence high
- **Problem:** speechTokens discards every character outside ASCII letters, digits, and periods after handling a limited symbol list. normaliseSpeech similarly discards unrecognized symbols. Neither preserves the micro sign or Greek mu, so both independent conditions in audioCheck lose the same clinically significant information.
- **How it fails:** audioCheck("The label reads 5 μg. Verify units against your course materials.", "The label reads 5 g. Verify units against your course materials.") returns pass: true: both normalized strings and token sequences are identical. A recording that changes a microgram quantity to a gram quantity can therefore be published as verified. The same failure occurs with the common µg spelling.
- **Fix:** Normalize recognized clinical units to explicit equivalent tokens, including both µg and μg, and fail closed on unhandled meaning-bearing symbols rather than deleting them. Add faithful-transcript and corrupted-transcript tests for these units, then increment QA_VERSION so previously accepted recordings are rechecked.

### 3. [major] A stopped paid diagram review leaves no attempt record

- **Where:** `pulsern/ops/review-diagrams.mjs:64` · confidence high
- **Problem:** The script awaits reviewOne and its paid request before creating any report or updating the index. Error handling only helps when the promise settles. Unlike runReview in astra-review.mjs, there is no checkpoint before spending, despite this workflow's promise to keep every paid review.
- **How it fails:** The provider accepts a diagram-review request, but the connection hangs or the workflow reaches its timeout while awaiting the response. No record for that attempt exists under reports/diagram-review; the artifact/save steps can preserve only earlier reports. A subsequent run repeats the request without any local record of the paid attempt.
- **Fix:** Write a uniquely named incomplete-attempt report before invoking the paid reviewer, and finalize that same attempt afterward. Give the paid step a timeout shorter than the job timeout so artifact and commit cleanup can run. Test the checkpoint with an injected reviewer promise that never resolves.
