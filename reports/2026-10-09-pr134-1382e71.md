## Findings

### 1. [blocker] New files can masquerade as historical review reports and bypass review

- **Where:** `pulsern/ops/astra-review.mjs:85` · confidence high
- **Problem:** OWN_REPORTS exempts every file under pulsern/reports/astra based solely on its path. It does not establish that the file is a historical report or came from the trusted reviewer. The exemption also occurs before the new byte and symlink checks. A change containing only such files returns PASS without calling the model.
- **How it fails:** A PR adds pulsern/reports/astra/debug.md containing a service-role credential copied from an operational log. collectChanges skips its contents, and runReview reports that there is nothing to review. The credential is committed despite the non-negotiable secrets rule.
- **Fix:** Review newly added or modified files in this directory like other PulseRN files. Keep trusted review archives on the separate reviews branch, or require independently verified provenance before exempting an archive entry. Add an end-to-end test proving an arbitrary new file here cannot obtain a no-review PASS.

### 2. [blocker] Cached visual approval can be renewed after a worked caption changes

- **Where:** `pulsern/ops/review-diagrams.mjs:61` · confidence high
- **Problem:** The reuse key covers diagramHash and PNG bytes, but diagramHash excludes dynamicCaption and its computed output. The review prompt includes that output. This branch nevertheless replaces the old sourceKey with the current one whenever the narrower key matches, certifying clinical text that was not part of the cached review.
- **How it fails:** Only abg.dynamicCaption changes, introducing an incorrect worked-example interpretation. The drawing, facts and static steps remain unchanged, so the PNGs and reviewKey remain identical. The review job skips Astra, updates sourceKey, and the publication guard accepts the diagram with its new, unreviewed caption.
- **Fix:** Bind cache reuse to all content actually submitted for review, including computed captions and dynamic-step flags. Changes to clinical caption-generation logic must also invalidate the relevant approval rather than being treated as layout-only changes. Add a regression that changes only dynamicCaption and requires a new review.

### 3. [major] Upload failures mentioning nonexistence are treated as successful duplicates

- **Where:** `pulsern/ops/narrate.mjs:130` · confidence medium
- **Problem:** The duplicate-error test matches any occurrence of 'exist', not just an already-existing object. An error such as 'The specified bucket does not exist' is therefore ignored, and the manifest and report record the clip as successfully shipped despite no upload.
- **How it fails:** The bucket becomes unavailable after the initial getBucket check, and an upload returns a 404 message containing 'does not exist'. The run publishes a dead audio URL and can finish successfully. The player then fails to play that narration.
- **Fix:** Accept only the provider's explicit already-exists error code/status. Throw for not-found and other failures. Add upload-boundary tests covering both a genuine duplicate and a nonexistence error, asserting that the latter never writes a manifest entry.

### 4. [major] Git-quoted PNG filenames break the new mandatory CI check

- **Where:** `pulsern/ops/check-png-canonical.mjs:67` · confidence high
- **Problem:** git ls-files is read in its display format and split on newlines. Git quotes and escapes filenames containing non-ASCII characters, tabs or newlines. Those display strings are passed directly to readFileSync rather than decoded as filenames. The new PNG unit test uses the same unsafe enumeration.
- **How it fails:** A valid tracked image named public/pédiatrie.png passes the reviewer's exact UTF-8 path handling, but this check attempts to open Git's quoted, octal-escaped representation and throws ENOENT. The mandatory CI job fails before testing the image.
- **Fix:** Use git ls-files -z and split on NUL in both this script and tests/png-canonical.test.js. Add a fixture repository with an accented PNG filename to exercise the actual enumeration and read path.
