## Assessment

Do not ship yet. Three defects remain in legacy-progress handling: repeated answers can be discarded, calibrated Elo updates can be changed, and corrected legacy misses can lose their scheduled reviews. This assessment is based on the supplied changes; I did not run the tests or build.

## Findings

### 1. [blocker] Preserve repeated occurrences in parked legacy answer logs

- **Where:** `pulsern/src/guest.js:474` · confidence high
- **Problem:** foldPendingProgress identifies new rows using whether any current row has the same pendingRowKey. Legacy answers have no attempt ID or timestamp, so two legitimate attempts with the same question ID and outcome have identical keys. The subsequent no-new-rows branch restores current.log and current.ability, discarding the additional attempt.
- **How it fails:** Stored progress contains one legacy miss on question 9. An older open app submits a snapshot containing that miss followed by another incorrect review of question 9. reconcileProgress retains both occurrences, but newRows considers both already present. After absorption and deletion of the parked snapshot, only one answer remains and the second ability update is lost.
- **Fix:** Match legacy rows by occurrence count rather than set membership. Retain the reconciled log and apply only unmatched occurrences. Add a regression with stored log [miss] and parked log [miss, miss], asserting two answers and two ability updates after absorption and after an idempotent retry.

### 2. [blocker] Do not replace calibrated legacy Elo updates with difficulty seeds

- **Where:** `pulsern/src/guest.js:481` · confidence high
- **Problem:** The absorption loop rebuilds ability from current.ability using answerInput(row). Old shipped log rows contain neither rating nor source, so answerInput supplies an empty calibration. This replaces the old client's calibrated update with a difficulty-seed update, even though the incoming snapshot carries its computed ability.
- **How it fails:** Starting at theta 1200 and n=0, an older client correctly answers a difficulty-1 bank item calibrated at 1700. Its ability becomes approximately 1237.87. When that snapshot is parked and absorbed, this loop uses the difficulty-1 seed of 1100 and saves approximately 1214.40 instead. The student's ability, subsequent adaptive selection, and readiness estimate change incorrectly.
- **Fix:** Reconcile legacy ability updates without silently substituting seed ratings. Preserve the incoming computed ability where applicable, or obtain the calibration needed for a valid replay. Add a test using a bank rating substantially different from its difficulty seed and assert theta, not only n.

### 3. [major] Keep due reviews for corrected but unresolved legacy questions

- **Where:** `pulsern/src/question-review.js:305` · confidence high
- **Problem:** Unresolved cards are created only when the latest unresolved outcome is incorrect. A corrected legacy miss still has a scheduled review, but scheduleEntry refuses its raw numeric date because the identity is unresolved. Consequently, neither the real question nor an unresolved placeholder enters the due pool.
- **How it fails:** Migration 020 marks a legacy question ambiguous because its number and category match both a built-in and a bank item. Its history is wrong, then correct, with missSchedule[7] due today. historyIndex records the latest unresolved result as true, this loop omits the resolution card, and scheduleEntry returns null for both candidates. Today never serves the scheduled review, and Review Misses offers no way to identify that scheduled answer.
- **Fix:** Create a schedule-aware unresolved review when a raw legacy review date becomes due, even if the latest outcome was correct. Associate resolution with the relevant recorded occurrence and supply its catalog candidates. Add a regression using ambiguous wrong-then-correct history with a due numeric schedule.
