## Findings

### 1. [blocker] The PR still controls the supposedly trusted workflow

- **Where:** `.github/workflows/pulsern-astra-review.yml:23` · confidence high
- **Problem:** A pull_request workflow uses the workflow definition from the PR merge ref. Checking out the reviewer from the base branch does not protect the steps that select and invoke it. A PR can modify this YAML to bypass the trusted reviewer, fabricate rc=0, or execute PR-controlled code with the supplied secret. The new base-branch test checks for strings, not this trust boundary.
- **How it fails:** A same-repository PR changes the review step to emit rc=0 without invoking Astra. That modified workflow runs for the PR and produces a successful review check, despite the base branch containing an uncompromised reviewer.
- **Fix:** Run the orchestration through a base-defined trusted workflow or enforced required-workflow policy. If using pull_request_target, treat PR files strictly as data and remove the automatic execution of PR code during bootstrap; perform bootstrap through a separately approved process. Bind the result to the reviewed head SHA.

### 2. [major] Fork PRs satisfy the check without any review

- **Where:** `.github/workflows/pulsern-astra-review.yml:42` · confidence high
- **Problem:** The job-level condition skips every fork PR. GitHub treats a conditionally skipped job as successful for required-check purposes, so making this review check required does not make fork contributions fail closed.
- **How it fails:** A non-draft fork PR changes grading or approval logic. The review job is skipped, no report or adversarial review exists, and this check does not prevent merging.
- **Fix:** Review fork diffs through the trusted, data-only execution path without running fork code. If review cannot be performed, produce an explicit failing check rather than skipping the job.

### 3. [major] Git-quoted filenames are silently dropped from the review

- **Where:** `pulsern/ops/astra-review.mjs:268` · confidence high
- **Problem:** The name-status parser assumes Git prints literal, tab-separated paths. Git normally quotes paths containing non-ASCII characters, tabs, or newlines. A quoted path begins with a quotation mark, fails IN_SCOPE, and is silently treated as outside PulseRN. No test exercises collection from a real Git diff.
- **How it fails:** A PR changes only pulsern/public/révision.html. With Git's default core.quotePath behavior, name-status returns a quoted, escaped filename. collectChanges drops it, and main returns PASS with 'No PulseRN files changed' without making a review request.
- **Fix:** Use git diff --name-status -z and parse its NUL-delimited status/path records without trimming or decoding quoted display output. Add temporary-repository integration tests covering Unicode, tab, and newline filenames and assert that their actual diffs reach the prompt.

### 4. [major] Generated-page exclusions have no generation-integrity check

- **Where:** `pulsern/ops/astra-review.mjs:64` · confidence medium
- **Problem:** Files are excluded solely because their paths look generated. The reviewer neither verifies that they match generator output nor ensures their corresponding source was reviewed. A PR containing only excluded HTML receives PASS without an LLM call, even when it directly changes site copy or clinical content.
- **How it fails:** A PR directly edits public/learn/bow-tie-questions/index.html, or adds a hand-written HTML file beneath that directory. The gate excludes it and passes. If that public asset is shipped, its changes bypass this review entirely. I could not verify from the supplied files whether an independent deployment step always regenerates or removes such assets.
- **Fix:** Exclude generated content only after verifying it is reproducible from reviewed inputs. Otherwise include its changes in the review or fail closed. Test direct edits and unexpected new files inside the excluded directories, not just whether directory names match the exclusion list.

### 5. [major] Superseding a run can discard a paid review without a report

- **Where:** `.github/workflows/pulsern-astra-review.yml:36` · confidence high
- **Problem:** cancel-in-progress terminates the Node process, but the script writes its first report only after the model call completes or throws normally. Process cancellation is not caught by that try/catch. The preservation steps additionally require saved=true, which is emitted only after the script returns and an Markdown report exists. always() cannot recover a report that was never written.
- **How it fails:** A developer pushes another commit while OpenRouter is processing a paid review. GitHub cancels the previous run before save(), leaving no report artifact or reviews-branch record for that attempt. The renderer-only interrupted-run test does not exercise this path.
- **Fix:** Disable superseding cancellation once model spending starts, or durably checkpoint the attempt before the request and finalize interrupted attempts through cancellation-safe cleanup. Make preservation discover existing reports independently of the review step's saved output, and test an actual interrupted process.
