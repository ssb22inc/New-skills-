## Findings

### 1. [blocker] Raw localStorage/sessionStorage access in app entry can crash the auth boot

- **Where:** `pulsern/src/app-main.jsx:18` · confidence high
- **Problem:** enforceOneTimeAppRelogin is called with raw window.localStorage and window.sessionStorage as arguments from inside useEffect with no surrounding try/catch. On a browser where accessing localStorage throws (private/partitioned modes, blocked third-party storage, SecurityError), the effect throws before the .catch() can attach, so AppEntry never reaches the 'error' state and AuthGate/App never mounts. The new code already has storageOrNull() for exactly this case and uses it everywhere else.
- **How it fails:** Student opens /app/ in Safari private/partitioned context or with browser storage blocked. Accessing window.localStorage throws SecurityError. AppEntry effect throws, no retry UI, study app unusable until browser settings change.
- **Fix:** Use storageOrNull(() => window.localStorage) / storageOrNull(() => window.sessionStorage) when calling enforceOneTimeAppRelogin, or make the function null-safe and wrap the arguments in try/catch.
