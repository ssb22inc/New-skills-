## Assessment

Not ready to merge. The supplied code still permits a review bypass through symlinks, silently changes PNG transparency during conversion, and accepts a clinically meaningful narration mismatch. The canonical-image gate also prevents legitimate updates to existing noncanonical PNGs. These findings are from static inspection; I did not run the tests or verify hosted GitHub settings.

## Findings

### 1. [blocker] Compact page reviews hide symlinks and omit their published contents

- **Where:** `pulsern/ops/astra-review.mjs:293` · confidence high
- **Problem:** The page branch digests the blob without checking or reporting its Git file mode. For a symlink, that blob contains only the target path—not the HTML that the build will publish. This also bypasses collection of targets under the excluded reports/astra directory.
- **How it fails:** Add pulsern/public/learn/example/index.html as a symlink to ../../../reports/astra/payload.html and add unsafe HTML at that target. The target is skipped as an earlier review report, while the page reaches the reviewer as a TEXT line containing a relative path, without the symlink mode. Vite's public-file copying can dereference the link and publish the unreviewed HTML.
- **Fix:** Inspect Git tree modes before choosing a compact representation. Reject symlinks in publishable paths, or resolve and review their actual targets under an explicit safe policy. Include mode changes in compact reviews and add an end-to-end symlink regression test.

### 2. [blocker] Audio QA still discards the minus sign in Rh-negative blood groups

- **Where:** `pulsern/ops/narrate-lib.mjs:100` · confidence high
- **Problem:** Minus signs are preserved only when followed by a digit. A minus after a blood-group letter survives keepLetters but is subsequently discarded as punctuation. Both the exact-token comparison and the similarity comparison therefore lose the Rh restriction. The new sign-written blood-group test checks only that lettera survives, not the sign.
- **How it fails:** audioCheck accepts the script "Group A− red cells lack the Rh D antigen. Check compatibility before transfusion." against "Group A red cells lack the Rh D antigen. Check compatibility before transfusion." Both normalize identically, although the transcript incorrectly generalizes the absence of Rh D to all group A red cells.
- **Fix:** Preserve and normalize blood-group signs to explicit plus/minus tokens before punctuation removal. Test faithful symbol-to-word transcripts and transcripts that add or drop the Rh sign. Bump QA_VERSION so affected prior approvals are rechecked.

### 3. [blocker] Canonicalization silently removes meaningful PNG transparency

- **Where:** `pulsern/ops/png-canonical.mjs:60` · confidence high
- **Problem:** decodePng accepts 8-bit RGB and grayscale PNGs but ignores their tRNS transparency chunks. canonicalPng then writes those samples as opaque pixels, and the CLI overwrites the original file. The pixel-preservation test cannot detect this because it uses the same transparency-blind decoder on both files.
- **How it fails:** Convert a valid 8-bit RGB PNG whose tRNS chunk makes its red background transparent. The resulting canonical PNG has an opaque red background. Transparent-key masks and overlays change appearance, and the original transparency information is lost.
- **Fix:** Decode tRNS into an explicit alpha channel before canonical encoding, or reject such files before writing anything. Likewise, explicitly handle or reject other rendering-affecting chunks. Verify preservation with an independent decoder or browser, including a transparent-key PNG fixture.

### 4. [major] Requiring canonical encoding on both sides makes legacy PNGs impossible to update

- **Where:** `pulsern/ops/astra-review.mjs:288` · confidence high
- **Problem:** Every existing side must pass reviewableImage, including the base-branch blob. An existing PNG produced by an ordinary encoder consequently fails review even when its replacement is canonical. Running the converter recommended by the error message changes only the head blob and cannot repair the immutable before blob.
- **How it fails:** Update an existing Chromium- or zlib-encoded screenshot, canonicalize the replacement, and open a PR. collectChanges still rejects the original screenshot. Deleting that noncanonical PNG also fails, leaving no ordinary reviewed migration path.
- **Fix:** Provide a safe representation or explicit reviewed migration policy for trusted noncanonical baseline images while retaining canonical enforcement for newly introduced image bytes. Add tests for noncanonical-before/canonical-after updates and deletion of a legacy image.
