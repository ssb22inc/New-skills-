## Findings

### 1. [blocker] Sign-out timeout silently drops unsaved flashcard progress

- **Where:** `pulsern/src/App.jsx:529` · confidence high
- **Problem:** The timeout branch journals only answer-log rows, invalidates queued saves, and signs out without warning. Flashcard schedules, card XP, and the daily new-card ledger are not represented in those rows.
- **How it fails:** An earlier upsert is stalled. The student grades several flashcards, queuing a newer payload containing their schedules and XP, then signs out. After three seconds, unsavedAnswers returns no question rows and the queued flashcard payload is invalidated before it runs. Signing back in restores none of those grades.
- **Fix:** Include recoverable flashcard-grade and undo events in the pending journal, including schedule, XP, and new-card-ledger changes. Until that exists, do not silently take the timeout branch when non-question changes remain unsaved; explicitly offer retry or confirmed loss. Add an integration test with a stalled earlier save and queued card grades.

### 2. [blocker] Pending recovery leaves plaintext account history behind after sign-out

- **Where:** `pulsern/src/progress-load.js:143` · confidence high
- **Problem:** The pending journal stores dated answers, correctness, categories, and timing in plaintext localStorage. Hashing the account identifier in the key provides no confidentiality. signOutAndForgetTrial removes only the old plaintext-key formats, deliberately leaving this journal accessible after authentication is cleared.
- **How it fails:** A student signs out on a shared computer while saving is stalled. The next person can enumerate pulsern-pending-progress-v1:* in that browser and read the previous student's answer history without signing into that account. The expiry field does not remove the data until a later sweep runs.
- **Fix:** Do not retain plaintext signed-in study history after logout. Either encrypt recovery data with a key obtainable only after authenticating as its owner, or remove it on sign-out and explicitly explain any unsaved-loss choice. Test confidentiality and cleanup, not merely the absence of the literal user ID.

### 3. [blocker] History-account trial imports can earn first-answer XP twice

- **Where:** `pulsern/src/guest.js:383` · confidence high
- **Problem:** importTrialOntoHistory awards XP and records __trialRewarded markers without adding answer rows. Subsequent live scoring consults only the log, never these markers or the imported outcome. Consequently, a paid trial answer is treated as an unpaid first attempt, and an imported miss is treated as never previously missed.
- **How it fails:** An existing account adds a considered correct trial answer for builtin:7 and receives 20 XP. Later, the built-in fallback serves that question; answering correctly earns another 20 XP. Alternatively, correcting an imported trial miss earns full first-try XP rather than the five-point correction award, and does not increment the fix-a-miss task because no prior wrong row exists.
- **Fix:** Persist an imported per-question outcome and award state without replaying existing-account ability history, and consult it in live XP, correction detection, and pool decisions. Test merge-onto-history followed by a live answer for both correct and missed trial items.

### 4. [blocker] Replaying an older pending answer overwrites a newer review outcome

- **Where:** `pulsern/src/progress-load.js:126` · confidence high
- **Problem:** applyUnsavedAnswers appends every missing attempt to the end of the current server log and applies its schedule using the old answer day. It never checks whether that question already has a later server answer. This makes synchronization order replace answer chronology for latest-result and scheduling decisions.
- **How it fails:** A Monday correct answer remains pending on one device. On Tuesday, the student misses the same question on another device, scheduling it for Wednesday. When the first device reconnects on Wednesday, recovery appends Monday's correct answer after Tuesday's miss and advances the schedule from Monday. The current miss disappears and the Wednesday review is postponed; ability updates also run in the wrong order.
- **Fix:** Journal sufficient ordering metadata and merge recovered attempts chronologically. An older recovered answer must not replace a newer per-question outcome or schedule. Handle ability updates consistently with that ordering, and test recovery when the server already contains a later answer to the same item.

### 5. [blocker] Schedule migration assigns a shared numeric ID to its first historical source

- **Where:** `pulsern/src/question-key.js:93` · confidence high
- **Problem:** rekeySchedule copies the numeric schedule onto the first newly classified log row and immediately deletes the numeric entry when all rows are classified. If historical rows with that number resolve to different canonical questions, the first row consumes a schedule that belongs to a later question.
- **How it fails:** A legacy save contains an earlier built-in answer and a later bank answer with the same numeric ID but different categories. Classification correctly identifies both sources. The existing numeric review date belongs to the later bank answer, but rekeySchedule moves it to the earlier built-in question and leaves the bank question without its saved review date.
- **Fix:** Determine which latest scheduling-eligible answer owns each numeric schedule before moving it. Do not consume schedules while iterating historical rows in forward order; leave genuinely ambiguous ownership unresolved. Add a migration test with two sources sharing an ID and a schedule belonging to the later source.

### 6. [major] Leaving an unresolved due review can trap the Today round

- **Where:** `pulsern/src/question-review.js:286` · confidence high
- **Problem:** sessionPool removes held IDs from catalog questions before reviewPools synthesizes unresolved review cards. Those synthesized cards therefore bypass the held filter. QBank subsequently filters out resolvedLegacy cards only after the due-only selection, so an excluded unresolved card can suppress all fresh questions and trigger fallbackSkip back to itself.
- **How it fails:** Today has one due unresolved legacy miss plus available new questions. The student selects Leave unresolved. The card is marked skipped, but the next pool recreates it as the sole due item. QBank filters it out, finds an empty pool, and restores the same skipped unresolved card. Repeating Leave unresolved never advances to the new questions.
- **Fix:** Apply held and explicitly deferred unresolved identities before the due-only shortcut, including synthesized cards, and fall through to fresh questions when all due candidates are excluded. Add a browser test for an automatic Today round with one unresolved due miss, new questions, and the Leave unresolved action.
