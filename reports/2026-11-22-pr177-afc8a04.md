## Findings

### 1. [major] Explicit Home is ignored when Today remounts for an unanswered trial

- **Where:** `pulsern/src/App.jsx:1226` · confidence high
- **Problem:** Today initializes its stage from needsFirstAnswer, while homeSeen initializes to the current homeEpoch. When Home causes Today to mount, the home-reset effect therefore treats that explicit Home request as already handled and leaves the forced question open.
- **How it fails:** A trial learner with zero answers advances the tour to Practice or Case Study, then presses the tour's Home button. applyLeave closes the tour, selects Today and increments homeEpoch, but the newly mounted Today renders "Answer this to unlock Today" instead of the home dashboard. Home works differently when pressed on the earlier tour steps where Today remains mounted.
- **Fix:** Make an explicit Home destination determine Today's initial view as well as subsequent resets. Preserve the forced-question behaviour for Skip and the answer action. Add a rendered regression test pressing Home from a tour step that has unmounted Today.

### 2. [major] Skipping the tour no longer consistently returns to Today

- **Where:** `pulsern/src/App.jsx:866` · confidence high
- **Problem:** dismissTour selects Today only when activating is true. That worked when the tour occupied one screen, but the new tour changes the actual tab. For an already-activated learner, Skip now leaves them on whichever section the tour last visited, contradicting the documented Skip-to-Today contract in first-answer.js.
- **How it fails:** An existing learner replays the tour, advances to Cards and presses Skip or Escape. The overlay closes onto the flashcard deck rather than Today.
- **Fix:** Route to Today whenever the tour is dismissed, and keep only the first-question kick conditional on activating. Test dismissal from a non-Today step for both activated and unanswered-trial accounts.

### 3. [major] The exam-exit test checks text, not ending or scoring the exam

- **Where:** `pulsern/tests/home-nav.test.js:19` · confidence medium
- **Problem:** The test named "scores a live exam before going home" only calls the confirmation-message builder and asserts strings. It does not exercise confirmLeave, the bound exam exit, submission failure/retry, or waiting for pending ability/XP records before unmounting. No behavioural test for this new critical orchestration is included in the supplied changes; I could not verify coverage elsewhere.
- **How it fails:** Removing examExitRef.current?.() would leave this test green while confirming Home never submits the once-only exam. Navigating immediately instead of waiting for pendingRecords would also leave it green while dropping unprocessed progress updates.
- **Fix:** Add a rendered integration test with a mocked exam API: cancel must keep the exam running; confirm must submit the committed responses; navigation must wait for successful scoring and all record updates; a submission error must retain the attempt for retry.

### 4. [minor] Practice screenshot description identifies the previous question
