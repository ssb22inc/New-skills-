## Assessment

Request changes. The new review paths can strand students on unavailable-question screens or send incomplete case-step descriptors into QBank rendering. The migration also depends on particular production content, and two safety tests pass without exercising their advertised failure paths. This was a static review; tests and build were not run.

## Findings

### 1. [blocker] The stalled-save test never starts the supposedly stalled write

- **Where:** `pulsern/tests/guest.test.js` · confidence high
- **Problem:** In "a stalled write unblocks the next save and does not land afterward", both saves are enqueued synchronously before the queue's promise callback runs. latest already names the second save, so the first returns stale before executing its task. Its gate and abort listener are never reached. The test therefore passes even if timeout and abort handling are removed.
- **How it fails:** A regression leaves an already-running save permanently stalled or fails to abort it before proceeding. This test remains green because it only checks skipping a superseded task that never began, falsely reporting coverage of the data-loss-sensitive timeout path.
- **Fix:** Await an explicit first-task-started barrier before enqueueing the second save. Advance a controlled clock through the timeout, assert that the active signal was aborted, and verify the second write completes while releasing the first operation later cannot write.

### 2. [blocker] The partial-catalog test never requests its failing second page

- **Where:** `pulsern/tests/progress-load-browser.test.js` · confidence high
- **Problem:** The test "shows the miss and does not install the partial page" supplies only one row on its first page. Production pagination treats any page shorter than 1,000 rows as complete, so the scripted second-page error is never read. The independent case-catalog request fails in the stub and supplies the expected error banner. Opening absent bank:2500 produces the expected placeholder whether or not the first page was installed.
- **How it fails:** The loader regresses to installing a partial bank after a later-page failure. This test still passes: it exercises no later-page failure and never checks whether the supplied partial question entered the New questions catalog.
- **Fix:** Supply 1,000 valid first-page questions followed by the failing page, and make the case-catalog fixture succeed. Assert that the second question page was requested and that first-page items were not installed as the usable bank. Then exercise successful retry of the saved miss.

### 3. [major] Exclude non-reviewable case steps from QBank misses

- **Where:** `pulsern/src/question-review.js` · confidence high
- **Problem:** catalogMissCards includes incorrect case answers even when they were recorded with schedule:false. The QBank catalog never contains the corresponding canonical case-step questions, so these answers become unavailable-question cards that no catalog retry can resolve. deriveMissSchedule also schedules these case misses on a subsequent load.
- **How it fails:** A student answers a CaseStudy step incorrectly, then opens Review misses. The case step appears as "This question didn't load" with only Retry. Retrying the question and case catalogs cannot open it. After reloading, the derived due entry can also interrupt the Today round.
- **Fix:** Keep source:"case" and schedule:false answers out of QBank review-card generation and schedule derivation. If case remediation is intended, route it to the actual case renderer instead. Add a regression covering an incorrect case step followed by Review misses and Today, including after reload.

### 4. [major] Replace the displayed unavailable-question card after a successful retry

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** QBank stores a catalogMiss placeholder in q state. Its Retry button reloads the parent catalog, but no effect or handler re-resolves the displayed q when that catalog changes. The component continues taking the q.catalogMiss return branch even after the real question becomes available.
- **How it fails:** A saved bank miss is opened while the bank request has failed. The student restores connectivity and taps Retry. The bank now loads successfully, but the screen still shows "This question didn't load" and never offers the answer controls. The student must abandon and reopen the sitting to recover.
- **Fix:** When the catalog changes, re-resolve a displayed catalogMiss by its canonical key and restore the current navigation entry with the real question. Preserve the unscored state and restart its display timer. Test failure, opening the placeholder, successful Retry, and answering without leaving the screen.

### 5. [major] Keep legacy case-choice descriptors out of New questions

- **Where:** `pulsern/src/question-review.js` · confidence high
- **Problem:** legacyCaseSteps adds descriptors without options, answer, or rationale to the same list consumed by unseenQuestions. unseenQuestions blocks an unresolved number only when it has multiple peers. A sole case candidate therefore qualifies as a fresh, playable question despite lacking the data QBank requires.
- **How it fails:** The bank is unavailable and the log contains an unclassified incorrect answer for legacy case id 101 in Physiological Adaptation. legacyCandidates adds the sepsis-step descriptor as the sole item with that number. New questions can select it, after which the multiple-choice renderer encounters missing options instead of presenting a usable question.
- **Fix:** Separate identification candidates from playable catalog questions, or explicitly mark and exclude candidate-only descriptors from fresh and ordinary review pools. Add a test with the fallback catalog and an unresolved legacy case miss that starts New questions and verifies no descriptor can be selected.

### 6. [major] Remove the migration self-check's dependency on bank question 101

- **Where:** `pulsern/supabase/migrations/020_relabel_legacy_progress.sql` · confidence high
- **Problem:** The first bank/case schedule self-check passes an unkeyed Pharmacology answer for id 101 through the live catalog lookup, then unconditionally requires bank:101. The migration does not establish that catalog fixture. A valid database without that exact question/category combination raises "review date did not stay with the bank question" and cannot apply the migration.
- **How it fails:** Applying migrations to an empty or minimally seeded staging database, or another valid database without Pharmacology question 101, fails in the DO block before the progress update runs.
- **Fix:** Make the self-check independent of production question contents. Use controlled, isolated fixtures for catalog resolution and canonical rows for schedule-owner tests, with fixture cleanup guaranteed. Verify the migration against a database containing only the repository's required seed content.
