## Assessment

Not ready to merge. The paid-job boundary still permits credential exposure, and visual approvals can be issued for incomplete or mismatched review inputs. Findings are based on the supplied code; I did not run CI or verify GitHub environment and branch-protection settings.

## Findings

### 1. [blocker] Branch-controlled symlinks can expose the paid job's GitHub token

- **Where:** `.github/workflows/pulsern-narrate.yml:190` · confidence high
- **Problem:** The paid checkout persists its write credential in branch/.git/config, then upload-artifact uploads branch-controlled report directories. No step rejects symlinks before uploading them; the artifact globber follows symbolic links. The diagram-map and diagram-review workflows have the same exposure.
- **How it fails:** A feature branch adds pulsern/reports/narration/git-token.txt as a symlink to ../../../.git/config. A maintainer runs narration on that branch. The artifact contains the checkout's authorization header, exposing the contents/actions-write token while the job is still running. Rejecting the symlink in the subsequent Astra review is too late: artifact upload precedes that review.
- **Fix:** Reject symlinks and non-regular files in all branch-controlled inputs and artifact trees before credentialed processing. Keep checkout credentials unpersisted and provide authentication only to the trusted push operation. Add an integration test with a report-file symlink pointing at a mock credential file and verify that no artifact can contain its bytes.

### 2. [blocker] Source traversal can read secrets outside the branch checkout

- **Where:** `pulsern/ops/review-diagrams-lib.mjs:269` · confidence high
- **Problem:** diagramSources follows any relative import using posix.normalize and join, without enforcing a containment boundary. It then places the file's contents into the paid model request. Prepared-data slug validation does not protect these import paths.
- **How it fails:** An untrusted prepare job supplies an otherwise valid plan, while src/diagrams/abg.jsx contains an import from ../../../.git/config. The trusted paid job resolves that to branch/.git/config and sends its persisted GitHub credential to OpenRouter as diagram source. A sufficiently traversing path can also read /proc/self/environ, including the review process's API key.
- **Fix:** Constrain source resolution to an explicit allowed project root, reject normalized paths that escape it, and check real paths so symlinks cannot evade containment. Fail before calling the model on prohibited imports. Test both ../ traversal and symlink escapes with sentinel secrets.

### 3. [blocker] Prepared frames are not bound to the commit receiving approval

- **Where:** `.github/workflows/pulsern-diagram-review.yml:143` · confidence high
- **Problem:** The prepare and paid jobs independently check out the moving branch name. The prepared artifact contains no enforced commit binding, while the paid script computes SOURCE_KEY from its later checkout and records approvals against that key.
- **How it fails:** Prepare renders commit A. Before the paid checkout starts, another push moves the branch to B. The reviewer receives A's pictures, captions and narration alongside B's source, and a passing result is recorded with B's sourceKey. The publication tests accept that approval even though B's actual rendering was never shown. Workflow concurrency does not prevent ordinary pushes or the other paid workflows from moving the branch.
- **Fix:** Resolve the feature branch to a SHA before preparation and use that exact SHA for both checkouts. Carry and verify that identity with the prepared artifact; never assign a later tree's sourceKey to earlier frames. Add a test that moves the branch between jobs and requires either a pinned review or an explicit failure.

### 4. [blocker] The production prepared path allows visual approval without any images

- **Where:** `pulsern/ops/prepared.mjs:76` · confidence high
- **Problem:** reviewPlan accepts an empty images array, arbitrary image labels, and incomplete frame sets. The strict imagePlan coverage check runs only during branch-controlled preparation, not in the trusted paid path. Consequently, its missing-frame tests do not protect the workflow's actual trust boundary.
- **How it fails:** A malformed or modified prepare script emits a diagram with valid words and steps but images: []. review-diagrams.mjs sends a text-only request and can record PASS with the current sourceKey. A plan containing only light-theme frames is likewise accepted, so the required dark-theme and step-specific visual review can be bypassed.
- **Fix:** Have trusted code define and validate the required frame identities: both themes, the overview, and every step, with no omissions or duplicates. Generate labels from those identities rather than trusting free-form labels. Reject zero-image and partial plans before spending or writing approval records, and test the --prepared path itself.

### 5. [major] Publication freshness ignores supported drawing dependencies

- **Where:** `pulsern/ops/diagram-attest.mjs:32` · confidence high
- **Problem:** sourceKey hashes only immediate .js/.jsx/.json files in src/diagrams, the explainer, and theme tokens. In contrast, diagramSources supports transitive imports, including .mjs files and modules outside that directory. Changing one of those dependencies does not invalidate the publication approval or map.
- **How it fails:** A reviewed diagram imports a threshold from src/diagrams/limits.mjs or ../clinical-limits.js. A later edit changes that threshold without touching the importing file. sourceKey remains unchanged, so approval(), mapIsCurrent(), and the merge-time diagram gate continue accepting the old visual approval. The more complete reviewKey would detect the change only if someone voluntarily reran the review job.
- **Fix:** Make the publication freshness key cover the same resolved dependency set that is shown to the diagram reviewer, or explicitly prohibit dependencies outside the hashed set. Add mutation tests for .mjs files, nested modules, and relative imports outside src/diagrams.
