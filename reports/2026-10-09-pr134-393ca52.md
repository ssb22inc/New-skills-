## Findings

### 1. [blocker] The untrusted prepare job can poison caches restored by the paid job

- **Where:** `.github/workflows/pulsern-diagram-review.yml:160` · confidence high
- **Problem:** Both jobs run under the default-branch workflow_dispatch ref. The prepare job executes arbitrary branch code, which can access Actions cache-writing capabilities, while the paid job restores an npm cache in that same trusted cache scope. contents: read and environment restrictions do not isolate Actions caches. The diagram-map and narration workflows have the same arrangement.
- **How it fails:** On a cache miss, malicious prepare code reserves the cache key/version that the paid job will restore and uploads a crafted cache archive containing a replacement trusted/pulsern/ops/narrate.mjs. Cache restoration happens after the trusted checkout. The later recording step therefore executes the replacement with SUPABASE_SERVICE_ROLE_KEY and OPENAI_API_KEY, despite never intentionally executing a script from the branch checkout.
- **Fix:** Do not restore caches writable by these untrusted default-ref jobs into credentialed jobs. Remove cache restoration from the paid jobs, or establish genuinely separate cache trust scopes. Disabling only the prepare job's automatic cache save is insufficient because its executed code can use the cache API directly.

### 2. [blocker] The dependency walk skips project modules that Vite actually loads

- **Where:** `pulsern/ops/diagram-attest.mjs:87` · confidence high
- **Problem:** Every import not starting with '.' is treated as an external package and skipped. Vite supports root-relative project imports such as '/src/clinical/limits.mjs'. Those modules are consequently absent from both the source shown to the diagram reviewer and the approval freshness key. The manual extension order also prefers .jsx over .js, unlike Vite, so extensionless imports can fingerprint a different file from the one executed.
- **How it fails:** A diagram imports a threshold from '/src/clinical/limits.mjs'. Changing a threshold used only outside the screenshot's example leaves diagramSources(), sourceKey(), and the rendered example unchanged. review-diagrams.mjs then reuses the old PASS, and the mapper can publish the changed clinical behavior without its dependency reaching the visual/clinical reviewer.
- **Fix:** Make dependency resolution match the application's actual module resolution. Follow root-relative project imports within the allowed source tree, and reject unsupported or ambiguous resolution rather than silently skipping it. Add regression tests for root-relative imports and colliding .js/.jsx extensionless imports, including an off-example logic change.

### 3. [blocker] Frame coverage is validated against an untrusted step list

- **Where:** `pulsern/ops/prepared.mjs:98` · confidence high
- **Problem:** expectedFrames() is derived from d.steps supplied by the branch's prepare script. Nothing checks that those are the actual steps of the pinned application's diagram. The commit field proves only that the supplied SHA matches HEAD; it does not authenticate the prepared metadata or screenshots. The current tests remove frames while retaining their steps, so they miss this bypass.
- **How it fails:** For the real ABG diagram, prepared data omits the kidneys step and both corresponding frames—or supplies steps: [] with only the two overview frames. reviewPlan() accepts it. The paid runner can then record a completed PASS with the current sourceKey even though the omitted step was never visually reviewed. approval() accepts that record and permits publication.
- **Fix:** Determine the required diagram IDs and step keys independently from the pinned application using trusted preparation/orchestration code in the isolated, secretless environment, and verify the prepared inventory against that independently established inventory before recording approval. Add a test that removes a real step and its matching frames together and requires rejection.
