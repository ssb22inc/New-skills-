## Assessment

Not ready to merge. ## Findings

### 1. [blocker] Tag normalization still hides executable changes inside quoted attributes

- **Where:** `pulsern/ops/astra-review.mjs:108` · confidence high
- **Problem:** Quoted values are initially preserved, but the final replacements run over the entire assembled tag, including those values. In particular, /\s*=\s*/ removes meaningful JavaScript whitespace. Consequently, pageDigest produces identical output for onclick="if (1 = = 1) alert(1)" and onclick="if (1 == 1) alert(1)", although the first handler is invalid and the second executes.
- **How it fails:** A generated-page change activates a previously invalid event handler by changing '= =' to '=='. collectChanges sends '(no textual change)' and no full file, so the executable change bypasses review. The new quoted-attribute tests exercise newlines and ordinary spaces, but not the final replacements that corrupt preserved values.
- **Fix:** Apply all normalization exclusively to unquoted segments, or preserve complete tags exactly. Add a regression asserting that these two handlers produce different digests, including an end-to-end collection test.

### 2. [blocker] A fresh visual approval can leave stale question pairings publishable

- **Where:** `pulsern/tests/diagram-gate.test.js:71` · confidence medium
- **Problem:** The shipping guard checks only whether each diagram has a current visual PASS. It never checks whether the shipped pairings were approved against that diagram's current clinical content. buildItemMap drops diagramHash, while freshness filtering happens only when map-diagrams.mjs is run. Running the visual-review workflow alone can therefore satisfy this guard without renewing or removing old pairing decisions.
- **How it fails:** An existing detemir question has a reviewed pairing with p.type='long'. This change narrows that row to glargine U-100 and makes the matcher reject detemir. After a fresh visual PASS, the guard accepts the unchanged map, even though the old pairing can still draw the glargine profile for the detemir question. I could not verify whether an unshown runtime consumer independently rejects such stale pairings; neither this guard nor the serialized map establishes that protection.
- **Fix:** Bind shipped pairings to the diagram revision used in their pairing review and enforce that binding during build or consumption. Alternatively, regenerate and validate the map from current decision records as a required publication step. Add a regression where clinical content changes and a fresh visual PASS must not revive an old pairing.

### 3. [major] Faithful D5W and D10W transcripts fail the word-level audio check

- **Where:** `pulsern/ops/narrate-lib.mjs:144` · confidence high
- **Problem:** The abbreviation joining handles a hyphen after a single letter but not the suffix after a spelled-out number. speechTokens('D-five-W') becomes ['d5', 'w'], whereas speechTokens('D5W') becomes ['d5w']; D-ten-W has the same problem. Both spoken forms occur in the actual tonicity narration. The new faithful-transcript tests duplicate this normalization in asTranscribed, generating the same incorrect split instead of testing an independently written transcript.
- **How it fails:** The tonicity/dextrose clip is spoken correctly and transcribed using the standard abbreviations 'D5W and D10W'. audioCheck rejects it on both takes, discards the narration entry and fails the run despite correct audio.
- **Fix:** Normalize complete spoken abbreviations, including their trailing letters. Add literal positive fixtures using 'D5W' and 'D10W' against the real narration, alongside negative fixtures with changed concentrations; do not generate those expected transcripts with the production normalizer.
