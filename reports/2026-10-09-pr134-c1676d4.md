## Assessment

## Findings

### 1. [blocker] Lockfile package-path changes can disappear from review

- **Where:** `pulsern/ops/astra-review.mjs:193` · confidence high
- **Problem:** lockDigest strips the leading "node_modules/" from package keys and substitutes "(root)" for the empty key. These transformations are not one-to-one. Moving an otherwise identical entry from "node_modules/p" to "p" produces an identical digest, although those keys identify different installation/workspace locations. The exact-JSON serialization check does not prevent this subsequent information loss.
- **How it fails:** A PR changes only that package location in a normally serialized package-lock.json. collectChanges supplies an empty dependency-summary diff and no full file, so the trusted reviewer sees "(no textual change)" rather than the actual lockfile change and can certify it without reviewing it.
- **Fix:** Represent every package key exactly, preferably as a JSON-encoded field alongside its complete value. Do not strip prefixes or use aliases that can collide with real keys. Add an end-to-end regression proving that moving an entry between "p" and "node_modules/p" produces a visible review diff.

### 2. [blocker] Number normalization adds spoken digit sequences together

- **Where:** `pulsern/ops/narrate-lib.mjs:62` · confidence high
- **Problem:** wordsToNumbers sums every adjacent number word without validating cardinal-number grammar or distinguishing a spoken digit sequence. Consequently, "nine one one" becomes "11". The new exact-token QA then treats different spoken numbers as identical: audioCheck("The emergency number is nine one one.", "The emergency number is eleven.") passes with similarity 1 and no mismatch.
- **How it fails:** An emergency-response narration script spells out 911 for TTS. A faithful transcript containing "911" is rejected, while a recording transcribed as "eleven" is accepted and can be published. The exact-word check does not protect the clinical number because normalization already destroyed its meaning.
- **Fix:** Parse only valid cardinal-number constructions, and handle spoken digit sequences separately rather than summing them. Fail closed on ambiguous constructions. Add positive and negative tests for 911 and other consecutive single-digit sequences, including the faithful digit-form transcript.

### 3. [blocker] Narration continues after verification fails twice

- **Where:** `pulsern/ops/narrate.mjs:142` · confidence high
- **Problem:** After both recording attempts fail audioCheck, the code saves the failure and executes continue, starting generation for the next step. This directly contradicts non-negotiable rule 8: after verification fails twice, stop and report exactly what failed. Returning a failure code after processing the remaining clips is not stopping at the failed gate.
- **How it fails:** The first clip fails verification on both takes. The job nevertheless makes additional paid synthesis/transcription calls and publishes passing clips into the manifest before eventually exiting unsuccessfully.
- **Fix:** Persist the failed attempts and existing results, set the failure exit code, and stop the recording loop immediately after the second verification failure. Add an orchestration test asserting that no subsequent synthesis call occurs after two failed checks.
