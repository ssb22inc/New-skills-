## Findings

### 1. [blocker] Failed device saves silently discard trial answers at sign-up

- **Where:** `pulsern/src/guest.jsx:37` · confidence high
- **Problem:** saveGuest returns false when localStorage.setItem fails, but this effect ignores the result. The trial continues displaying that the answers are saved for seven days and will move into the account. Signing up unmounts GuestTrial, and App can recover only the last successfully stored copy—not the answers held in this component.
- **How it fails:** localStorage reads work, but writes throw QuotaExceededError. A visitor completes five questions and selects Create free account. The account opens with none of those answers, XP, or ability updates because the in-memory guest state was discarded and no durable copy exists.
- **Fix:** Track and surface save failures. Preserve the guest payload across the auth transition in memory as well as attempting durable storage, or prevent the handoff from claiming success until the payload is safely available to the signed-in app. Add a browser test where setItem throws during the trial and verify that signing up does not lose the answers.

### 2. [blocker] Multi-day trials falsely display a Day 1 streak

- **Where:** `pulsern/src/guest.jsx:121` · confidence high
- **Problem:** SaveProgress hardcodes Day 1 in both the summary and carry-over list; AuthScreen repeats the same hardcoded claim. Guest answers retain their actual local days, and mergeGuestIntoBlob advances the streak across those days, so the displayed result can disagree with what signing up preserves.
- **How it fails:** A visitor answers two questions before local midnight and finishes the remaining three after midnight. The save screen and auth screen say Day 1, but importing this supported trial produces a two-day streak. The existing cross-midnight unit test verifies the two-day import without checking either displayed claim.
- **Fix:** Derive the guest streak from the answer-day history using the same streak rules as import, and use that result on both the save and auth screens. Add browser coverage for a trial spanning two local dates.

### 3. [major] Guest import awards first-answer XP without checking account history

- **Where:** `pulsern/src/guest.js:183` · confidence high
- **Problem:** Import recomputes XP against an initially empty seen array. Prefixing the incoming IDs also means the have check does not recognize an existing account answer to the same bundled question. Normal account recording handles this relationship through linkBuiltInGuest, but import bypasses it.
- **How it fails:** An account has already answered a bundled fallback question correctly and earned its XP. The student signs out, encounters that same question in the guest trial, answers it correctly, signs back in, and chooses Add. Import awards the full first-answer XP again, even though recording that same answer through the normal account path would return reason 'repeat'.
- **Fix:** Calculate imported XP against the account's existing history using canonical question identities and the bundled-question aliases. Preserve the distinction between an unrelated shared-bank item and a bundled item that happens to have the same numeric ID. Add an integration test importing a trial question already answered correctly in the account.
