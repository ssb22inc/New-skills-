## Assessment

Not ready to release. Two persistence paths can corrupt saved progress, sign-out can fail when browser storage is blocked, and new regression tests contain assertions that no longer match the code. Reviewed the supplied diffs and images; tests were not executed.

## Findings

### 1. [blocker] Reloading drops card operation IDs and subtracts previously earned XP

- **Where:** `pulsern/src/rewards.js:102` · confidence high
- **Problem:** migrateRewards discards cardOps, although the save reconciler uses those IDs to distinguish existing grades from undos. On load, acceptedBlob and loadedBaseline retain the stored operations, but the migrated UI snapshot has none. mergeCardOps interprets their disappearance as undoing every stored grade, and reconcileProgress subtracts their XP from the account total.
- **How it fails:** Grade a card Good after the time floor and save its 5 XP. Reload. The initial autosave compares the stored cardOps with the migrated rewards lacking cardOps and saves an XP total reduced by 5, despite retaining the card's schedule and reviewed-day count.
- **Fix:** Preserve and validate cardOps in migrateRewards. Add a round-trip regression that grades a card, serializes it, runs migrateBlob, and passes the migrated snapshot through the actual save reconciliation; XP, operation IDs, schedules, and day counts must remain unchanged.

### 2. [blocker] A first-save conflict preserves remote answers but overwrites their XP and ability

- **Where:** `pulsern/src/guest.js` · confidence high
- **Problem:** When baselineBlob is null, reconcileProgress treats the fresh server blob as the baseline. Remote answers are consequently considered already accounted for, but the !hasBaseline XP branch takes local.xp when there are no unseen local attempts. The ability merge likewise lets local default ability replace the server's populated ability. The resulting log and ability no longer describe the same answers.
- **How it fails:** Two tabs read a new account before either creates its progress row. Tab A saves a correct answer. Tab B's delayed initial empty autosave encounters the new revision and reconciles with loadedBaseline still null. It retains A's answer in the log but writes XP back to zero and ability back to defaults. This subsequently produces an incorrect readiness estimate.
- **Fix:** Represent a confirmed absent row with an explicit normalized empty baseline, rather than treating it as an unknown baseline and substituting the later server state. Test the real store conflict path with two initial no-row reads, one saved answer, and one delayed empty autosave.

### 3. [major] Blocked storage prevents the sign-out call

- **Where:** `pulsern/src/App.jsx:657` · confidence high
- **Problem:** finishSignOut evaluates window.localStorage and window.sessionStorage before calling the clearing helper. Either getter can throw SecurityError. The helper's internal catches cannot catch argument evaluation, so auth.signOut is never called. This bypasses the storageOrNull handling introduced elsewhere for this supported failure mode.
- **How it fails:** A student signs in using Supabase's in-memory session fallback in a browser that denies storage access, then taps Sign out. The handler invalidates the save queue and releases its account bookkeeping, throws while obtaining storage, and leaves the student signed in.
- **Fix:** Pass storageOrNull(() => window.localStorage) and storageOrNull(() => window.sessionStorage) to the helper, ensuring storage cleanup failure cannot prevent authentication sign-out. Add an integration test invoking the shipped sign-out handler with throwing storage getters.

### 4. [major] New regression assertions still require the pre-operation-ID handlers

- **Where:** `pulsern/tests/review3.test.js:37` · confidence high
- **Problem:** The wiring test requires the exact strings "undoLog.current[id] = { prev: srsMap[id], xp: xpGain, day: todayStr() }" and "onUngrade?.(rec.xp, rec.day)". The shipped handlers now include opId in both places, so neither assertion can pass.
- **How it fails:** Running npm test against this change fails this test even when the card handlers behave correctly. The committed regression suite therefore cannot be green as required.
- **Fix:** Update these obsolete assertions, preferably replacing them with behavioral coverage of grade/undo operation IDs and persistence round-tripping rather than exact implementation-string checks. Run the complete test suite after the correction.
