## Findings

### 1. [blocker] Person schema asserts an associate degree from 'Carleen Health Institute of South Florida' with no verification source; likely a fabricated credential

- **Where:** `ops/author.mjs (and generated pages such as public/about/index.html, public/learn/*/index.html)` · confidence high
- **Problem:** In personNode(), the hasCredential array includes `{ credentialCategory: 'degree', name: 'Associate degree in nursing', recognizedBy: { '@type': 'EducationalOrganization', name: 'Carleen Health Institute of South Florida' } }`. This institution appears nowhere else in the repository, the review ledger, or the license lookup. It is very likely an AI-hallucinated school name. Because personNode() is used by build-learn.mjs (approved guides) and build-public-pages.mjs (all product/trust pages, including /about/), this false credential is now asserted in structured data on dozens of public pages. A search engine summary can surface it as fact, and the /about/ page itself says 'Associate degree in nursing.' If the school is not real, this is a false user-facing credential claim.
- **How it fails:** A student or search AI reads the Person JSON-LD and concludes the founder holds a degree from a nonexistent institution.
- **Fix:** Remove the degree credential or verify the school actually exists and is the founder's school, then cite that source in the comment/ledger.

### 2. [major] Public copy and schema claim every guide is RN-reviewed, but the system still supports a pending state

- **Where:** `ops/build-learn.mjs (renderIndex), ops/build-public-pages.mjs (aboutPage and editorial-policy page)` · confidence medium
- **Problem:** The /learn/ index now states 'Sheldon Bennett, RN, writes and reviews every guide' and 'Every guide lists its sources and the RN who reviewed it.' The editorial-policy meta description says 'has an RN review every public guide.' The about page says 'Sheldon writes and reviews every public study guide on this site.' However, provenanceFor() still returns `decision: approved ? 'approved' : 'pending'`, and build-learn renders pending guides with 'review evidence pending'. If any current or future guide is pending or its content/source-set hash mismatches, these universal statements are false. The previous copy correctly limited the claim to 'Each approved guide...'.
- **How it fails:** A new guide is added without a matching RN review; the public hub and policy pages still tell users every guide has been reviewed.
- **Fix:** Make the copy conditional on actual review status, or gate the universal wording to only display when all rendered guides are approved.

### 3. [major] License verification URL not verified live; 'Check his license' link may not resolve to the named person

- **Where:** `content-review-records.json / ops/author.mjs / public/about/index.html` · confidence medium
- **Problem:** The change replaces Nursys with a Florida DOH URL: `https://mqa-internet.doh.state.fl.us/MQASearchServices/HealthcareProviders/LicenseVerification?LicInd=648118&Procde=1701`. The deterministic SEO guardian only checks URL shape (host, path, numeric LicInd/Procde); it never fetches the page. I could not verify live that this URL resolves to Sheldon Bennett's RN license, or that LicInd=648118 is him. The /about/ page and every schema `sameAs` now present this as proof. If the link is wrong or returns an error/another person, the site makes an unsupported verification claim.
- **How it fails:** A user clicks 'Check his license' and sees an error or a different licensee, while the page claims verification.
- **Fix:** Verify the live URL and the licensee name/number match, add a source reference to the verification date, and consider a more durable verification path.

### 4. [minor] Unused `reviewer` variable in articleJsonLd

- **Where:** `ops/build-learn.mjs (articleJsonLd)` · confidence high
- **Problem:** `const reviewer = REVIEW_LEDGER.reviewer;` is declared but never used after the refactor to personNode(). This is dead cleanup-prone code and could confuse future edits, though it does not affect output.
- **How it fails:** None; maintenance-only.
- **Fix:** Remove the unused declaration.
