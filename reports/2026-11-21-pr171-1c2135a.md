## Assessment

Do not merge as written. The change replaces the audio accuracy gate with an unconditional pass and introduces migration paths that can stall voicing or put student requests behind bulk work. This review is based on the supplied changes; tests and live Polly output were not independently verified.

## Findings

### 1. [blocker] Nonempty audio is declared accurate without checking what it says

- **Where:** `pulsern/api/_speak.js:699` · confidence high
- **Problem:** makeChecked now assigns pass: true and similarity: 1 to every nonempty provider response. saveChecked persists that fabricated verdict, and speak serves the clip as verified. Changing TTS providers does not establish that the resulting waveform preserves every clinical value, unit, negation and word. The retained voiceCheck tests no longer protect the production publication path, and the previous wrong-number rejection tests were removed.
- **How it fails:** For the approved script 'Potassium 2.9 milliequivalents per liter.', a truncated clip or a clip that reads a different value is saved with a perfect passing record and played to students. Nothing now examines the audio before publication.
- **Fix:** Restore an independent audio accuracy gate before setting pass or saving playable audio. Retain Polly synthesis if desired, but transcribe or independently review its actual output and reject mismatched or incomplete clips. Add an end-to-end negative test proving that changed numbers, units and negations cannot produce a playable clip.

### 2. [major] The unbounded legacy scan can prevent the voice worker from ever running

- **Where:** `pulsern/ops/read-aloud-worker.mjs:609` · confidence medium
- **Problem:** queueLegacyMarin runs before runJob and before the READ_ALOUD_MINUTES deadline is established. It scans the entire bank and performs record and queue downloads for every matching passage, but saves no scan cursor; its only completion marker is written at the end. A workflow timeout therefore restarts the mandatory scan from the beginning rather than allowing queued passages to be voiced.
- **How it fails:** With 15,000 matching legacy passages and roughly 100 ms per storage round trip, the two sequential read phases per passage alone exceed the workflow's 45-minute timeout, even after earlier runs have queued those passages. Every scheduled run times out in migration before reaching runJob, leaving both migrated clips and student requests unvoiced. The current production clip count and latency could not be verified.
- **Fix:** Make migration incremental and resumable with a persisted cursor and a bounded time or item allowance. Drain student requests even while migration remains incomplete, and include migration time in the overall run deadline.

### 3. [major] Bulk revoicing occupies the student-request priority queue

- **Where:** `pulsern/ops/read-aloud-worker.mjs:562` · confidence high
- **Problem:** Every previously saved Marin passage is inserted into queue/, the same oldest-first lane used for student demand. The legacy flag is ignored by drainQueue. A later Listen request neither promotes an already queued legacy passage nor moves a new request ahead of this unsolicited backlog, contradicting the documented student-first behavior.
- **How it fails:** The migration inserts thousands of legacy passages, then a student presses Listen on an unvoiced item. Their request is processed only after the older migration entries, potentially after those entries exhaust the day's budget, even though prewarming is supposed to yield to student requests.
- **Fix:** Keep bulk revoicing in a lower-priority lane than explicit student requests, or implement priority and promotion that drainQueue actually honors. Add a test with an older bulk-revoice backlog and a newer student request, asserting that the student request is synthesized first.
