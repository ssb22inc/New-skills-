## Assessment

The change is broadly sound, but there are two real gaps and one maintainability issue worth fixing before release.

## Findings

### 1. [major] 410 page is a new public page without required legal links or NCSBN disclaimer

- **Where:** `pulsern/ops/retired-page.mjs:3` · confidence high
- **Problem:** RETIRED_BODY is served to users at every /compare/* URL, but its markup has no footer and therefore no Terms/Privacy/disclaimer links and no NCSBN trademark disclaimer. The page even contains 'NCLEX' in link text. This contradicts the project guardrail that Terms/Privacy/disclaimer links and the NCSBN trademark disclaimer stay visible on public PulseRN pages.
- **How it fails:** A user follows an old /compare/pulsern-vs-uworld/ link and lands on a PulseRN-branded page that advertises free NCLEX questions while providing none of the required legal/disclaimer links.
- **Fix:** Add the standard footer with the legal links and the 'NCLEX® is a registered trademark…' disclaimer to RETIRED_BODY, or reuse the standard page chrome.

### 2. [major] Test passes without exercising the Vercel middleware matcher that actually controls 410 behavior

- **Where:** `pulsern/tests/retired-commercial.test.js:67` · confidence medium
- **Problem:** The test asserts middlewareConfig.matcher equals an array, then calls middleware(new Request(...)) directly. The direct call ignores the matcher entirely. If the matcher is misconfigured or if /compare/:path* does not match trailing-slash or query URLs under Vercel, the test still reports safety.
- **How it fails:** In production, a request to /compare/ or /compare/foo?utm=1 falls through to the new 404.html rather than the 410 page, while the unit test remains green because it never applied the matcher.
- **Fix:** Add an integration/staging assertion, or at least a local helper that parses/matches paths with the same path-to-regexp semantics used by Vercel, and test that /compare, /compare/, /compare/foo, and query variants are routed to the middleware response.

### 3. [minor] 404 page is committed as public/404.html and also regenerated by the builder, so the two can drift

- **Where:** `pulsern/ops/build-public-pages.mjs:170` · confidence high
- **Problem:** The builder writes public/404.html from notFoundPage(), but the repository also contains a hand-committed public/404.html. The tests only inspect the committed file, not the builder output. A future change to notFoundPage() could produce a 404 that lacks the noindex meta, correct links, or legal footer and tests would still pass.
- **How it fails:** Someone edits notFoundPage() and breaks the noindex directive or footer; the release passes because tests only read the static committed file, while the deployed build uses the generated version.
- **Fix:** Make the committed file the single source of truth or add a test that executes build-public-pages.mjs/logic and asserts the generated 404 matches the committed file.
