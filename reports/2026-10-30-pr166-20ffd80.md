## Findings

### 1. [major] Repeated provider refusals now keep the failed-run chain alive

- **Where:** `pulsern/ops/read-aloud-worker.mjs:429` · confidence high
- **Problem:** The new progress calculation counts provider refusals as progress and permits chaining after every failure type. Both queue processing and bank prewarming deliberately stop after three consecutive provider refusals because that indicates a setup problem. Those same three refusals now make progress true and more true, automatically restarting the job despite that circuit breaker.
- **How it fails:** If a provider configuration problem makes every speech request return 400, each run records three passages as rejected, detects the repeated-refusal setup failure, and then dispatches another run after ten minutes. The next run skips those rejection records and rejects the next passages. This continues through the bank until the daily slot budget is exhausted, leaving affected passages unavailable for seven days rather than stopping the chain during the persistent failure.
- **Fix:** Propagate an explicit non-retryable setup/circuit-open outcome from both queue processing and bank prewarming, and prohibit self-dispatch for that outcome regardless of prior progress. Add a multi-run test with persistent 400 responses proving that three consecutive refusals stop automatic chaining.
