## Assessment

Do not ship yet. The new save queue can discard answered questions on sign-out, and two reward-state paths produce incorrect results. I reviewed the supplied diffs and images; I did not execute the tests.

## Findings

### 1. [blocker] Sign-out discards the newest queued progress

- **Where:** `pulsern/src/App.jsx:513` · confidence high
- **Problem:** The sign-out handler invalidates the save queue before ensuring its latest payload has been persisted. invalidate() makes queued saves return stale without executing, and signing out then removes the session needed to write them. The checked answers exist only in component memory and disappear when AuthGate unmounts App.
- **How it fails:** An upsert is slow while the student answers another question. The second answer's autosave queues behind that request. The student signs out before the first request finishes: the queued payload containing the second answer is invalidated and never sent. Signing back in loses that answer and its associated progress.
- **Fix:** Expose a queue flush operation and await successful persistence of the newest snapshot before signing out. On failure, keep the student signed in and offer retry or explicit confirmation that unsaved work will be lost. Add a browser test with one delayed in-flight upsert, a newer queued answer, and an actual sign-out/unmount.

### 2. [blocker] Earning a cover can erase a simultaneous promotion

- **Where:** `pulsern/src/App.jsx:1024` · confidence high
- **Problem:** The promotion effect queues a functional markMomentsSeen update, but the following cover effect replaces rewards with g.rewards computed from the older rewardsRef.current. When both effects run after the same answer, the replacement discards the new rankHigh and badgesSeen markers. Neither effect's relevant dependencies change afterward to repair those markers.
- **How it fails:** The eighth question on the fifth study day of a week also satisfies a promotion or badge threshold. Both celebrations appear, but the saved rewards retain the old rankHigh/badgesSeen values. If accuracy subsequently slips, the supposedly permanent earned rank can disappear; the badge can also be celebrated again.
- **Fix:** Apply the cover grant against the latest queued rewards state rather than replacing it with a render-time snapshot. Prefer one reducer/transition that preserves both the grant and moment markers. Add an integration test where one answer earns a cover and promotion together, then verify the persisted markers survive a reload and later accuracy decline.

### 3. [major] Trial questions become fresh, fully rewarded questions again in offline fallback

- **Where:** `pulsern/src/guest.js:159` · confidence high
- **Problem:** The handoff changes a built-in answer's ID to guest-<id>, but the signed-in built-in fallback still uses its original numeric ID. QBank's freshPool and answerXp do not connect those identities. expandTrialQuestions creates the prefixed review copy without excluding or aliasing the identical numeric original.
- **How it fails:** A visitor correctly answers built-in question 7, earns XP, and creates an account. If the shared-bank fetch fails, signed-in practice uses QUESTIONS. Numeric question 7 is considered unseen despite the guest-7 answer, so the same stem and already-revealed answer are served as a new question and earn full first-answer XP again.
- **Fix:** Preserve built-in provenance and use a consistent identity, or provenance-aware aliases, across guest handoff, fallback fresh-question filtering, and XP repeat detection. Do not alias an unrelated shared-bank item merely because its numeric ID matches. Test a real guest handoff followed by a failed bank fetch and verify the answered built-in is not treated as fresh or paid twice.
