## Assessment

## Findings

### 1. [blocker] Malformed final verdicts can be discarded in favor of an empty example

- **Where:** `pulsern/ops/astra-review.mjs:545` · confidence high
- **Problem:** A candidate that fails JSON parsing is ignored unless reviewish() finds double-quoted assessment/findings keys. Consequently, a valid empty example followed by a single-quoted final review returns the example as the verdict. Valid JSON wrappers such as {"review":{...}} are also silently ignored by looksLikeReview(). This can publish PASS while discarding the actual blocker findings.
- **How it fails:** The response contains {"assessment":"Example only","findings":[]} followed by {'assessment':'Blocked','findings':[{'severity':'blocker'}]}. The second span is malformed, but reviewish() returns false, so parseReviewText() returns the empty example and runReview() posts a successful verdict instead of recording an incomplete review.
- **Fix:** Accept only an unambiguous verdict after removing explicitly supported envelopes. Fail closed on additional malformed or wrapped verdict-shaped output rather than selecting an earlier example. Add regressions for single-quoted final reviews and nested final-review wrappers.

### 2. [major] Manual audits assume unchanged pages without comparing any commits

- **Where:** `.github/workflows/pulsern-seo-guardian.yml:129` · confidence high
- **Problem:** workflow_dispatch and scheduled runs always feed an empty filename list to the detector. That is treated as proof that no marketing page changed, so the workflow generates a synthetic PASS without checking whether this commit has ever received its required page review. Even under the newly narrowed policy, absence of a comparison is not evidence of unchanged pages.
- **How it fails:** A PR changes landing.jsx and its normal search review fails to produce a valid report. Dispatching this workflow on the same PR branch/head sets changed=false and writes a skipped PASS. If the other checks succeed, the dispatched audit is green for that commit without any completed model review of the changed page.
- **Fix:** Run the model for events without a trustworthy comparison range, or compare against a persisted reviewed SHA and require valid commit-bound evidence before skipping. Add a workflow-level regression for a dispatched page-changing commit.

### 3. [major] The homepage HTML entry is missing from the detector roots

- **Where:** `pulsern/ops/seo-page-change.mjs:11` · confidence medium
- **Problem:** The explicit homepage root is landing.jsx, while the HTML-path rule only covers pulsern/public/. PulseRN's documented Vite entry, pulsern/index.html, can change the homepage title, metadata, inline content, or scripts without matching either rule. Dependency traversal only follows recognized import/new-URL expressions, not Vite's HTML-entry relationship. The unattached builders could theoretically add an indirect edge to index.html; that could not be verified from the supplied files.
- **How it fails:** A change edits only homepage metadata in pulsern/index.html. Unless an unattached builder happens to reference that file through one of the recognized expressions, marketingPagesChanged() returns false and the workflow skips the model despite a public marketing-page change.
- **Fix:** Include pulsern/index.html explicitly among the marketing roots and test an index.html-only change against the real classifier.
