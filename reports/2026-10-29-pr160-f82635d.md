## Assessment

Do not merge yet. The daily spending controls are bypassable under concurrency, and the UTC quota calendar violates the project's date rule. Audio-unit validation needs confirmation before student playback. The tests also miss the default no-key route, and transient provider failures can permanently reject passages.

## Findings

### 1. [blocker] Concurrent requests bypass both daily spending caps

- **Where:** `pulsern/api/_speak.js:234` · confidence high
- **Problem:** Usage is enforced with an unlocked download/check/upload sequence. Concurrent requests read the same counters, all pass the limit check, and overwrite each other's increments. Counter upload failures are also ignored after work has been queued or purchased.
- **How it fails:** With one passage remaining, a signed-in student submits many different valid bank segments concurrently. Every request can enqueue work or invoke OpenAI, while the final stored counter advances by only one. Ordinary requests from different students can similarly undercount the global budget.
- **Fix:** Reserve passage capacity atomically before queueing or synthesis, using a database transaction/RPC that checks and increments both counters and deduplicates the passage. Fail closed if reservation persistence fails. Add concurrent-request and failed-counter-write tests.

### 2. [blocker] Similarity-based QA does not establish exact clinical-unit preservation

- **Where:** `pulsern/api/_speak.js:88` · confidence medium
- **Problem:** Canonicalizing units makes different units comparable tokens, but this wrapper does not require those tokens to match. Under the documented audioCheck contract—0.92 similarity plus exact numbers, negations and directions—a unit substitution inside a long passage can pass. The short microgram/milligram rejection test can pass merely because that substitution substantially lowers similarity. The imported audioCheck implementation was not supplied, so I could not verify whether it separately protects these newly constructed compound-unit tokens.
- **How it fails:** A long rationale is transcribed correctly except that '25 micrograms per kilogram per minute' becomes '25 milligrams per kilogram per minute'. The numbers remain identical and the overall similarity can exceed 0.92; without an independent unit invariant, the incorrect audio is saved and reused for students.
- **Fix:** Require exact preservation of canonical units and their associated quantities independently of similarity. Add long-passage tests containing a single mg/mcg, mg/dL/g/dL, or rate-unit substitution, and verify that the imported check actually rejects them before enabling publication.

### 3. [blocker] Daily quota dates introduce the explicitly forbidden UTC calendar logic

- **Where:** `pulsern/api/_speak.js:120` · confidence high
- **Problem:** utcDay introduces toISOString().slice(0, 10) to determine daily resets. Rule 4 explicitly requires local calendar dates and forbids introducing this expression for calendar logic. Documenting the new behavior as UTC in HUMAN_TASKS.md is not an owner amendment to that rule.
- **How it fails:** A student in UTC-5 reaches the cap at 23:50 local time. At 00:10 on the next local study day, both requests still share the same UTC usage key, so the new local day's allowance remains exhausted; resets instead occur at 19:00 local time.
- **Fix:** Use the existing local-date helpers with an explicit applicable calendar timezone. If operational quotas genuinely require UTC, obtain an explicit owner exception rather than silently changing the date contract.

### 4. [major] The missing-key test passes because the Supabase mock has no storage

- **Where:** `pulsern/tests/ai-auth.test.js:122` · confidence high
- **Problem:** The createClient mock returns only auth and from, so the handler obtains undefined storage and speak immediately returns 503. OPENAI_API_KEY being absent is not what causes the asserted response. With real configured storage and bank access, absence of that key is the supported queueing mode and should return 202 for an uncached passage.
- **How it fails:** A regression that makes production's default no-key deployment stop queueing every passage would still pass this test. The test would also produce the same 503 with an OpenAI key present because its mock cannot reach the relevant branch.
- **Fix:** Provide realistic storage and student-scoped bank mocks. Assert that a valid no-key request returns 202 and writes the queue without contacting OpenAI. Keep a separate 503 test that explicitly removes required storage or bank configuration.

### 5. [major] A transient second-take failure becomes a permanent QA rejection

- **Where:** `pulsern/api/_speak.js:167` · confidence high
- **Problem:** makeChecked retains the first failing take in best when the second synthesis or transcription fails. Both callers treat any non-null best as a completed check, save pass=false, and stop future attempts. The worker additionally removes the queue entry. Thus a provider error is recorded as though two completed takes failed accuracy review.
- **How it fails:** The first take misreads a number, then the second transcription returns 429 or 500. The passage receives a failed record and returns 422 indefinitely under the same QA version, even after the provider recovers. Every student is forced onto the device voice for that passage.
- **Fix:** Distinguish two completed QA failures from an incomplete run caused by a provider error. Do not persist a terminal failed record for an incomplete run; retain the queue entry for retry. Add tests for a failed first check followed by a second synthesis or transcription error.
