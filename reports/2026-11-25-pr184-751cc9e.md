## Findings

### 1. [major] Undo grade does not reverse the streak/day advancement made by touchDay

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** Concrete path: a student grades their first flashcard of a local day, then taps Undo grade. `grade()` calls `touchDay()` before scheduling/XP. `touchDay()` runs `advanceStreak(...)`, sets `streak` to the next day, and can enqueue streak milestones and update `rewards.best/milestones`. `unnoteCard()` only reverses rewards/daily via `setRewards(...)` and `setDaily(...)`; it never restores `streak`, `touchedDay.current`, or queued streak moments. The same-day guard in `touchDay` then prevents a regrade from applying the day twice, so the streak remains advanced despite no completed study. This contradicts the in-code comment that undo reverses all of the grade and can be farmed day-by-day for streak/milestone progression.
- **How it fails:** Today streak count 0, lastDay null, a due card is shown. Grade it, then Undo grade. Expected: streak count 0 and no moment. Actual: streak count 1, lastDay today, and any 7/30-day milestone moment may already be queued; the task/daily count is decremented but the streak is not.
- **Fix:** Make grade/undo keep a reversible streak action (or recompute the streak from the graded activity ledger) so undoing the first/only study event of a day also undoes the streak day, or explicitly define flashcards as streak-qualifying immediately and update comments.

### 2. [major] Correct unresolved legacy rows permanently hide matching bank/builtin questions with no resolution UI

- **Where:** `pulsern/src/question-review.js` · confidence medium
- **Problem:** `historyIndex()` puts any row with `unclassified: true` into `idx.unresolved`, regardless of correctness. `settledResult()` returns `pending` for a catalog question whenever `idx.unresolved.get(num) === true`, including correct-answer rows. `unseenQuestions()` then filters out every question with that raw id from the new-question pool. `unresolvedCards()` only creates a resolution card for `correct === false` or a raw schedule entry, so a correct ambiguous legacy row has no UI where the student can name the source. Input: migration 020 leaves `{id:7, cat:'Pharmacology', correct:true, unresolved:true, unclassified:true}` when both built-in and bank questions match id 7; after load, bank item `bank:7` (and/or builtin:7) is permanently absent from New Questions.
- **How it fails:** A returning student with such a legacy row signs in and loads the bank. Any bank question whose id collides with that ambiguous row is removed from freshPool and not surfaced in Review Misses because the row is already correct. The question is silently lost to that account.
- **Fix:** Either resolve correct rows conservatively through the same candidate UI, or change `unseenQuestions` to only block ambiguous ids for incorrect/unresolved misses; if hiding is intended, provide an explicit claim/dismiss path for correct unresolved rows.

### 3. [minor] Catalog error banner says the question catalog didn't load when only cases failed

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** `const catalogError = bankFailed || casesFailed;` drives a banner headed "The question catalog didn't load" with copy about the question bank. If only `casesFailed` is true, questions are loaded and usable, and the banner misdescribes the failure.
- **How it fails:** A client with a successful `questions` fetch but a failed `case_studies` fetch sees text telling them the question catalog failed and offering to retry the bank.
- **Fix:** Split messaging based on `bankFailed`/`casesFailed`, e.g. 'The case-study catalog didn't load' when only case_studies failed.
