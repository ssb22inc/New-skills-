## Assessment

Two blockers undermine the new diagram workflow: branch-controlled matcher code can return protected bank content into an uploaded artifact, and the visual-review renderer does not verify that production uses the same build-tool versions it rendered with.

## Findings

### 1. [blocker] Branch matcher can leak paid-bank content through the prepared artifact

- **Where:** `pulsern/ops/map-diagrams.mjs:181` · confidence high
- **Problem:** The trusted prepare script passes each bank row's stem, options, and rationale to branch-controlled matcher code. It then preserves each matcher's arbitrary `p` value in `proposed` and writes that object to the prepared JSON, which the workflow uploads as an artifact. The browser network sandbox does not restrict this return channel.
- **How it fails:** A branch changes `proposePairs` to return `{ d: "abg", p: q.rationale }` (or encodes other row fields in `p`). The prepare step writes those values into `map.json` and uploads them, making entitlement-protected question content available to anyone who can access the workflow artifact. The new sandbox test only checks outbound network requests, so this path passes it.
- **Fix:** Do not pass real bank rows to branch-controlled code. Run matching against the bank only in trusted code, or redesign the prepare stage so its untrusted code receives no protected question content; do not rely on validating or scrubbing the matcher's output as the security boundary.

### 2. [blocker] Renderer does not check the production build-tool versions

- **Where:** `pulsern/ops/render-diagrams.mjs:99` · confidence high
- **Problem:** `used` is populated only by the bundle's `resolveId` hook, but Vite and `@vitejs/plugin-react` are loaded directly before that hook and are never added to the set. Consequently `packageMismatches` does not compare those build tools against the branch lockfile, despite their ability to change the production transform/rendering. Hashing the branch lockfile into the review key forces a review but does not make the renderer use the branch's toolchain.
- **How it fails:** A branch updates Vite or the React plugin in its lockfile. The trusted renderer still builds and reviews the diagram with its own versions, the mismatch check passes, and the production build uses the branch's changed toolchain. The approved frames can therefore differ from what students see, while the visual review appears current. The added dependency test changes React only and misses this case.
- **Fix:** Compare the exact versions and integrity of Vite, `@vitejs/plugin-react`, and every other production transform/build dependency against the renderer's toolchain, or reject any build-tool lockfile change unless the renderer can reproduce it exactly.
