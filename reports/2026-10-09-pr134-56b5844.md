## Findings

### 1. [blocker] Vite glob imports escape the approval dependency graph

- **Where:** `pulsern/ops/diagram-attest.mjs:59` · confidence high
- **Problem:** importsOf() follows import declarations, import(), and require(), but ignores import.meta.glob(), which Vite expands into real dependencies. Files loaded this way outside src/diagrams are absent from both diagramSources() and sourceKey(). A signed visual approval and pairing map can therefore remain current after their clinical logic changes.
- **How it fails:** An ABG module loads src/clinical/*.json using import.meta.glob("../clinical/*.json", { eager: true, import: "default" }) and uses a table in its worked-example interpretation. After approval, changing that table leaves sourceKey and the diagram's content fingerprint unchanged. The publication tests accept the existing signed map and approval, while students receive the changed interpretation. The omitted table also never reaches the diagram reviewer as source.
- **Fix:** Either reject import.meta.glob and other unsupported dependency-loading constructs, or expand their dependencies using trusted code and include every matched file in both the review request and freshness key. Add a regression test that changes a glob-loaded clinical file and requires invalidation.

### 2. [major] Approval freshness omits extra theme tokens used in rendered frames

- **Where:** `pulsern/ops/diagram-attest.mjs:32` · confidence high
- **Problem:** themeBlock() hashes only the adjacent .app and .app[data-theme="dim"] blocks. In contrast, render-diagrams.mjs explicitly collects additional token blocks containing --mon or --read-size and incorporates them into the rendered themes. Those additional drawing inputs are excluded from the approval freshness key.
- **How it fails:** After diagrams are approved and paired, an additional monitor-token block changes --ecg or --mon. The renderer would produce different ECG frames, but sourceKey remains unchanged, so the signed approvals and shipped map still pass the freshness gate without a new visual review.
- **Fix:** Use one shared theme-token extraction routine for rendering, review source, and sourceKey, including the additional blocks. Add a mutation test for a token outside the two primary theme blocks.

### 3. [major] The pairing dry run now requires the protected private signing key

- **Where:** `pulsern/ops/map-diagrams.mjs:77` · confidence high
- **Problem:** SIGNER is created with signerFrom() for every invocation except --prepare, including --dry-run. Consequently, the previously public-data-only dry run throws before reading any questions unless the private attestation key is supplied. A dry run does not sign or publish records; checking existing approvals requires only the public key.
- **How it fails:** An operator runs node ops/map-diagrams.mjs --dry-run locally, even with PULSERN_ATTEST_PUBLIC_KEY configured. It exits with 'PULSERN_ATTEST_PRIVATE_KEY is not set' instead of reporting candidate pairings. The new CLI test explicitly requires this regression, so the suite will not catch it.
- **Fix:** Use a public-key verifier for dry runs, with a fail-closed unverified state when the public key is unavailable, as the narration dry run does. Instantiate signerFrom() only for runs that write signed records, and replace the private-key-required dry-run test with coverage proving that no private key is needed and no publication records change.
