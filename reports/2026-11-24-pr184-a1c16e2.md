## Assessment

Not ready to release. The warfarin correction is sound, but legacy review history and trial imports have defects that can lose review access or produce incorrect ability estimates and answer ordering. Review was based on the supplied code and images; tests were not executed.

## Findings

### 1. [blocker] Historical imports update ability in the wrong order

- **Where:** `pulsern/src/answer-apply.js:99` · confidence high
- **Problem:** Historical answers are inserted chronologically into the log, but updateAbility applies them to the account's current ability. Elo updates are order-dependent, especially across the n=10 and n=30 K-factor boundaries, so the resulting ability no longer represents the saved answer sequence.
- **How it fails:** A category has n=9. The student misses a trial question, subsequently answers an account question correctly, then imports the earlier trial. The correct account answer has already used K=40; the imported earlier miss now uses K=24. Chronological processing would apply those K factors to the opposite answers, producing a different theta and readiness estimate.
- **Fix:** Reconcile historical imports chronologically rather than applying them as new events to the final ability state. Preserve the information needed for deterministic replay or reconciliation, and test exact theta/readiness equality between chronological recording and delayed import—not merely equality of ability.n.

### 2. [blocker] Legacy history stops matching the production question catalog

- **Where:** `pulsern/src/question-review.js:29` · confidence high
- **Problem:** An unscoped legacy log row resolves to a raw identity such as "42", while QBank now stamps loaded questions as "bank:42" or "builtin:42". App only classifies legacy rows after both bank and case catalog reads succeed. Until then, existing answers appear unseen and their saved review dates do not match any question. The legacy pool tests use unscoped questions on both sides, so they miss this production mismatch.
- **How it fails:** A valid existing save contains a missed bank question and its numeric-keyed review date. The question-bank read succeeds but the independent case-study request fails, or the student loads the offline fallback. Review Misses omits the saved miss and New questions treats previously answered items as new. A case-service outage can therefore disable existing QBank review history for the entire sitting.
- **Fix:** Provide a source-aware legacy migration that does not require unrelated catalog requests to succeed. Preserve unresolved history explicitly rather than silently treating it as unseen or cleared. Add an integration regression using a legacy save, the stamped production catalog, and a failed catalog request.

### 3. [blocker] Trial attempt IDs are incorrectly used as answer timestamps

- **Where:** `pulsern/src/guest.js:240` · confidence high
- **Problem:** guestEventAt interprets the trial's startedAt plus the answer index as the time each answer happened. Answers given minutes or days later are therefore dated only milliseconds after the trial started. applyAnswer uses these invented timestamps to order results and decide whether to suppress review-schedule updates.
- **How it fails:** A guest starts a trial Monday, answers a built-in question incorrectly Tuesday evening, and then adds the trial to an existing account that answered that question correctly Tuesday morning on another device. The guest miss is assigned Monday's timestamp, inserted before the account's correct answer, and considered superseded. The actual latest miss never enters Review Misses.
- **Fix:** Record an actual timestamp on every guest answer and preserve it through import. Keep attempt IDs solely for idempotency. For legacy guest rows, use a conservative fallback consistent with their recorded local day. Test interleaved account/trial answers and a trial spanning midnight, asserting latest results and review dates.

### 4. [major] A bank refresh can make skipped questions disappear from navigation

- **Where:** `pulsern/src/question-review.js:90` · confidence high
- **Problem:** expandTrialQuestions restores missing bundled questions only from the answer log. Skipped or drafted questions have navigation entries but no log row. If the asynchronous bank load replaces the fallback catalog during a sitting, those questions are no longer available to reveal(), which switches the session to done when lookup fails.
- **How it fails:** The student starts on fallback content while the bank loads, skips a bundled question, and moves on. The bank then arrives without that exact bundled identity. Back or Review skipped cannot restore the question and instead shows the session-complete/no-new-questions screen, despite the outstanding skip and available bank questions.
- **Fix:** Retain immutable question snapshots for every opened navigation entry, or include all held navigation identities when preserving fallback questions across catalog changes. Add a browser test that replaces the questions prop after skipping and verifies Back, draft restoration, and Review skipped still work.
