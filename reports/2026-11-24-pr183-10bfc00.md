## Assessment

## Findings

### 1. [major] Suspend study shortcuts while the toolkit is open

- **Where:** `pulsern/src/study-keys.js:67` · confidence high
- **Problem:** The global shortcut guard excludes tours, filter sheets, and menus, but not the open toolkit. Checking whether the event target is inside a dialog is insufficient: LabPanel's Clear search button removes itself when clicked, which leaves focus on document.body in Chromium. Subsequent digits and Enter then operate on the question underneath the modal.
- **How it fails:** Open the toolkit over an unanswered QBank question, enter a search, and click Clear search. Type "1" and press Enter intending to perform another lookup. With focus now on the body, "1" selects the first answer underneath the toolkit and Enter checks and records it without the student seeing the question feedback. The toolkit browser harness uses dummy question controls rather than QBank, so its existing focus tests cannot catch this.
- **Fix:** Disable underlying study keyboard handlers whenever the toolkit is open, regardless of the event target. Apply the same suspension to Flashcards' separate cardNavAction listener. Also return focus to the search input after clearing, and add an integration test using the real QBank that verifies clearing and typing in the toolkit cannot select, submit, or navigate the underlying question.
