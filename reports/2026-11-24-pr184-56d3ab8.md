## Assessment

Changes need revision. Historical guest imports can corrupt established ability estimates, overwrite review schedules out of chronological order, and undercount streaks. Review was based on the supplied diffs and images; tests were not executed.

## Findings

### 1. [blocker] Historical imports recalculate established ability with different item ratings

- **Where:** `pulsern/src/answer-apply.js:66` · confidence high
- **Problem:** replayAbility resets every category and replays all answers using the calibration available during import. The log does not retain the item rating originally used, and canReplay checks only question identity. Consequently, importing an older answer can change ability in completely unrelated categories.
- **How it fails:** An account correctly answered a difficulty-1 bank question calibrated at 1600, moving that category from 1200 to approximately 1236.36. The student then adds an earlier guest answer in another category before bank calibration loads. The replay uses the difficulty-1 seed of 1100 instead, rewriting the established category to approximately 1214.40. Current calibration can similarly differ from historical calibration even after loading. Subsequent readiness estimates and adaptive selection use the corrupted ability.
- **Fix:** Persist the rating actually applied to each new answer and replay only the affected category using historical ratings. Where historical information is insufficient, do not reset unrelated established ability estimates. Add a regression test importing an older answer in another category while the saved bank answer used a non-seed rating.

### 2. [major] Unrelated legacy rows prevent chronological review-schedule replay

- **Where:** `pulsern/src/answer-apply.js:166` · confidence high
- **Problem:** Replaying one question's schedule is conditional on canReplay(placed), which requires every row in the entire log to have a classified identity. One unrelated legacy or unclassified answer therefore makes an older imported answer update the current schedule directly, even when a later answer to that question is already recorded.
- **How it fails:** The account contains an unrelated unscoped legacy row and a canonical correct answer to builtin:7 on Tuesday. A Monday guest miss for builtin:7 is imported ahead of Tuesday's answer. Because the unrelated row makes canReplay return false, the import schedules a one-day review from Monday, due Tuesday. Chronological processing should apply Monday's miss followed by Tuesday's correction, producing a three-day interval due Friday. The existing tests cover the chronological replay only when all rows are classified.
- **Fix:** Determine schedule replay eligibility from the target question's history, independently of ability replay and unrelated rows. Replay its matching, dated answers chronologically so an older import cannot supersede a later answer. Test this with an unrelated unclassified row present.

### 3. [major] Multiple imported days before an existing streak are undercounted

- **Where:** `pulsern/src/answer-apply.js:42` · confidence high
- **Problem:** noteEarlierDay extends the streak only when the individual imported day is immediately before its current start. Guest entries are processed oldest first, so an earlier day rejected initially is never reconsidered after a later imported day bridges the gap.
- **How it fails:** An existing account has a one-day streak ending Tuesday. Its device trial contains answers from Sunday and Monday, and the student chooses Add. Sunday is initially two days before the streak start and is ignored. Monday then extends the streak to two days, but Sunday is never revisited. The final count is 2 despite study on three consecutive local days.
- **Fix:** Reconcile imported study days as a set against the existing streak, or perform a separate newest-to-oldest streak-extension pass while retaining chronological order for answer and ability processing. Add a regression test for Sunday and Monday trial answers merged into a Tuesday account streak.
