## Findings

### 1. [blocker] Branch-controlled pairing decisions can skip review and publish different values

- **Where:** `pulsern/ops/map-diagrams.mjs:154` · confidence high
- **Problem:** The decision cache comes from the feature branch, but matching public hashes and extracted values are sufficient to skip the reviewer. Neither the cached decision nor its `shown` field is authenticated. `publishable()` checks `extracted`, while `buildItemMap()` publishes `shown` without checking that it follows from the confirmed values.
- **How it fails:** For a question whose potassium is 6.2, retain the correct hashes and `extracted: {"k":6.2}` but change the cached entry to `attach: true, shown: {"k":2.9}`. With a legitimately approved potassium diagram, the trusted mapper skips the paid review and publishes 2.9. The application's question and diagram fingerprints both match, so it draws hypokalemia beside a hyperkalemia question.
- **Fix:** Authenticate pairing decisions with a signature covering the question, diagram, extracted values, and reviewer outcome; reject unsigned or modified cache entries before reuse. Derive the published values from the authenticated confirmation and current extraction rather than trusting a separate cached `shown` field. Add an end-to-end regression for the modified-cache example.

### 2. [blocker] The merge-time publication test accepts forged review signatures

- **Where:** `pulsern/tests/diagram-gate.test.js:165` · confidence high
- **Problem:** In the normal secret-less CI path, the publication gate checks only that `sig` contains 64 hexadecimal characters. The comment assumes that the trusted mapper wrote the map, but nothing in this test or the application enforces that provenance. This critical test therefore reports approval for records that were never signed or reviewed.
- **How it fails:** Commit a hand-written map with current fingerprints and `sourceKey`, together with an index entry containing `verdict: "PASS"`, the expected frames, and `sig: "0".repeat(64)`. All assertions in the shipped-map gate pass without running either paid workflow. `pairsFor()` then displays the pairings without consulting the review index.
- **Fix:** Make publication verify authentic approvals independently of the branch's assertion that a mapper ran. Use public-key signatures verifiable in CI, or a trusted publication-validation job that holds the verification credential and treats the branch as data. Do not expose the HMAC secret to PR test code. Add a regression requiring a correctly shaped but invalid signature to fail the actual publication gate.

### 3. [blocker] A forged current-clip entry bypasses audio verification

- **Where:** `pulsern/ops/narrate.mjs:132` · confidence high
- **Problem:** `isCurrentClip()` trusts the branch's input ID, QA version, audio-hash string, and URL suffix. Those public fields do not establish that the referenced recording passed QA for this script. The trusted narration job skips such an entry, and `audioFor()` subsequently trusts its separately supplied text fingerprint.
- **How it fails:** Copy another existing clip's `audio` and hashed URL into a step's manifest entry while retaining the desired step's current `id`, `textFp`, and QA version. The narration workflow counts it as unchanged and never transcribes it. CI's manifest checks pass, and students hear the other clip over the intended clinical caption.
- **Fix:** Authenticate completed audio-QA records, binding the script identity, text fingerprint, QA version, exact audio hash, and storage location. Verify that record before skipping a clip and before publication, or retrieve and recheck untrusted entries. Test swapping two valid hashed clip URLs while retaining each step's script metadata.

### 4. [blocker] Registry changes can inherit a signed visual approval without being reviewed

- **Where:** `pulsern/ops/review-diagrams.mjs:111` · confidence high
- **Problem:** The renderer executes `src/diagrams/index.js`, but `diagramSources()` starts from the individual diagram module and the explainer, not the registry entry point. Although `sourceKey()` hashes the registry's top-level text, the per-diagram request and review key omit it. This reuse branch then carries an old verdict to the new global source key and signs it again.
- **How it fails:** Change `index.js` to wrap `abg.dynamicCaption` or `abg.Diagram`, preserving behavior for the default example but returning an incorrect result for other patient values. The prepared example captions and frames remain identical, and the individual diagram sources remain identical. `canReuse()` succeeds, no model sees the wrapper in the diagram review, and the old PASS is re-signed for the changed code.
- **Fix:** Include the actual registry entry point and its transitive project dependencies in the source shown to the reviewer and in the per-diagram review key. Ensure the publication key covers that same dependency closure. Add a regression that changes non-example behavior through the registry and requires a new review.

### 5. [major] Browser installation occurs after tests that now require a browser

- **Where:** `.github/workflows/pulsern-ci.yml:45` · confidence medium
- **Problem:** `tests/prepared.test.js` now launches the real diagram renderer during `npm test`, but Chromium is installed only after that command succeeds. The new ordering depends on a browser already being available before the explicit provisioning step.
- **How it fails:** On a clean runner without a browser executable available to `launchBrowser()`, the preparation tests fail when they launch Chromium, and CI never reaches `playwright install`. I could not verify whether the unchanged, unattached `browser.mjs` supplies a system-browser fallback that happens to work on the current hosted image.
- **Fix:** Move the Playwright browser-install step before `npm test`, or explicitly separate browser-dependent tests and run them after installation. Verify the workflow on a clean runner with no pre-existing Playwright browser cache.
