## Assessment

Changes are required before release. Guest imports can incorrectly suppress ability updates, and the legacy bank-case repeat test uses provenance that real legacy saves do not contain. The warfarin correction and changed screenshots show no new clinical error.

## Findings

### 1. [blocker] Guest imports conflate unrelated bank and built-in questions

- **Where:** `pulsern/src/guest.js:229` · confidence high
- **Problem:** guestImportIdentity adds the bare numeric ID as an alias whenever that ID exists in the built-in registry. It cannot establish that an account log row with that number represents the built-in question. Both shipped import paths pass QUESTIONS, so an unrelated shared-bank answer can make the imported answer count as already answered, suppressing its XP, ability update, daily credit and streak credit.
- **How it fails:** An account has answered shared-bank question 7, whose stem differs from built-in question 7. The student completes built-in question 7 in the guest trial and selects Add. The import aliases guest-7 to 7 and incorrectly treats the two different questions as one. The existing test demonstrating independent bank IDs does not exercise this shipped import path with the built-in registry supplied.
- **Fix:** Match cross-namespace answers only when persisted provenance or a verified canonical content identity establishes equivalence. Do not alias historical numeric log IDs merely because the built-in registry contains that number. Add an import regression test with an unrelated bank row sharing a built-in ID and pass builtIns exactly as App does.

### 2. [blocker] Accepted repeat attempts are omitted from the ability calculation

- **Where:** `pulsern/src/guest.js:282` · confidence high
- **Problem:** The import appends alreadyAnswered attempts to the answer log but skips their updateAbility calls. Ordinary signed-in record calls update ability for every scored attempt, including repeat reviews. An XP-repeat restriction is therefore changing the readiness input policy only for imported answers.
- **How it fails:** A student previously missed guest-1, later answers it correctly in another trial, and explicitly adds that trial to the same account. The correct attempt is appended and can earn the correction bonus, but the category theta and observation count remain unchanged. Enough imported repeats can also move the log past the 12-answer readiness threshold without corresponding ability observations.
- **Fix:** Apply updateAbility to every validated newly imported attempt that survives attempt-level idempotency. Keep XP eligibility separate from ability updates. Test both a repeated correct answer and a corrected miss against the equivalent sequence of signed-in record calls.

### 3. [major] Legacy bank-case repeat test invents a source marker absent from old saves

- **Where:** `pulsern/tests/review3.test.js` · confidence high
- **Problem:** The N7 test supplies source: "case" on its historical bank-case row. The pre-change CaseStudy record call did not persist that marker, and tagLegacyCaseRows only recognizes the bundled case allowlist—not database cases. Consequently, sameAnswer rejects the legacy numeric alias for real saved bank-case answers, despite the test reporting successful migration.
- **How it fails:** A real legacy save contains { id: 50120, cat: "Pharmacology", diff: 3, correct: true } from database case 12, step 0. Migration leaves source unset. Reopening that step produces case-db12-0, and answerXp awards another 30 first-answer XP instead of identifying the earlier correct attempt. The current fixture passes only because it manually adds the missing provenance.
- **Fix:** Test the actual pre-change row without source. Resolve legacy bank-case identities using actual case/question registries or another provenance-preserving migration before applying legacy aliases; do not infer identity where a question-ID collision remains possible.
