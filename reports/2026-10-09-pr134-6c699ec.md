## Assessment

Not ready to merge. The visual-review gate can certify a different build from the one deployed, and narration QA still has a clinical-abbreviation false pass. This review is based on the supplied changes; tests and GitHub environment settings were not independently verified.

## Findings

### 1. [blocker] Computed Vite configuration bypasses the supported-build gate

- **Where:** `pulsern/ops/diagram-attest.mjs` · confidence high
- **Problem:** buildConfigProblems() rejects selected object-property syntax, not unsupported configuration generally. For example, adding Object.assign(config, JSON.parse('{"resolve":{"alias":{"./kit.jsx":"/src/clinical/alternate-kit.jsx"}}}')) to an otherwise supported configuration passes: the forbidden keys exist only inside a string. Production follows that alias, while bundleDiagrams() ignores the candidate configuration and moduleClosure() follows the original kit.
- **How it fails:** A branch supplies an alternate kit that changes a clinical gauge or label and installs the alias through JSON.parse. The visual reviewer sees the original drawing and original module closure. Its review key can remain unchanged, allowing review-diagrams.mjs to reuse the old PASS and sign it with the candidate's new sourceKey. The alternate drawing has never received that visual review.
- **Fix:** Accept only a narrowly defined declarative configuration whose values can be completely resolved by trusted code; reject unsupported calls, assignments, indirection and configuration mutation. Alternatively, derive and verify the actual production module graph in an isolated build. Add a regression test using an alias introduced through JSON.parse/Object.assign and require refusal before an approval is reused or signed.

### 2. [blocker] Plural stripping accepts a dropped letter in a fluid abbreviation

- **Where:** `pulsern/ops/narrate-lib.mjs` · confidence high
- **Problem:** speechTokens() removes a terminal s from every token longer than four characters, including alphanumeric clinical abbreviations. D10NS becomes d10n, while D10N already becomes d10n. Consequently, audioCheck("The solution is D10NS.", "The solution is D10N.") returns pass=true with similarity 1 despite the missing formulation letter.
- **How it fails:** An explainer script names D10NS and a recording/transcript drops the final S. recordAll() treats the clip as faithful, and the narration job uploads and signs the incorrect recording. The exact-word check does not protect this clinical abbreviation.
- **Fix:** Do not apply unrestricted suffix stemming to clinical abbreviations or alphanumeric tokens. Use explicit, reviewed plural/unit aliases instead of deleting arbitrary final letters. Add faithful and corrupted D10NS transcript tests, and bump QA_VERSION so recordings accepted by the weaker rule are rechecked.

### 3. [major] Candidate dependencies are hashed but never used for the visual review

- **Where:** `pulsern/ops/render-diagrams.mjs` · confidence high
- **Problem:** bundleDiagrams() resolves bare imports through createRequire() rooted in the trusted checkout. Production installs the candidate's package-lock.json instead. sourceKey() hashes the candidate dependency files, but diagramRequest()/reviewKey() do not include their contents, and moduleClosure() deliberately stops at package imports. There is no check that the two dependency trees agree.
- **How it fails:** A feature branch upgrades React/ReactDOM or another dependency used by a diagram. The prepare job still renders with the default branch's installed version. If the source and those old-version screenshots are unchanged, the paid job reuses the old verdict and signs the new dependency-bound sourceKey. A rendering regression introduced by the candidate dependency is therefore absent from the purported review of that build.
- **Fix:** Fail closed when candidate runtime dependencies differ from the dependencies used by the trusted renderer, or render with the candidate's exact dependency tree in an appropriately isolated preparation environment. Bind the dependency identity actually used for rendering into the review key. Test a candidate/trusted dependency mismatch through the approval-reuse path.
