## Assessment

Request changes. The guest handoff can lose data and changes earned XP, imported misses cannot be reviewed, and several reward behaviors contradict their user-facing guarantees. The new public trial also exposes incorrect clinical content and omits required disclaimers. Tests were reviewed statically; I could not execute them from the supplied artifacts.

## Findings

### 1. [blocker] An older autosave can clear trial answers before the merged save succeeds

- **Where:** `pulsern/src/App.jsx:602` · confidence high
- **Problem:** Every completed autosave checks the shared pendingGuestClear ref, even if that save's serialized blob contains no trial answers. The ref identifies pending work, not the save that actually carries it.
- **How it fails:** An existing account's initial autosave remains in flight. The student taps Add, setting pendingGuestClear and starting a merged save. The initial save completes and deletes the device trial; the merged save then fails. Neither the account nor the device retains the trial answers.
- **Fix:** Bind trial clearing to successful persistence of the specific snapshot containing the merged entries, and serialize writes so an older snapshot cannot overwrite it. Show the saved confirmation only after that write succeeds. Add a browser test with deferred initial and merged writes, rejecting the merged write.

### 2. [blocker] The public trial serves the incorrect warfarin question

- **Where:** `pulsern/src/guest.jsx:32` · confidence high
- **Problem:** The new unconditional guestPool(QUESTIONS) path includes built-in question 3. It keys vitamin K plus holding warfarin for INR 4.8 without active bleeding, and its rationale teaches vitamin K as routinely indicated. For INR 4.5–10 without bleeding, vitamin K is not routinely recommended absent additional bleeding-risk considerations, which this stem does not provide.
- **How it fails:** An anonymous visitor receives question 3 in the trial and is taught that an INR of 4.8 without bleeding routinely calls for vitamin K.
- **Fix:** Correct the question and rationale through the accuracy gate before including it in the trial. Provide a defensible answer for the stated circumstances, or explicitly supply the additional risk factors needed to justify vitamin K.

### 3. [blocker] The new guest study screen omits required disclaimers and legal links

- **Where:** `pulsern/src/guest.jsx:87` · confidence high
- **Problem:** GuestTrial renders questions, clinical rationales, and the save screen without an educational-use disclaimer, NCSBN trademark disclaimer, or Terms/Privacy/disclaimer links. The lab disclaimer is confined to an initially closed toolkit and does not supply these notices.
- **How it fails:** A visitor studies all five questions at /app/try without ever seeing the required notices or legal links. The authenticated Stats notices are unreachable from this screen.
- **Fix:** Add a visible guest footer containing the educational-use and NCSBN trademark disclaimers and the required legal links. Test their presence on both the question and completion screens.

### 4. [blocker] Fresh accounts never persist earned promotions

- **Where:** `pulsern/src/App.jsx:494` · confidence high
- **Problem:** A direct signup with no saved row keeps emptyRewards().rankHigh as null. The moments effect passes the same current snapshot as both before and after; detectMoments therefore compares the current rank against itself while rankHigh is null and never records a promotion. This contradicts the visible promise that earned ranks are never taken away.
- **How it fails:** A new account earns New Grad RN, then its recent accuracy falls below the requirement: the displayed rank falls again because no high-water mark was saved. Reloading instead applies legacyRankIndex to this modern account, potentially granting a title whose answer/mastery requirements were never met. Existing tests start with migrated rewards or explicitly set rankHigh to 0, missing this path.
- **Fix:** Initialize genuinely new accounts with rankHigh 0 and persist each earned promotion. Apply legacy XP grandfathering only to genuinely legacy saves. Test direct signup with no progress row, promotion, declining accuracy, and reload.

### 5. [blocker] Reduce effects leaves multiple reward animations enabled

- **Where:** `pulsern/src/App.jsx` · confidence high
- **Problem:** The setting adds fx-reduced, but the new .stat-chip.pulse, .flashcard.flip-in, .feedback.ok, and .opt.st-picked-correct animations are unconditional. Only the OS media query disables them; fx-reduced does not. The setting explicitly promises to turn off every reward animation and vibration.
- **How it fails:** With OS reduced motion off, a student enables Reduce effects in Stats. XP still scales, correct feedback still pulses/scales, and cards still rotate when flipped. The unit test checks motionAllowed, while browser coverage checks only the OS preference.
- **Fix:** Gate these animations on the same effect preference or add explicit fx-reduced overrides. Add a browser test enabling the in-app setting while prefers-reduced-motion remains no-preference and assert computed animation names are none.

### 6. [major] Merging a trial awards XP that rapid answers did not earn

- **Where:** `pulsern/src/guest.js:100` · confidence high
- **Problem:** guestAnswer applies the reading-time floor, but its persisted log omits timing or award eligibility. mergeGuestIntoBlob recomputes XP by calling answerXp without ms, which defaults to Infinity. Consequently, previously ineligible correct answers receive full XP during handoff.
- **How it fails:** A guest rapidly answers five items correctly and sees 0 XP on the trial completion screen. Creating an account then awards the full difficulty-based XP for those same answers.
- **Fix:** Persist enough per-answer eligibility information to recompute awards without discarding the time floor, validate it during handoff, and preserve the originally earned total. Add a test that merges a rapid-answer trial and verifies its XP remains zero.

### 7. [major] Imported trial misses become unresolvable answer-history entries

- **Where:** `pulsern/src/guest.js:121` · confidence high
- **Problem:** The merge prefixes log IDs with guest- but does not retain corresponding questions or merge their review schedules. Account allQuestions contains the numeric bank/fallback questions and custom questions, not these prefixed IDs. Review pools therefore cannot resolve imported misses to content.
- **How it fails:** A guest misses a question and adds the trial to an account. The wrong answer affects stats and ability, but it never appears in Review Misses or a due Today review. A reload can derive a schedule entry, but still cannot find the question.
- **Fix:** Keep imported trial questions resolvable under their collision-safe IDs and merge their review scheduling consistently. Test that an imported wrong answer appears in Review Misses and can subsequently be corrected without mapping it to an unrelated shared-bank numeric ID.

### 8. [major] Resetting progress leaves today's streak update disabled

- **Where:** `pulsern/src/App.jsx:1028` · confidence high
- **Problem:** resetAll clears streak state but does not clear touchedDay.current. Once the student has studied today, touchDay returns early for every subsequent answer on that date even after the reset.
- **How it fails:** A student answers a question, resets all progress, then answers another question that same day. Daily answers and XP advance, but the streak remains Day 0 until a reload or another calendar day.
- **Fix:** Reset the touched-day guard along with streak state. Add an integration test covering answer, reset, and another answer on the same local date, expecting a Day 1 streak.
