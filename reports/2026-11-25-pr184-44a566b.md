## Assessment

Text pass: The change is substantial and generally well-tested, but I found several issues that should be addressed before release: a design-system violation in the new reward colors, an inaccurate accessibility description on the changed product screenshot, a potential RLS gap in the pending-merge table, and a logic mismatch where repeat correct answers can still build a personal-best run despite earning zero XP.

Picture pass: No defects found in the after images.

## Findings

### 1. [major] New orange color violates explicit design-system rule

- **Where:** `src/App.jsx:1180` · confidence high
- **Problem:** The rule 'Design system: teal/green palette, coral only for incorrect/critical, amber only for caution, no new colors' is violated. The new CSS variables --streak-flame:#E2701A and --streak-flame-fill:#F8D2A8 introduce a new orange/amber color for streak visuals that is not coral and not reserved for caution. This will be visible to every student in the streak chip and shift card.
- **How it fails:** A student opens the app and sees the new orange flame icon in the header and Today screen, violating the owner's explicit palette constraint.
- **Fix:** Reuse the existing amber variable (--amber:#E9A23B) for the flame, or make the flame a teal/green shade. Do not introduce a new hex color.

### 2. [major] Alt text for Today dashboard screenshot still describes removed 'study goal' card

- **Where:** `index.html:214` · confidence high
- **Problem:** The alt attribute for /product/pulsern-today-dashboard.png says 'PulseRN Today dashboard showing the daily round, candidate monitor, study goal, and progress cards', but the screenshot now shows 'Today's shift', 'Clinical career', 'Student Nurse', and 'Day 0 of 7' — the 'study goal' card was replaced. The same inaccurate alt appears in src/landing.jsx and public/product/product-screenshots.json. Screen reader users get a description that does not match the image.
- **How it fails:** A visually impaired student using a screen reader hears 'study goal' but the image shows a shift checklist and career card, misleading them about the product's features.
- **Fix:** Update the alt text to 'PulseRN Today dashboard showing the daily round, candidate monitor, today's shift, and clinical career cards' or specifically reflect the visible elements.

### 3. [major] progress_pending_merge has no insert policy; trigger may fail under RLS

- **Where:** `supabase/migrations/022_progress_revision_guard.sql:30` · confidence medium
- **Problem:** The table progress_pending_merge has RLS enabled with only SELECT and DELETE policies. The revision guard trigger is security definer and inserts rows when a legacy save is parked. If the function owner (migration role) does not have BypassRLS, the insert will be blocked by RLS, causing the trigger to raise an error and the progress update to fail, potentially preventing saves for that user.
- **How it fails:** A user on an older app version attempts to save. The trigger attempts to park the snapshot but hits an RLS violation, the entire update transaction fails, and the student's progress save is rejected with an error.
- **Fix:** Add an insert policy on progress_pending_merge for the authenticated user (e.g., WITH CHECK (auth.uid() = user_id)), or ensure the migration role has BypassRLS and document that requirement.

### 4. [minor] Run increments on repeat correct answers even though XP is zero

- **Where:** `src/answer-apply.js:91` · confidence medium
- **Problem:** In applyAnswer, run is incremented whenever answerCountsForRun returns true (correct and considered). answerCountsForRun does not check for repeats. A student who answers the same question correctly again (e.g., after a re-delivery) will have their consecutive-correct run and best-run increased, even though the answer earned no XP and was already mastered. The old run logic also incremented on any correct, but the new XP rules create an inconsistency: a repeat is a non-scoring event for XP but still scoring for run.
- **How it fails:** A student reviews a previously correct question, answers it correctly again, and their personal best run increases from 3 to 4 without learning anything new, making the best-run stat less meaningful.
- **Fix:** Pass a repeat indicator to answerCountsForRun or compute run by excluding answers where answerXp returned reason 'repeat'. Consider making run only increment on first-time correct or fix corrections.

### 5. [minor] assertCaptureFontsLoaded relies solely on document.fonts statuses and may not account for unused fonts

- **Where:** `ops/capture-product-screenshots.mjs:60` · confidence low
- **Problem:** The function iterates document.fonts and requires every listed face to have status loaded. If a required font face is declared but never used by any element, the browser may not have attempted to load it, and face.load() might not be called on it because it is not in document.fonts. This could cause the assertion to pass even though the font is not actually available, defeating the purpose of the check.
- **How it fails:** A future change removes usage of one Archivo weight from the app but the capture still passes because that face is not in document.fonts, allowing screenshots to be taken with a fallback font.
- **Fix:** Explicitly call document.fonts.load() for each required family/weight in the page before checking statuses, as the existing settle() function does for 'PulseRN Capture Symbols'.
