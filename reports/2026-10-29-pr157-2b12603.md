### 1. [blocker] Exclude numeric tokens from compound folding

- **Where:** `pulsern/ops/narrate-lib.mjs:279` · confidence high
- **Problem:** Restricting the regex to letters does not exclude numbers: speechTokens converts number words into digits. A script containing "forty-five" registers the pair "40 5", which foldCompounds then joins into "405" wherever those adjacent tokens occur. audioCheck has no separate numeric-sequence check, so this can approve changed clinical numbers.
- **How it fails:** Compare script "The forty-five-year-old client's respiratory rate and pain score are forty, five." with transcript "The forty-five-year-old client's respiratory rate and pain score are 405." The comma keeps the scripted readings as separate tokens initially, but the age-derived compound pair merges them into "405". Both comparisons then match exactly, producing pass=true and similarity=1.
- **Fix:** Never register or fold compound components whose normalized tokens contain digits. Add this regression with a passing faithful baseline and a failing merged-number transcript. The current numeric test contains no hyphenated compound, so it never exercises this failure path. Bump QA_VERSION when tightening the check so potentially affected approvals are rechecked.
