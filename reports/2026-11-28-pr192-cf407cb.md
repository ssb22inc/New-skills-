## Assessment

The change is mostly copy/SEO/attribution work, but it does introduce a false marketing claim on a supported path and leaves a stale image-provenance manifest. No clinical answer keys, scoring, or auth paths are affected.

## Findings

### 1. [blocker] Homepage claims every public guide is reviewed, but the build supports unreviewed public guides

- **Where:** `src/landing.jsx (FAQ entry 'Who created PulseRN?') and index.html (FAQPage JSON-LD first answer)` · confidence high
- **Problem:** The visible/FAQ copy and structured data now say Sheldon Bennett 'reviews every public guide'. However `ops/build-learn.mjs` still publishes guides where `provenanceFor(a).review.decision` is not `approved`. On that path the guide is still a public page at `/learn/<slug>/`, its meta line says 'review evidence pending', and the `/learn/` index correctly switches to 'Guides are written by, and approved guides are reviewed by,'. The homepage/FAQ claim would be false. Concrete state: any article whose recorded review is pending, out of date, or whose content/source hash no longer matches the ledger entry.
- **How it fails:** A pending guide is rendered and indexed publicly; a student then sees the homepage/FAQ saying every public guide is reviewed.
- **Fix:** Condition the home/FAQ claim on the same review state, or state 'approved guides are reviewed by Sheldon Bennett, RN.'

### 2. [major] Product screenshot source-set manifest is stale after source changes

- **Where:** `public/product/product-screenshots.json` · confidence high
- **Problem:** This PR changes `src/landing.jsx`, `src/pricing.js`, and `src/grading-note.js`, but the manifest's `sourceSetSha256` and the `sourceFiles` hashes for those files were not updated; it was edited only to change image captions. The file now records a source-set that does not match the current repository.
- **How it fails:** Any product-image/provenance check or release gate that recomputes source hashes will fail closed, or the public manifest will falsely assert the screenshots came from the current source set.
- **Fix:** Regenerate or update the source hash block after the source changes.

### 3. [minor] Free practice page gets a CTA linking to itself

- **Where:** `ops/build-public-pages.mjs (page() callout; generated public/free-nclex-practice-test/index.html)` · confidence high
- **Problem:** The generic page callout appends `<a class="button alt" href="/free-nclex-practice-test/">Try 20 free questions</a>` to every generated public page. On the generated `/free-nclex-practice-test/` page, this becomes a self-link to the very page the user is already on.
- **How it fails:** A user on `/free-nclex-practice-test/` follows the CTA and is reloaded on the same page instead of advancing to a useful next step.
- **Fix:** Suppress the secondary free-practice CTA when the slug is `free-nclex-practice-test`, or point it to a useful next page.

### 4. [minor] FAQ test contains a no-op replace

- **Where:** `tests/homepage-faq.test.js` · confidence high
- **Problem:** The expected answer uses `.replace("A 7-day free pass", "A 7-day free pass")`, which does nothing. It is dead code that suggests intended normalization while actually comparing the raw strings unchanged.
- **How it fails:** A later maintainer may believe this is a meaningful label normalization and trust the test to validate something it does not.
- **Fix:** Remove the no-op; if label normalization is needed, make it intentional and test its behavior separately.
