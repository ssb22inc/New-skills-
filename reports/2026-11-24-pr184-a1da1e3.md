## Assessment

Not ready to release. Legacy-history handling can hide saved misses or associate them with unrelated questions, and synthesized reviews bypass Focus filters. Review was based on the supplied diffs and images; the tests were not executed.

## Findings

### 1. [blocker] A failed catalog read hides legacy misses from review

- **Where:** `pulsern/src/App.jsx:903` · confidence high
- **Problem:** Classification requires both catalog reads to succeed. Until classification runs, legacy rows remain unscoped, but the new review logic neither serves their questions nor creates unresolved-review cards for them. settledResult returns "pending", scheduleEntry rejects their numeric schedules, and unresolvedCards only handles rows already marked unclassified. This also makes the dashboard report "No misses to fix" when saved misses exist.
- **How it fails:** Load a pre-change save containing a wrong answer and its numeric missSchedule entry. If the case-studies request fails—even while the question-bank request succeeds—the missed question disappears from Review Misses and Today for the entire mount. The same failure affects the built-in offline fallback.
- **Fix:** Represent unresolved legacy history explicitly even when a catalog read fails, without guessing its source. Preserve access through an unresolved-review card or another safe fallback, and support retrying the catalog read. Add a browser regression using an ordinary unscoped legacy miss, not a fixture already marked unclassified, with one catalog request failing.

### 2. [blocker] A remaining catalog hit can misassign historical answers

- **Where:** `pulsern/src/question-key.js:69` · confidence high
- **Problem:** The unique-hit branch assigns a source before checking whether the hit's category contradicts the saved category. Moreover, bankIds contains only currently approved practice items, so absence from that list does not establish that a historical answer was not a bank answer. With an overlapping ID, withdrawing a bank item can cause its old answers and review schedule to be reassigned to an unrelated bundled question.
- **How it fails:** A legacy miss belongs to a bank question whose number also exists in the bundled catalog under another category. The bank question is subsequently rejected or withdrawn. On the next load, only the bundled catalog contributes a hit, so classifyLog assigns the bundled key and rekeySchedule transfers the old review date. Review Misses then displays the unrelated bundled stem, and answering it advances the wrong question's review.
- **Fix:** Reject a proposed classification when its known category contradicts the normalized saved category. Do not use the approved-only bank list as proof of historical source absence; retain unresolved provenance where necessary. Add a regression for an overlapping bank item removed from the approved catalog.

### 3. [major] Unresolved review cards bypass category and item-type filters

- **Where:** `pulsern/src/question-review.js:236` · confidence high
- **Problem:** QBank applies inFocus before calling reviewPools, but unresolvedCards then reconstructs every unclassified miss from the complete log. Those synthesized cards are never passed through the Focus predicate, so filtering the supplied question list does not filter these reviews.
- **How it fails:** A student has an unresolved Pharmacology miss and selects only Management of Care, or selects only dosage calculations. Review Misses still counts and serves the Pharmacology unresolved card, synthesized as type "mc", even when no matching review exists in the selected focus.
- **Fix:** Apply the same Focus predicate to synthesized unresolved cards before computing counts and session pools. Keep the full candidate catalog available separately for identifying the historical question. Add UI tests covering category and item-type filters with unresolved history.
