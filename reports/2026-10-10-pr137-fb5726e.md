## Assessment

The new free-pass duration is consistently reflected in the client and public copy, and the migration predicates appear aligned with the helper. However, the migration's critical SQL behavior is not actually tested, and updated comparison claims are published with source records that predate the claimed change.

## Findings

### 1. [blocker] Migration test checks SQL fragments, not migration behavior

- **Where:** `pulsern/tests/free-pass.test.js:104` · confidence high
- **Problem:** The migration test only searches the SQL for expected strings and checks the separate JavaScript helper. It never executes or behaviorally evaluates migration 017, so it can pass while the database migration changes entitlements incorrectly.
- **How it fails:** If the migration's final `and not exists (...)` is accidentally changed to `or not exists (...)`, the test still finds `other.plan <> 'pass1'` and passes. An expired legacy pass belonging to someone with a paid-plan row could then be refreshed, contrary to the migration's stated exclusion.
- **Fix:** Add a database-level migration test, or another behavioral SQL test that applies the migration to representative rows and verifies active, expired, paid/comped, and already-extended cases. Do not treat substring assertions as evidence that the SQL matches the helper.

### 2. [major] Updated seven-day claims cite older source checks

- **Where:** `pulsern/ops/commercial-content.mjs:7` · confidence medium
- **Problem:** The comparison pages now claim a seven-day free pass and set their page verification date to 2026-10-10, but the PulseRN sources they cite still record `accessedAt` as 2026-09-29 (and retain IDs dated 2026-09-03). Those records predate this change; the prior public copy described a one-day pass. The generated pages therefore claim verification and cite evidence that does not substantiate the changed duration.
- **How it fails:** A prospective student following the cited source record sees a seven-day trial claim on a page marked verified 2026-10-10, while the recorded PulseRN pricing/home checks are from before the seven-day offer existed. The comparisons' sourcing and freshness claims are consequently misleading.
- **Fix:** Record the actual check date and source version for the PulseRN pricing/home evidence used to support the seven-day offer, regenerate the evidence and pages, and ensure the displayed page verification date does not imply checks that the source records do not document.
