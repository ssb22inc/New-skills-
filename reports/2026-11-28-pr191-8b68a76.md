## Findings

### 1. [minor] Retired-path matching logic is split and the list is dead production data

- **Where:** `ops/retired-page.mjs:5 and middleware.js:8:5` · confidence medium
- **Problem:** RETIRED_PATHS is exported and tested, but neither middleware.js nor isRetired() consumes it. The actual retired set is hardcoded twice: the Vercel matcher hardcodes /compare, and isRetired() hardcodes the /compare prefix. If a future retired path outside /compare is added to RETIRED_PATHS, isRetired() would return true for it but middleware would not answer 410.
- **How it fails:** Developer adds '/old-course/' to RETIRED_PATHS and assumes publication is retired; traffic to /old-course/ falls through to the normal 404/static path instead of the 410 middleware.
- **Fix:** Have middleware or isRetired derive behavior from RETIRED_PATHS, or rename the list so it cannot be mistaken for the actual retired-path source.

### 2. [minor] Public 410 can be cached for an hour after same-URL relaunch

- **Where:** `middleware.js:16:16` · confidence low
- **Problem:** The 410 response is cacheable with public, max-age=3600. The file comment explicitly contemplates relaunching a page at the same URL later. A cached 410 could still be served by browsers/proxies for up to an hour after that relaunch.
- **How it fails:** Page /compare/pulsern-vs-uworld/ is relaunched; a visitor who previously received the 410 within the current hour may still see Gone instead of the new page.
- **Fix:** Use a shorter TTL for the 410, add a purge mechanism on relaunch, or document that the cache TTL must be cleared as part of relaunch.

### 3. [minor] 404 page has two sources of truth and no drift test

- **Where:** `public/404.html:1 and ops/build-public-pages.mjs notFoundPage():1` · confidence medium
- **Problem:** The 404 markup exists both as a committed public/404.html and as notFoundPage() in build-public-pages.mjs. The tests read the committed file, not builder output, so the generated page can drift from the tested artifact without failing CI.
- **How it fails:** ATTRIBUTION_BOOT_TAG, CSS, or footer/legal copy changes in the builder; build rewrites public/404.html, but tests continue validating the old strings or no longer catch a regression in the deployed file.
- **Fix:** Either generate the public file only and delete the duplicate source, or add a test that executes notFoundPage() and compares it to public/404.html.
