## Assessment

Request changes. The paywall can quote a different price from checkout, onboarding can falsely announce active free access, and the cap/entitlement tests exercise an independent implementation rather than the production grant function. Cohort-read failures also produce false availability figures.

## Findings

### 1. [blocker] Displayed prices do not follow the server's cohort pricing

- **Where:** `pulsern/src/billing.jsx:86` · confidence high
- **Problem:** The paywall uses catalog prices unless a code was explicitly applied, but checkout automatically charges clinical members $40 for sub30. Ordinary code-check responses also ignore membership, while checkout overrides those codes with the cohort price.
- **How it fails:** A member arriving through /clinicals sees $99 in the plan picker but receives a $40 checkout. More seriously, if that member applies an active partner code worth $70 off, code-check displays $29, but checkout ignores that quote and charges $40.
- **Fix:** Return effective, membership-aware prices from the server when loading the paywall. Use the same pricing decision for initial display, code-check, and checkout, including an explicit and consistent rule for partner-code precedence.

### 2. [blocker] Expired members are told their 30 free days are active

- **Where:** `pulsern/src/clinical.js:198` · confidence high
- **Problem:** completeClinicalClaim treats "already" as sufficient to display "Your 30 free days are on" without checking the subscription expiry. The RPC deliberately does not extend an existing membership, and AuthGate discards its expires_at value.
- **How it fails:** A student whose clinical trial expired visits /clinicals on a new device. The RPC returns "already" with an expired expires_at. Empty localStorage causes the welcome screen to announce active free access, although no access was granted or renewed.
- **Fix:** Pass the returned expiry into the onboarding decision and verify that access is currently active before displaying active-trial copy. Expired existing members should receive an accurate expired-access or installation message instead.

### 3. [blocker] Cap and entitlement tests validate unused duplicate logic

- **Where:** `pulsern/tests/clinical.test.js:174` · confidence high
- **Problem:** The cap, eligibility, expiry, and idempotency tests call claimCohortSpot, but production calls the SQL claim_cohort_spot RPC. The migration test only searches for text, and billing tests stub the RPC's result. These tests therefore do not establish that the production publication-independent entitlement gate enforces those properties.
- **How it fails:** Changing the SQL cap condition to never reject claims leaves the JavaScript cap tests, SQL substring assertions, and mocked billing tests passing. Production can then exceed the advertised cap despite a green safety suite.
- **Fix:** Exercise migration 019 against PostgreSQL and call the actual RPC for cap exhaustion, internal-account exclusion, paid/comp eligibility, expiry extension, repeat claims, and concurrent claims for the last spot. Do not present tests of an independent JavaScript model as verification of the production function.

### 4. [major] Applying CLINICALS does not refresh the access it grants

- **Where:** `pulsern/src/billing.jsx:72` · confidence medium
- **Problem:** Clinical code-check now creates or extends a subscription, but apply only updates the displayed code. It does not invoke the supplied onRefresh callback or otherwise propagate the changed entitlement to the parent.
- **How it fails:** An expired student applies CLINICALS successfully. The database grants 30 free days, but the component continues using the old expired entitlement and can leave the student on the purchase screen until a separate refresh. I could not verify whether the unprovided App.jsx has an independent refresh mechanism that mitigates this.
- **Fix:** After a successful clinical claim through code-check, refresh the parent's entitlement and transition out of the paywall when access is available. Add an interaction test covering an expired entitlement becoming a valid trial after Apply.

### 5. [major] Failed cohort reads are reported as available spots

- **Where:** `pulsern/api/marketing.js:258` · confidence high
- **Problem:** Any cohort-read error is converted to empty member arrays. buildCohortFunnels always turns those arrays into a clinical cohort with zero members and the full cap available, and buildMarketingPayload publishes it as a live offer. The equivalent fallback exists in api/funnel.js.
- **How it fails:** The cohort has all 20 spots occupied, but either cohort_members or internal_accounts temporarily fails to read. The endpoint still returns HTTP 200 advertising 20 available spots. Before migration 019 is applied, it likewise advertises an offer whose claim RPC does not exist.
- **Fix:** Distinguish unavailable cohort data from a successfully read empty cohort. Omit or explicitly mark cohort availability and offers as unknown when the migration is absent, and surface other read failures rather than fabricating zero membership.
