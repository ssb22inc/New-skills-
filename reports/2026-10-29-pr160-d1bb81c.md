## Assessment

Two concrete defects need correction: daily admission counts do not match the documented per-item contract, and usage pruning can hide storage failures from the workflow. The new tests do not cover either failure path.

## Findings

### 1. [major] The per-item quota counts question and feedback scripts separately

- **Where:** `pulsern/api/_speak.js:479` · confidence high
- **Problem:** The item claim hashes the entire ref, including part, step and result. Consequently, a question and its explanation consume separate admissions; a flashcard's front and back consume two; and a six-step case can consume thirteen. This contradicts LIMITS and HUMAN_TASKS.md, which specify one admission per bank item with its parts counted together.
- **How it fails:** Before the relevant passages have been voiced, a student listens to 150 distinct questions and their explanations. That can exhaust the 300-item daily allowance, so the next question is refused even though the student has requested only 150 bank items. The app-wide admission allowance is inflated in the same way.
- **Fix:** Key the admission claim by stable bank-item identity and voice, excluding the script part, step and result. Allow later scripts for that admitted item to reuse its claim. Add tests requesting both sides of a card, question plus feedback, and all steps of a case under a one-item allowance.

### 2. [major] Pruning silently converts a storage outage into successful empty usage

- **Where:** `pulsern/ops/read-aloud-worker.mjs:315` · confidence high
- **Problem:** pruneUsage catches failure of listAll(bucket, "usage") and substitutes an empty array. runJob therefore receives a successful pruning result rather than pruned.error, despite the worker's documented requirement that storage trouble fail the workflow.
- **How it fails:** The bank is already voiced and its cursor is marked done, but listing the usage root returns a storage error. The scheduled run reports zero old slots removed and exits successfully. Repeated failures leave usage objects accumulating without the promised failed-run signal.
- **Fix:** Let the root listing error propagate to runJob's existing pruning catch. Add a test where only the usage-root listing fails and assert that runJob.failed is true and its summary contains the pruning diagnostic.
