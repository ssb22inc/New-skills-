## Findings

### 1. [blocker] Binary-extension files can pass review without their contents being reviewed

- **Where:** `pulsern/ops/astra-review.mjs:236` · confidence high
- **Problem:** This branch replaces every matching file with only its hash and size. It neither verifies that the file is actually binary nor requires a separate content review. A hash identifies a change; it cannot establish the accuracy of an image, PDF or recording. runReview can still return PASS for these files.
- **How it fails:** A PR replaces a public clinical diagram PNG or educational PDF with incorrect content. Astra receives only two hashes and byte counts, so the changed clinical material is never inspected. Likewise, text stored under a matching extension is hidden solely because of its filename.
- **Fix:** Fail closed for assets whose contents cannot be represented for review. Route supported images/documents/audio through an appropriate trusted review path bound to the exact bytes. Detect text independently of the extension and include its actual changes. Add tests proving that a hash-only asset summary cannot certify publication.

### 2. [blocker] UTF-8 decoding can erase executable changes before the lossless page digest

- **Where:** `pulsern/ops/astra-review.mjs:222` · confidence high
- **Problem:** The page blobs are read through gitIn with encoding: "utf8". Invalid UTF-8 bytes are replaced with U+FFFD before pageDigest runs. Different byte sequences can therefore produce identical digests, despite the new lossless guarantee. Generated-page entries have no raw diff or full-file fallback.
- **How it fails:** Use a page under public/learn with <meta charset="windows-1252"> and an inline script comparing string literals containing bytes 0xE9 and 0xEA. Changing the second literal to 0xE9 changes the browser's comparison from false to true. Node decodes both versions as a comparison between replacement characters, so collectChanges reports no textual change and omits the executable modification.
- **Fix:** Read blobs as buffers and verify lossless decoding before constructing a textual digest. Reject unsupported encodings rather than replacing bytes silently, or use an encoding-aware representation that preserves every changed byte. Add a real-git regression test using these non-UTF-8 HTML buffers.

### 3. [blocker] The executable-permission test fixes the script instead of checking it

- **Where:** `pulsern/tests/save-results.test.js:60` · confidence high
- **Problem:** chmodSync(SCRIPT, 0o755) succeeds even when the checked-in script is not executable. It also repairs the actual script before the subsequent save tests invoke it, masking the same defect throughout the suite.
- **How it fails:** Commit save-results.sh with mode 100644. npm test changes it to executable and passes all the save tests. The diagram-map, diagram-review and narration workflows do not run this repair; they invoke ops/save-results.sh directly and fail with Permission denied after doing the paid work.
- **Fix:** Remove the chmod mutation. Assert executable access or the tracked executable mode without modifying the source file, and let the direct-invocation tests fail naturally when the bit is absent.

### 4. [major] Manual PR resolution lacks pull-requests read permission

- **Where:** `.github/workflows/pulsern-astra-review.yml:53` · confidence medium
- **Problem:** Once an explicit permissions block is supplied, omitted GITHUB_TOKEN permissions are disabled. The new resolver calls GET /repos/$REPO/pulls/$IN_PR using that token, but only contents: write is granted. Reading a private repository's PR requires pull-requests: read. Repository visibility was not provided, so I could not verify whether this currently affects this deployment.
- **How it fails:** In a private repository, a diagram or narration workflow pushes results and dispatches the trusted review with a PR number. The resolver's PR lookup fails with an authorization error before setting the review range or posting a status. Manual re-review fails the same way.
- **Fix:** Grant pull-requests: read to the trusted review workflow, retaining the App-only status publisher. Add a permission check alongside the existing workflow tests.
