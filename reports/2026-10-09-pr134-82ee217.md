## Assessment

Request changes. Several earlier gaps are addressed, but the required review remains bypassable, the page digest still hides executable changes, and narration QA can approve reversed clinical statements. The ABG compensation logic also retains a clinically unsafe assumption. Two new tests do not establish their advertised guarantees. This assessment is based on static review; tests were not executed.

## Findings

### 1. [blocker] The trusted-ref check is controlled by the untrusted dispatch ref

- **Where:** `.github/workflows/pulsern-astra-review.yml:90` · confidence high
- **Problem:** workflow_dispatch loads the workflow from the selected ref. A check inside that workflow cannot establish its own trustworthiness: the branch can remove this check, change the reviewer, and retain statuses: write.
- **How it fails:** A contributor with repository write access pushes a branch that removes the default-branch check and makes its reviewer return 0. Dispatching that branch runs its altered YAML and reviewer, which can publish pulsern/astra-review=success on the target PR head without the trusted review.
- **Fix:** Enforce status-publisher provenance outside branch-editable YAML. Use a trusted GitHub App or enforced required-workflow mechanism whose identity and credentials an unreviewed branch cannot use to satisfy the required check. A removable shell condition is not a trust boundary.

### 2. [blocker] A second PR with a narrower base can certify the same unsafe head

- **Where:** `.github/workflows/pulsern-astra-review.yml:97` · confidence high
- **Problem:** The resolver verifies the head against a PR but never requires that PR to target the trusted integration branch. Commit statuses belong to a SHA, not to the PR or base/head range that was reviewed.
- **How it fails:** Head H contains an unsafe change plus a harmless final commit. One PR targets main; another targets a branch already containing the unsafe change. Reviewing the second PR examines only the harmless delta and posts success on H, satisfying the first PR's required status even if its full change failed review.
- **Fix:** Before allowing status publication, require the PR's base repository and base ref to match the protected integration target. Apply this to both dispatch and pull_request_target paths. Reviews against other bases must be report-only or use a separately enforced, range-bound check.

### 3. [blocker] Whitespace normalization still hides executable JavaScript changes

- **Where:** `pulsern/ops/astra-review.mjs:128` · confidence high
- **Problem:** squash(body) removes semantically significant whitespace from script bodies. The same normalization is also applied inside attribute values. Consequently, different browser behavior can produce identical page digests and no review diff.
- **How it fails:** Changing a script body from "// disabled alert(1)" to "// disabled\nalert(1)" activates the JavaScript, but both digest to "// disabled alert(1)". Arbitrary previously commented code can therefore be activated without appearing in the review.
- **Fix:** Preserve script/style bodies and attribute values exactly, using escaped strings if one-line records are necessary. Normalize only whitespace proven insignificant by a parser. Add regression tests for line comments, automatic semicolon insertion, and whitespace inside quoted attributes.

### 4. [blocker] Audio QA accepts opposite clinical diagnoses

- **Where:** `pulsern/ops/narrate-lib.mjs:140` · confidence high
- **Problem:** The exact-match safeguard protects a limited list of numbers, negations, and direction words, but not clinical terms such as acidosis and alkalosis. Overall character similarity remains sufficient to approve a clinically reversed statement.
- **How it fails:** Use the actual ABG ph-step narration as the script and replace its first "acidosis" with "alkalosis" in the transcript. The critical-term arrays remain identical and similarity remains above 0.92, so audioCheck passes a recording teaching that pH below 7.35 is alkalosis.
- **Fix:** Fail closed on clinically meaningful lexical substitutions. Prefer exact token agreement after explicitly allowed speech/spelling normalization, with a separate review path for other differences, rather than a short keyword whitelist. Add this real-script diagnosis-swap regression.

### 5. [blocker] Insufficient compensation is incorrectly excluded from mixed-disorder detection

- **Where:** `pulsern/src/diagrams/abg.jsx:38` · confidence high
- **Problem:** The new compensation checks examine only excessive compensation. Inadequate compensation is always treated as uncomplicated none/partial compensation, although it can indicate a second disorder. The interpreter has no onset or time-course information that would justify assuming the compensatory response simply has not developed.
- **How it fails:** For pH 7.15, PaCO2 30, and HCO3 10, Winter's expected PaCO2 is 21–25. The observed 30 can indicate superimposed respiratory acidosis, but the function returns partially compensated metabolic acidosis with mixedPossible=false. The new test explicitly enshrines never flagging under-compensation.
- **Fix:** Evaluate both sides of the expected-compensation interval and report inadequate-compensation/mixed-disorder uncertainty where appropriate. Do not assume a time course absent from the inputs. Replace the blanket under-compensation test with cases covering both appropriate compensation and possible additional disorders.

### 6. [blocker] The source-key invalidation test never changes any source

- **Where:** `pulsern/tests/diagram-gate.test.js:32` · confidence high
- **Problem:** The test claims to verify invalidation after drawing changes and stability after generated-data changes, but only calls sourceKey twice on the unchanged repository. It tests repeatability, not the publication gate's critical invalidation behavior.
- **How it fails:** Replacing sourceKey with a function returning a constant 24-character hexadecimal string passes this test. Once approvals carry that constant, subsequent drawing changes no longer invalidate them, while this test continues reporting success.
- **Fix:** Create a temporary source tree using sourceKey(root). Independently mutate a diagram, the kit, the player, and theme tokens and assert that each changes the key. Mutate item-map.json and narration.json and assert that those do not change it.

### 7. [blocker] Existing clips bypass the strengthened QA and immutable-storage migration

- **Where:** `pulsern/ops/narrate.mjs:101` · confidence medium
- **Problem:** The unchanged-clip shortcut checks only clipId, which contains neither the QA-policy version nor the storage format. Entries produced by the old similarity-only gate are therefore accepted without the new checks, and old input-addressed URLs are retained.
- **How it fails:** A legacy manifest entry has the current script/voice ID but its audio omitted a negation and passed the former similarity threshold. Re-running this updated pipeline skips that entry, leaving the unsafe recording attached. I could not verify whether the current narration manifest contains such legacy entries because it was not supplied.
- **Fix:** Version the QA attestation and require both a current attestation and byte-addressed audio metadata before skipping a clip. Re-transcribe and validate legacy recordings, or regenerate them, and remove entries that fail migration.

### 8. [major] The CLI smoke test fails once all diagrams are approved

- **Where:** `pulsern/tests/diagram-gate.test.js:84` · confidence high
- **Problem:** The smoke test requires the text "Held back", but map-diagrams.mjs prints that only when at least one diagram lacks a current passing review. The test therefore depends on an unfinished approval state rather than successful CLI startup.
- **How it fails:** Run the visual-review workflow successfully for every diagram and commit the resulting current index. On the next test run, the mapper correctly has no held-back diagrams and emits no such message, causing this test and CI to fail.
- **Fix:** Make the CLI test independent of repository approval state. Use controlled fixture approvals and a local database-response stub, then assert the intended startup/result behavior and exit status instead of requiring a warning that should disappear after successful review.
