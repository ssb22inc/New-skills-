### 3. [minor] A shift cover earned while the cover bank is full is recorded as granted and lost if a cover is spent later in the same week

- **Where:** `src/rewards.js:242` · confidence medium
- **Problem:** `maybeGrantCover` adds the Monday week to `coverWeeks` even when `rewards.covers` is already `MAX_COVERS`, so `covers` does not increase and `granted` is false. If the student later spends a cover in that same week, a subsequent call to `maybeGrantCover` sees `coverWeeks.includes(wk.monday)` and returns without granting. The cover the student earned is therefore silently lost.
- **How it fails:** State: `rewards.covers = 2`, `coverWeeks = []`, and the current week has 5 qualifying study days. `maybeGrantCover` returns `{ covers: 2, coverWeeks: [monday], granted: false }`. The student then misses a day, `advanceStreak` consumes one cover, leaving `covers = 1`. Later in the same week `maybeGrantCover` sees the already-recorded Monday and returns without granting, so the expected banked cover never appears.
- **Fix:** Only add `wk.monday` to `coverWeeks` when a cover is actually banked (`rewards.covers < MAX_COVERS`). If at cap, leave the week unmarked so the cover can be earned if capacity opens later in the same week, or explicitly document and render for users that covers over the cap are discarded at the moment they are earned.

### 4. [minor] Ambiguous badge text

- **Where:** `pulsern/public/product/pulsern-today-dashboard.png` · confidence medium
- **Problem:** The 'Day 0 - 7 to 7' badge is ambiguous and potentially misleading.
- **How it fails:** Students may not understand the meaning of the '7 to 7' time range in a study context.
- **Fix:** Clarify the badge text (e.g., use a clear date or remove the time range).
