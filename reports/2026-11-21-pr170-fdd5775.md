## Assessment

Not ready to merge. The fallback removes the existing audio-accuracy gate, and playback can hang on later segments or be canceled by an unrelated idle reader. The new audio prefetch cache also retains downloaded clips indefinitely.

## Findings

### 1. [blocker] Unchecked device speech bypasses the audio-accuracy gate

- **Where:** `pulsern/src/read-aloud.jsx:140` · confidence high
- **Problem:** Queued passages and passages rejected by the accuracy check now go directly to deviceSpeak without any verification of the audio actually delivered. Approved source text does not establish that a different speech engine pronounces its numbers, units, and clinical terms correctly. This removes the existing checked-audio guarantee and conflicts with the standing accuracy gate for all student-facing content. The updated tests record utterance input text, not spoken output, so they cannot establish that this replacement is accurate.
- **How it fails:** A clinically significant passage receives 422 because its audio failed verification, or has never been verified at all. Listen nevertheless delivers an unchecked rendering from the device. A dropped or mispronounced value in that rendering reaches the student without any gate capable of detecting it.
- **Fix:** Keep unverified or rejected passages screen-only unless the replacement audio also passes the required accuracy gate. Do not treat the "Device voice" label or equality of utterance input text as approval of the resulting audio.

### 2. [major] Later segments can wait indefinitely instead of using the fallback

- **Where:** `pulsern/src/read-aloud.jsx:369` · confidence high
- **Problem:** Only the starting segment has a bounded wait. Every later segment awaits tasks[i] without a deadline. Having the preceding segment's playback time available does not guarantee that its request has completed.
- **How it fails:** The stem request succeeds, but an option request remains pending during a network stall. After the stem finishes, playback waits indefinitely for that option instead of reading it with the device voice. The same failure occurs after the first segment falls back at 900 ms while the remaining requests stay pending. Existing tests answer every outstanding request before advancing playback, so they miss this path.
- **Fix:** Apply a bounded readiness decision to every segment, falling back when its request is still unresolved. Add a browser test that leaves a later request unresolved after the preceding segment ends and verifies that reading advances.

### 3. [major] Stopping an idle reader cancels another reader's device speech

- **Where:** `pulsern/src/read-aloud.jsx:324` · confidence high
- **Problem:** halt always calls the global speechSynthesis.cancel(), even when this hook has no run or does not own the active speech. Each reader invokes halt on mount, key changes, and unmount. An unrelated reader can therefore cancel the current owner's utterance. The canceled owner's deviceSpeak resolves "aborted", and playFrom returns without resetting its playing state or advancing.
- **How it fails:** Reader A is speaking through the device voice. Reader B mounts, switches to "off", or unmounts while idle. B's halt cancels A's utterance, leaving A silent while its bar still reports playing. The harness mounts only one reader at a time, so its cancellation tests cannot catch this.
- **Fix:** Associate device utterances with their owning run and cancel them only through that owner's abort signal or an explicit ownership transfer. An idle reader's cleanup must not cancel global speech. Add a simultaneous-two-reader regression test.

### 4. [major] Prefetched audio blobs are never released

- **Where:** `pulsern/src/read-aloud.jsx:122` · confidence high
- **Problem:** Every successfully prefetched clip creates an object URL retained in the module-level warmed map. There is no eviction or URL.revokeObjectURL call. Prefetch runs for every viewed item even when Listen is never pressed, and refreshed signed URLs retain additional copies of the same passage.
- **How it fails:** During a long practice or case-study session, navigating through items continually downloads and retains their audio for the lifetime of the SPA. Returning after signed-link expiry adds duplicate blobs. Audio resources grow without bound and can exhaust a memory-constrained student's browser.
- **Fix:** Use a bounded audio cache with eviction and revoke object URLs when evicted. Release unused clips after item changes or retain only a limited recent working set, and test that eviction revokes the corresponding URLs.
