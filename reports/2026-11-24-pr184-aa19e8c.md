## Assessment

Changes needed. The new answer-run accounting fails for batched results, shift completion disagrees between screens, and the guest-to-sign-in flow can reopen as sign-up. The warfarin correction is appropriate. Review was based on the supplied code and images; tests were not executed.

## Findings

### 1. [major] Batched exam results no longer accumulate correct-answer runs

- **Where:** `pulsern/src/App.jsx:945` · confidence high
- **Problem:** The previous functional run update has been replaced with `nextRun = counts ? run + 1 : 0`, using the render's captured value. Multiple calls to record before React commits a render therefore calculate from the same run, rather than from the preceding answer. This also corrupts best-run and combo calculations.
- **How it fails:** When a readiness exam records multiple results during submission, an all-correct batch starting from run 0 can finish at run 1 instead of the number of correct answers. A wrong answer inside the batch also fails to reset the starting point used by subsequent correct answers. The exam browser tests replace record with a harness callback, so they do not exercise this App-level regression.
- **Fix:** Accumulate run transitions through a reducer or synchronously maintained ref so each recorded result sees the preceding result, while still returning the appropriate feedback data. Add an integration test that records a mixed batch through App's actual recording logic.

### 2. [major] Weekly rounds mark incomplete daily shifts as complete

- **Where:** `pulsern/src/rewards.js:245` · confidence high
- **Problem:** `shiftStatus` requires assessments, scheduled reviews, and fixing a miss to complete a shift, but `dayShiftDone` checks only eight questions. Weekly rounds use that weaker predicate to announce "shift complete" and award shift covers.
- **How it fails:** A student answers eight questions while four flashcards remain due and misses remain uncorrected. Today correctly shows only 1/3 tasks done, but weekly rounds marks that same day as a completed shift. Five such incomplete days earn a cover despite none satisfying Today's completion rule.
- **Fix:** Use one completion definition for Today, weekly rounds, and cover awards, retaining the per-day evidence needed to evaluate it. If covers intentionally require only eight questions, label those historical counts as eight-question days rather than completed shifts. Test the case with eight answers and unfinished review tasks.

### 3. [major] Guest sign-in preserves a flag that switches reloads back to sign-up

- **Where:** `pulsern/src/auth.jsx:464` · confidence high
- **Problem:** `toAuth("signin")` preserves the entire query string, including the legacy `start=1` sign-up flag. `authModeFromUrl` gives that flag precedence over the explicit `/app/sign-in` path.
- **How it fails:** A visitor enters through `/app/?start=1`, tries the guest questions, and selects Sign in or "I have an account". The address becomes `/app/sign-in?start=1`. Reloading that page displays Create account and submits through `auth.signUp` instead of signing in.
- **Fix:** Remove the legacy start flag when making an explicit auth-mode choice, or give explicit sign-in/reset paths precedence over it. Preserve unrelated attribution and cohort parameters. Add a routing regression test for `/app/sign-in?start=1`.
