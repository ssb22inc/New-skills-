## Findings

### 1. [blocker] Recorded bank misses no longer match the loaded questions

- **Where:** `pulsern/src/question-review.js:80` · confidence high
- **Problem:** applyAnswer writes log and schedule identities such as bank:123, but App loads bank questions without source or key. idOf therefore returns "123" for the question while latestResults and missSchedule contain "bank:123". expandTrialQuestions repairs only bundled/trial questions, not bank questions. Consequently, newly missed bank questions disappear from Review Misses and scheduled Today reviews. Legacy numeric schedule entries can instead remain perpetually due because subsequent answers update a different, canonical entry.
- **How it fails:** Answer an approved bank question incorrectly. Its log row and review date use bank:<id>, but the original question still has only its numeric id. Review Misses reports no matching miss, and the question does not return when its scheduled date arrives.
- **Fix:** Stamp questions with their source and canonical key when constructing the bank and bundled catalogs, before any pool calculation. Use that same identity for recording, pool membership, schedule updates, and the displayed next-review date. Add an integration regression that records an actual loaded bank question and then retrieves it through Review Misses and Today.

### 2. [blocker] Trial expansion creates duplicate navigation IDs for different questions

- **Where:** `pulsern/src/question-review.js:73` · confidence high
- **Problem:** A canonical trial row such as builtin:7 expands into a bundled question retaining id 7, even when the loaded bank already contains a different question with id 7. QBank navigation stores raw IDs, and reveal restores with reviewQuestions.find(x => x.id === view.id), which selects the original bank question first. The saved selection, correctness, and credit can therefore be displayed against an unrelated stem and rationale. QBank's freshPool also compares raw log IDs, so answering builtin:7 incorrectly suppresses the unrelated bank:7 from new practice.
- **How it fails:** Import two missed bundled trial questions whose numeric IDs also exist in the shared bank. Review the first bundled miss, advance to the second, then go Back. The first entry restores the shared-bank question with that ID while retaining the bundled question's recorded answer and verdict.
- **Fix:** Use canonical keys for freshness checks, navigation entries, held-question sets, and restoration lookups. Keep the numeric database ID separately for API calls. Test navigation with different bank and bundled stems sharing the same numeric ID; the existing prefixed guest-7 test does not cover the identities now produced by mergeGuestIntoBlob.

### 3. [blocker] Historical trial replay overwrites newer account progress

- **Where:** `pulsern/src/guest.js:270` · confidence high
- **Problem:** mergeGuestIntoBlob replays historical answers through applyAnswer using each old answer day, then installs state.daily directly. applyAnswer replaces daily whenever its day differs, so importing yesterday's trial into an account with eight answers today changes daily from today's eight answers to yesterday's trial count. Historical rows are also appended after newer account rows, making latestResults treat an older trial miss as newer than a later correction. Meanwhile, updateMissSchedule ignores the supplied answer day and schedules from the import date, so replay is not consistently historical either.
- **How it fails:** An account has answered eight questions today and correctly answered builtin:7 today. On another browser it has a pending trial from yesterday containing a miss on builtin:7. Choosing Add replaces today's daily counter and makes the older miss the latest result. The next answer today restarts daily.answered at one rather than nine.
- **Fix:** Give historical imports date-aware semantics: preserve or recompute the current LOCAL day's counter, determine latest results chronologically, and calculate imported review dates from the intended answer date rather than silently using import time. Add a regression with yesterday's trial and newer same-question account answers plus a nonzero daily counter today.
