## Findings

### 1. [blocker] Resolving one legacy miss rewrites every ambiguous answer with that number

- **Where:** `pulsern/src/question-key.js:26` · confidence high
- **Problem:** App's resolveLegacy maps claimLegacyRow over the entire log. This function assigns the selected source and key to every unclassified row sharing the numeric ID, although those historical answers may belong to different questions. The selection screen asks the student to identify one missed question; it does not establish the identity of every earlier answer.
- **How it fails:** A student previously answered builtin:7 correctly and later missed a different bank:7 in the same category. Migration leaves both records ambiguous. Selecting the bank question for the miss changes both records to bank:7. The built-in answer is misattributed, and answerXp now sees an earlier correct bank answer, so correcting the bank miss incorrectly earns zero rather than the correction bonus.
- **Fix:** Identify and resolve individual legacy records, or explicitly selected groups, rather than all records with the same number. Preserve earlier ambiguous records unless their identity is independently established. Add an integration regression with two ambiguous histories sharing an ID and verify that resolving the latest miss does not reassign the earlier answer.

### 2. [major] A numeric review schedule can remain due forever after a correct review

- **Where:** `pulsern/src/answer-apply.js:18` · confidence high
- **Problem:** adoptRawSchedule refuses to move a numeric schedule whenever any historical row with that number has another source. However, scheduleEntry can still serve that numeric schedule to its latest canonical owner. A correct answer then calls updateMissSchedule with the canonical key, finds no entry there, and leaves the old due schedule unchanged.
- **How it fails:** The log contains an earlier builtin:7 answer and a later bank:7 miss, with the legacy schedule stored under "7" and already due. Migration 020 retains this numeric entry when it finds multiple canonical owners. With only bank:7 in the active catalog, Review Misses serves it using the raw date. Answering correctly does not advance the date, and the same question remains due in each subsequent sitting.
- **Fix:** Use one ownership rule for reading and adopting numeric schedules. When the latest eligible answer establishes the owner, move and advance that schedule atomically; otherwise present it as unresolved rather than serving it as a normal review. Test the actual migration output followed by a correct live review and confirm the next due date advances.

### 3. [major] Legacy answers written after the one-time migration become inaccessible

- **Where:** `pulsern/src/state.js:14` · confidence high
- **Problem:** migrateBlob leaves source-less rows unchanged, but the documented follow-up classification never occurs in App: classifyLog is not imported or called after the catalogs load. The one-time SQL migration cannot cover legacy blobs written afterward. QBank treats these rows as pending, while unresolvedCards only exposes rows explicitly marked unclassified.
- **How it fails:** A student has the pre-change app open when migration 020 runs. Their next answer autosaves the old in-memory, source-less history over the migrated blob. After loading the new app, previously answered questions are excluded from New questions, and their misses are absent from Review Misses because neither classification nor an unresolved card is produced.
- **Fix:** Provide repeatable legacy classification at the progress read/write boundary using a trusted complete catalog, or otherwise ensure every source-less row reaches the unresolved flow. Do not rely exclusively on the one-time migration. Add a rollout regression that saves a pre-change blob after migration and then opens it through the shipped App.
