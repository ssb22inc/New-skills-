## Assessment

Not ready to ship. Claim handling can misrepresent a student's access, cohort-read failures produce invented availability, and the production entitlement function is not exercised by the new safety tests. This assessment is based on the supplied code; tests were not executed.

## Findings

### 1. [blocker] An expired membership produces a fresh-trial confirmation

- **Where:** `pulsern/src/clinical.js:215` · confidence high
- **Problem:** An "already" response triggers the welcome screen without checking whether the existing pass is still active. The SQL deliberately does not extend an existing member's pass, but the welcome says "Your 30 free days are on" and "The full study library is open."
- **How it fails:** After their clinical trial expires, a member follows /clinicals on another device or browser with no dismissal flag. The RPC returns "already" with an expired expires_at, and the student sees the active-trial confirmation before encountering the paywall.
- **Fix:** Include the returned entitlement/expiry in the welcome decision. Only confirm an active grant when access is actually active; handle expired existing memberships separately. Test both an active duplicate claim and an expired duplicate claim.

### 2. [blocker] Entitlement safety tests validate a duplicate implementation, not production SQL

- **Where:** `pulsern/tests/clinical.test.js:266` · confidence high
- **Problem:** Cap, eligibility, expiry, and idempotency tests execute claimCohortSpot(), which production never calls. Billing tests stub the RPC result, while the test claiming migration equivalence only searches SQL text. These tests can report the publication-critical entitlement rules as safe while the real implementation violates them.
- **How it fails:** Changing the SQL cap comparison from v_count >= v_cap to v_count > v_cap admits a twenty-first non-internal member. Every supplied cap test and migration assertion still passes because the JavaScript mirror remains correct and the SQL comparison is never executed.
- **Fix:** Apply the real migrations to a test database and exercise claim_cohort_spot directly, including concurrent final-slot claims, repeat claims, paid/comp rejection, expiry preservation, and function permissions. Do not present the unused JavaScript mirror and substring checks as verification of production enforcement.

### 3. [major] Link-based claims silently discard full and ineligible results

- **Where:** `pulsern/src/auth.jsx:377` · confidence high
- **Problem:** The link flow treats every successful HTTP response as a completed claim. For "full" and "ineligible", it clears the cohort marker and mounts the ordinary app without displaying the rejection. Unlike the backup-code flow, students never receive the existing full/ineligible messages.
- **How it fails:** The twenty-first eligible student follows /clinicals and creates an account after seeing the 30-day offer. The RPC returns "full", but the application silently starts the ordinary seven-day pass instead, without explaining that the advertised perk was not granted.
- **Fix:** Handle claimed/already, full, ineligible, and unexpected statuses explicitly before clearing the claim context. Show the applicable rejection and let the student knowingly continue with ordinary access. Exercise these states through AuthGate rather than source-text assertions.

### 4. [major] Failed cohort reads advertise a fully available offer

- **Where:** `pulsern/api/marketing.js:257` · confidence high
- **Problem:** A failed cohort/internal-account read is converted into empty arrays. buildCohortFunnels() nevertheless always emits a clinical cohort, so the response reports zero members and the entire cap available. Contrary to the catch comment, perk figures do not remain empty. The owner funnel has the same fallback.
- **How it fails:** All twenty spots are occupied, but a temporary database error prevents reading cohort_members. The marketing endpoint returns an offer with members: 0 and spotsLeft: 20, allowing the marketing agent to promote availability that does not exist. Before migration 019, it likewise advertises an offer that cannot be claimed.
- **Fix:** Represent unavailable cohort data explicitly and omit or mark cohort/offers figures unavailable while preserving the rest of the report. Distinguish a successful empty result from a failed read, and test both endpoints under read failures.
