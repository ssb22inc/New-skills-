## Assessment

Request changes. The code-review parser handles inline thinking defensively, but the shared content-publication parser can still mistake preliminary JSON inside that thinking for a completed approval.

## Findings

### 1. [blocker] Reject preliminary approval JSON inside inline thinking

- **Where:** `pulsern/ops/review.mjs:100` · confidence medium
- **Problem:** The model migration explicitly accommodates DeepSeek responses containing <think> blocks in astra-review.mjs, but review() returns that form unchanged and parseJson() extracts JSON from anywhere in it. For example, parseJson('<think>[{"verdict":"pass","confidence":0.99}]</think>\nI could not complete the review.') returns the passing array even though there is no final JSON verdict. I could not verify whether OpenRouter always separates this model's reasoning; the failure applies whenever it emits the inline form supported elsewhere in this PR.
- **How it fails:** A content reviewer includes a preliminary passing batch, with the factory's expected fields and confidence >=0.85, inside <think>, then ends with a refusal or incomplete prose answer. The shared parser returns the preliminary batch as the completed review, allowing a publication gate to consume approvals that were never finalized.
- **Fix:** Give the shared content parser the same final-payload discipline as the code-review parser: remove only an explicitly supported leading thinking block, unwrap at most one outer fence, and parse the entire remaining payload rather than extracting a JSON substring. Preserve support for both object and array verdicts. Add a regression test proving that passing JSON inside thinking followed by a non-verdict throws.
